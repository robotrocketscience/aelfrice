### Fixed

- **The published-figure gate reads code with a block scanner and a run-length span matcher, so a marker near a backtick is no longer silently dropped ([#1556](https://github.com/robotrocketscience/aelfrice/issues/1556)).** `scripts/check_derived_figures.py` excludes code before it parses a marker, so a figure quoted in a shell transcript is not read as a published claim. It did that with a single regex — ``` ``.*?``|`[^`]*` ``` — which paired backticks across the whole document, with no notion of a block and no notion of run length. A run of three is odd: two backticks paired, and the third became an opener that blanked everything down to the next backtick anywhere below it. **`docs/user/PRIVACY.md` carries six delimiter lines and parsed 0 markers**, the count a page with no markers in it also reports. A marker that never parses is indistinguishable from a figure nobody annotated, so the gate reported success over an unguarded figure — the #1160 defect class, inside the gate built to stop it. Measured on this branch's tree, Markdown markers move from **112** to **116**, and the repository total from **197** to **201**; `docs/user/CONFIG.md` and `docs/user/PRIVACY.md` each move from **0** to **2**.

  **The repair is two rules, because either one alone fails a bar the other holds.** `code_block_spans` follows CommonMark's fenced-code rules — an opener of three or more backticks or tildes indented at most three spaces, a backtick opener's info string carrying no backtick, and a closer of the same character, at least as long, with nothing after it but whitespace. `code_span_spans` follows CommonMark's inline rule — a span opens on a maximal run of backticks and closes on the next run of exactly that length, within one blank-line-delimited paragraph — so a run with no equal-length partner is literal text rather than a dangling opener. Over the 300-document seeded corpus in `tests/test_code_span_scanner_1556.py`, the block scanner alone leaves **56** documents violating the acceptance bar and loses **9** prose markers the old rule parsed; the span matcher alone leaks **188** markers out of fenced blocks, which deletes the feature the masking exists for; together both counts are **0**. The live corpus cannot make that distinction — either half recovers the same four markers there — so the generated corpus is the instrument that separates them.

  **The acceptance bar is absolute, and a differential prices the change beside it.** The bar: a marker outside every fenced block, in a paragraph carrying no backtick, parses, at its own line. The old rule breaks that on **93** of the 300 generated documents and this one on none. The differential holds the new scanner to a superset of what the old one parsed, and the one exception is enumerated rather than waived: where the old rule leaked a marker *out of* a real code block, this one correctly hides it.

  **Two declared divergences from CommonMark, and one of them now announces itself.** An unterminated opener masks nothing, where CommonMark runs the block to the end of its container — blanking to the end of the document is the exact shape of the defect being fixed. No file in the scanned corpus carries one today, so the two readings agree here, and `unterminated_fence` raises an advisory naming the line whenever a file grows one, because a silent divergence is how a gate goes quiet. The advisory quotes the closer length and the indent width the scanner itself enforces, and a test builds each remedy out of the message that was printed, so advice that would not clear the warning is red. Indented code blocks are not masked, because four-space indentation is the body of every Python function in a corpus that includes `src/`. Not masked either, and not masked before: HTML blocks, link reference definitions, and fences nested inside a blockquote or list item.

  Masking is now a whole-document decision made once, in `read_scannable`. It was not one before: a block containing a blank line lands in two `split_entries` entries, and an entry-level scanner holding an opener with no closer has to guess. Entry boundaries are still read off the raw file, because a blanked block is a run of whitespace-only lines and splitting the masked text would cut a page in two between a figure and the marker that names it. `split_lines` replaces `str.splitlines()` throughout, so the masked line list and the raw one agree on what a line is: `splitlines()` breaks on eight characters that masking turns into spaces, and one of them inside a block slid every entry after it and made the gate hard-fail a correct page at the wrong line.

  `docs/user/PRIVACY.md` can now publish the two budgets it names. The per-turn hook budget and the library retrieval budget gained markers on that page, and `benchmarks/published_constants.py` gained the two keys that re-derive them from the shipped constants, so a value edited in one place and not the other is red.

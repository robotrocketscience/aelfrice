### Fixed

- **aelfrice captured its own commands as beliefs, so a lock request left no usable trace ([#1620](https://github.com/robotrocketscience/aelfrice/issues/1620)).** A user ran `/aelf:lock <statement>`, nothing locked, nothing reported a failure, and the same instruction was restated twelve times over six weeks without ever binding. On that store `lock_level='user'` was set on exactly one belief out of 20,176.

  `is_transcript_noise` — the filter `ingest.py` actually uses — had no rule for aelfrice's own invocations, so `/aelf:lock <statement>` was written as an `agent_inferred` belief at μ=0.375, spending the evidence that a lock had been requested on a row describing the request. Two such rows exist on that store; neither produced a lock. A third row, dated 2026-08-19, has the rendered XML of another belief as its content.

  The slash form is matched unconditionally alongside the other structural prefixes. It has to be: `/aelf:lock <statement>` carries a statement that usually ends like written prose, so the category-1 escape hatch would rescue exactly the string the rule exists to drop, and no English sentence opens with `/aelf:`. The bare `aelf ` form joins the prose-escaped shell prefixes instead, because sentences do open with it. **That escape is punctuation-only**, as it has been for `git ` and `pytest ` since #1371: "aelf locks are injected verbatim in every session." survives, and the same sentence without a full stop does not. The limitation is pinned by a test rather than left implied. Measured on the live store, the new rules newly reject **45 of 20,177** beliefs, all of them command text or rendered blocks.

  **Also hardened, and honestly scoped: `aelf lock` could print success without locking.** The write was skipped when the resolved belief carried `ORIGIN_SPECULATIVE` — deliberately, because #550 Surface B owns phantom rows — but the skip fell through to the success lines. Surface B now runs *before* the write instead of at the end of the function: `find_phantom_lock_matches` only sees rows still carrying `ORIGIN_SPECULATIVE`, so promoting first means the write can no longer disqualify a phantom, which was the only reason it skipped them. The write is then unconditional, except that it preserves `ORIGIN_USER_VALIDATED` — the promotion target, and a stronger provenance than `ORIGIN_USER_STATED`. A verification reads the belief back through the same predicate `aelf locked` uses and exits non-zero if it is not there, naming any phantoms that were promoted, because Surface B commits per call and "nothing happened" would be false about the store.

  **That half is hardening, not a fix for an observed failure, and the distinction is load-bearing.** `actual_id` resolves by `sha256(text)`, while the only producer of `ORIGIN_SPECULATIVE` keys `content_hash` on `_constituent_key` — sha256 of the constituent ids plus the generator, explicitly not the content. A real phantom therefore cannot be `actual_id`, and pre- and post-change code produce identical store state on one. Restoring the skip is caught by no test in the suite, and that is expected for inert code; an earlier draft of this entry claimed otherwise and was wrong.

  Diagnosed against six hypotheses registered before the experiments ran. Three results contradict the obvious theories and are recorded so they are not re-proposed: locking over an ordinary captured belief already worked, and had since `f6f1d030` (2026-07-29), *before* both observed failures, so a content-hash collision was not the cause; the L0 read keys on `lock_level` and is not gated by origin, so the tier mechanism itself was never broken; and an earlier attempt filtered `_should_skip_bm25`, which is the BM25 *retrieval* gate (#674) with no belief writer behind it, so every unit test passed while ingest went on writing the command. The end-to-end arm here drives `ingest_jsonl` so that mistake cannot recur silently.

  **This does not prevent the reported failure from recurring**, and #1620 stays open for that reason. The lock was lost because the command never executed; stopping the capture preserves the evidence but does not make the lock happen. Reconciling "a lock was requested" against "a lock was applied" is [#1622](https://github.com/robotrocketscience/aelfrice/issues/1622), and that is the criterion that would have caught it.

  Also not covered: paraphrase defeating corroboration. `_content_hash` is `sha256(raw_text)` with no normalisation, so twelve restatements were twelve unrelated beliefs at corroboration 0, none reaching `aelf core`. The fix is a near-duplicate signal rather than a hash change — normalising whitespace and case would merge roughly 3 of the 12 — and it needs its own design.

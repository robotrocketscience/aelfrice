### Fixed

- **A lock could be requested and silently lost ([#1620](https://github.com/robotrocketscience/aelfrice/issues/1620)).** A user ran `/aelf:lock <statement>`, nothing locked, nothing reported a failure, and the same instruction was restated twelve times over six weeks without ever binding. On that store `lock_level='user'` was set on exactly one belief out of 20,176. Two independent routes lost it.

  **`aelf lock` reported success without locking.** `_cmd_lock` skipped the lock write when the resolved belief carried `ORIGIN_SPECULATIVE` — deliberately, because #550 Surface B owns phantom rows and promotes them, and rewriting origin at the write would disqualify a phantom from its own path — but the skip fell through to the success lines. A statement matching a phantom was promoted, reported as `locked: <id>`, and exited 0 while `aelf locked` did not list it.

  The fix is an **ordering change**: Surface B now runs *before* the write instead of at the end of the function. `find_phantom_lock_matches` only sees rows still carrying `ORIGIN_SPECULATIVE`, so promoting first means the write can no longer disqualify a phantom — which was the only reason it skipped them. With promotion already done the skip is unnecessary, the write is unconditional, and a statement the user asked to lock ends up locked. The write does not overwrite `ORIGIN_USER_VALIDATED`, which is the promotion target and a stronger provenance than `ORIGIN_USER_STATED`: locking records that a statement is ground truth, and should not demote how the row got there. A verification then reads the belief back and exits non-zero if it is not locked, because the one thing this command must never do is report a lock that did not happen.

  **The capture path stored the command as a belief.** `is_transcript_noise` — the filter `ingest.py` actually uses — had no rule for aelfrice's own invocations, so `/aelf:lock <statement>` was written as an `agent_inferred` belief at μ=0.375, spending the evidence that a lock had been requested on a row describing the request. The slash form is now matched unconditionally alongside the other structural prefixes, because the statement it carries usually ends like written prose and the category-1 prose escape hatch would otherwise rescue exactly the string the rule exists to drop; no English sentence opens with `/aelf:`. The bare `aelf ` form joins the prose-escaped shell prefixes instead, because sentences do open with it — "aelf locks are injected verbatim in every session." is a claim and still lands. aelfrice's own rendered injection blocks join the same structural group; one belief on that store has the XML of another belief as its content.

  Diagnosed against six hypotheses registered before the experiments ran. Three results are worth recording because they contradict the obvious theory: locking over an ordinary captured belief already worked, and had since `f6f1d030` (2026-07-29), *before* both observed failures — so a content-hash collision was **not** the cause; the L0 read keys on `lock_level` and is not gated by origin, so the tier mechanism itself was never broken; and an earlier attempt at this fix filtered `_should_skip_bm25`, which is the BM25 *retrieval* gate (#674) with no belief writer behind it, so every unit test passed while ingest went on writing the command. The end-to-end arm here drives `ingest_jsonl` so that mistake cannot recur silently.

  Nine mutations were run against the guards and all nine fail the suite, including restoring the speculative skip, moving promotion back after the write, removing the verification, and dropping the prose escape hatch.

  Not covered, and filed separately: reconciling "a lock was requested" against "a lock was applied", so a lost lock is detectable at all ([#1622](https://github.com/robotrocketscience/aelfrice/issues/1622)) — that is the criterion that would have caught this. Paraphrase defeating corroboration, which is why twelve restatements never promoted, needs a near-duplicate signal rather than a hash change and is not filed yet.

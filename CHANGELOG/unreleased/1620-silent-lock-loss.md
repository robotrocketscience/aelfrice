### Fixed

- **A lock could be requested and silently lost ([#1620](https://github.com/robotrocketscience/aelfrice/issues/1620)).** A user ran `/aelf:lock <statement>`, nothing locked, nothing reported a failure, and the same instruction was restated twelve times over six weeks without ever binding. On that store `lock_level='user'` was set on exactly one belief out of 20,176. Two separate routes lost it, and both are closed here.

  **`aelf lock` reported success without locking.** `_cmd_lock` skips the upgrade when the resolved belief carries `ORIGIN_SPECULATIVE` — deliberately, because #550 Surface B owns phantom rows and promotes them through `promote_phantom`, and rewriting origin at the lock site would disqualify a phantom from its own path. But the skip fell through to the success lines, so a statement matching a speculative row that Surface B then did *not* claim printed `locked: <id>`, exited 0, and left `lock_level` at `none`. The outcome line is now **built early and printed late**, after Surface B has run and the result is actually known; if neither a lock nor a promotion happened, the command says so on stderr and exits non-zero. Announcing success before the work finishes is what made the original failure invisible.

  **The capture path ate the command.** `_should_skip_bm25` applied two filters, for system tags and for triviality, and neither knew what an aelfrice command looks like. A prompt of `/aelf:lock <statement>` therefore passed both and was stored as an `agent_inferred` belief at μ=0.375 — spending the evidence that a lock was requested on a low-confidence belief *about* the request. Two such rows exist on the reporting store and neither produced a lock. Prompts that open with an aelfrice invocation are now skipped, as are prompts that open with aelfrice's own rendered output, which had been re-ingesting an injected `<belief …>` block as a new belief. The command filter is **anchored at the start**: a sentence that merely mentions a command ("the command `/aelf:lock` did not take effect yesterday") is a claim about the world and is still captured.

  Diagnosed against six hypotheses registered before the experiments ran, each tested against an isolated store. Three findings are worth recording because they contradict the obvious theory: locking over an ordinary captured belief already worked and has since `f6f1d030` (2026-07-29), *before* both observed failures, so a content-hash collision was **not** the cause; the L0 read path keys on `lock_level` and is not gated by origin, so the tier mechanism itself was never broken; and the first draft of this fix refused *before* Surface B, which broke phantom promotion outright — caught by `tests/test_phantom_promotion_trigger.py`, which is why the check now sits after it.

  Eight mutations were run against the guards and all eight fail the suite, including removing the refusal, returning 0 from it, dropping the speculative guard, and deleting the deferred success line.

  **Separately, `scripts/check_no_personal_paths.py` went from 85.9s to 0.80s.** Reading each tracked blob through its own `git show` forked once per file — 74.6 ms/file over 1,151 files, which had begun to blow the test's 60-second budget. It now reads every blob through a single `git cat-file --batch`. Determinism is unchanged: it still reads the index rather than the working tree, so a tracked symlink is not followed off the repository.

  Not covered, and filed separately: reconciling "a lock was requested" against "a lock was applied", so a lost lock is detectable at all ([#1622](https://github.com/robotrocketscience/aelfrice/issues/1622)) — that is the criterion that would have caught this. Paraphrase defeating corroboration, which is why twelve restatements never promoted, needs a near-duplicate signal rather than a hash change and has not been filed yet.

### Fixed

- **The onboard handshake now keeps each candidate's commit date, instead of stamping every accepted belief with the handshake-completion time ([#1609](https://github.com/robotrocketscience/aelfrice/issues/1609)).** `onboard_sessions.candidates_json` carried only `index`, `source`, and `text`, dropping `SentenceCandidate.commit_date` — the v1.1.0 git-recency date that direct `scan_repo` ingestion already uses as `belief.created_at`. Every belief accepted through the handshake collapsed to one shared `created_at`, so a session's temporal spine (`(created_at, rowid)` order) fell back to rowid, which carries no chronology. `start_onboard_session` now builds the git-recency map and passes it to the filesystem and AST extractors, the same way `scan_repo` does, and `commit_date` rides along in `candidates_json`; `accept_classifications` uses it as `created_at`, falling back to the handshake timestamp when the scanner found no date. Older sessions whose `candidates_json` predates this fix load unchanged — a missing `commit_date` key falls back to the same timestamp as before.

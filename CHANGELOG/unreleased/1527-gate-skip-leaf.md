### Performance

- **A gate-skipped hook fire stops importing the retrieval subtree it exists to skip ([#1527](https://github.com/robotrocketscience/aelfrice/issues/1527)).** The prompt-shape gate refuses trivial and system-generated prompts so they never retrieve. They never did retrieve — and imported the whole retrieval stack anyway, because the skip branch calls `_emit_user_prompt_submit_rebuild_log` unconditionally and that function reached into `aelfrice.context_rebuilder` *above* its own `session_id` and `:memory:` early returns, pulling `retrieval`, `triple_extractor`, `scoring`, `clustering`, `bfs_multihop`, `correction`, `derivation*`, `doc_linker*`, `exploration`, `compression` and `np_pattern` behind it. The import could not be gated on config either: deciding whether the log is enabled *is* `load_rebuilder_config`, which lived in the module being avoided. That circularity is why the fix is a module extraction rather than a lazy import — the same remedy #1407 applied to `sidecar_outcome`, for the same reason, that every hook fire is a fresh process. `aelfrice.rebuild_log` now holds the `[rebuilder]` / `[rebuild_log]` config resolution and the phase-1a diagnostic log, and `entity_extractor` / `triple_extractor` are function-scope imports below every early return, so a skipping fire (which passes an empty candidate list) never reaches them. `context_rebuilder` re-exports every moved name, so the CLI, the benchmarks and the existing callers import them unchanged. The other half is `hook.py`'s own module scope: `retrieve`, `search_for_prompt` and four `context_rebuilder` entry points now resolve through a `_lazy()` helper that reads `globals()` before it imports — which is where `monkeypatch.setattr(aelfrice.hook, ...)` writes, so the test modules that patch those names keep working — with a PEP 562 module `__getattr__` so `from aelfrice.hook import retrieve` and `setattr(..., raising=True)` still resolve on an unresolved module. Neither half moves the number alone; the leaf extraction is worthless while `hook.py` imports `context_rebuilder` eagerly, and the deferral is worthless while the rebuild-log call re-pays it. **The measurement is the module closure, and `scripts/measure_1527_import_closure.py` is what produces it**: it exports each git ref with `git archive` so neither arm is the installed package, then probes it in cold subprocesses with every `AELFRICE_*` / `AELF_*` variable stripped and `HOME`, the dotdir and the DB pinned to a scratch directory, because the lane resolvers are env-first and opening a `MemoryStore` is a write. Against `github/main`: **`import aelfrice.hook` falls from 35 `aelfrice` modules to 18, and a driven gate-skipped fire from 40 to 26**; `aelfrice.rebuild_log` costs 12 where `aelfrice.context_rebuilder` cost 28. `tests/test_hook_import_cost_1351.py` pins 18 and 26 as ceilings and asserts that none of the twelve retrieval-subtree modules loads on a skipped fire, with a second test driving a retrieving fire so the absence assertion cannot pass because a name was misspelled or a deferred import deleted rather than moved. **No millisecond figure is published.** An earlier draft of this entry carried one; independent paired re-derivations on the same tree did not reproduce its interval, and on a loaded developer machine none of them is worth publishing. The module closure is deterministic, so that is the claim. `query_understanding` stays eager: `_rebuild_and_format` binds `DEFAULT_STRATEGY` as a def-time default and `RebuilderConfig.query_strategy` binds it in a frozen dataclass field, and deferring it from `hook.py` alone saves **0** modules, because `rebuild_log` binds it too; deferring it from both files saves **5**, none of them on the retrieval path. `scripts/measure_1527_import_closure.py --marginal` re-derives both.

### Performance

- **A gate-skipped hook fire stops importing the retrieval subtree it exists to skip ([#1527](https://github.com/robotrocketscience/aelfrice/issues/1527)).** The prompt-shape gate refuses trivial and system-generated prompts so they never retrieve. They never did retrieve — and imported the whole retrieval stack anyway, because the skip branch calls `_emit_user_prompt_submit_rebuild_log` unconditionally and that function reached into `aelfrice.context_rebuilder` *above* its own `session_id` and `:memory:` early returns, pulling `retrieval`, `triple_extractor`, `scoring`, `clustering`, `bfs_multihop`, `correction`, `derivation*`, `doc_linker*`, `exploration`, `compression` and `np_pattern` behind it. The import could not be gated on config either: deciding whether the log is enabled *is* `load_rebuilder_config`, which lived in the module being avoided. That circularity is why the fix is a module extraction rather than a lazy import — the same remedy #1407 applied to `sidecar_outcome`, for the same reason, that every hook fire is a fresh process. `aelfrice.rebuild_log` now holds the `[rebuilder]` / `[rebuild_log]` config resolution and the phase-1a diagnostic log; its import closure is **12 `aelfrice` modules against the 28 `context_rebuilder` pulled in before this change**, and `entity_extractor` / `triple_extractor` are function-scope imports below every early return, so a skipping fire (which passes an empty candidate list) never reaches them. `context_rebuilder` re-exports every moved name, so the CLI, the benchmarks and the existing callers import them unchanged. The other half is `hook.py`'s own module scope: `retrieve`, `search_for_prompt` and four `context_rebuilder` entry points now resolve through a `_lazy()` helper that reads `globals()` before it imports — which is where `monkeypatch.setattr(aelfrice.hook, ...)` writes, so the ten test modules that patch those names keep working — with a PEP 562 module `__getattr__` so `from aelfrice.hook import retrieve` and `setattr(..., raising=True)` still resolve on an unresolved module. Neither half moves the number alone; the leaf extraction is worthless while `hook.py` imports `context_rebuilder` eagerly, and the deferral is worthless while the rebuild-log call re-pays it. Measured here, both arms in cold subprocesses against exported source trees so neither is the installed one, interleaved pair by pair, each fire pinned to its own fresh `HOME` / dotdir / DB: **`aelfrice` modules loaded fall from 35 to 18 at import and from 40 to 26 over a driven gate-skipped fire**. `import aelfrice.hook` goes **60.7 ms → 32.8 ms**, paired median **−28.2 ms, bootstrap 95% CI −28.5 to −27.8, faster in 41 of 41 pairs**. The whole fire goes **153.1 ms → 127.7 ms**, paired median **−25.2 ms, 95% CI −26.4 to −23.8, faster in 59 of 60 pairs**; an earlier run of the same harness on the same tree gave −27.9 ms (CI −31.3 to −26.1, 56/60), which is the spread to expect from machine load rather than from the change. `query_understanding` is deliberately left eager: `_rebuild_and_format` binds `DEFAULT_STRATEGY` as a def-time default and `RebuilderConfig.query_strategy` binds it in a frozen dataclass field, and it costs 5 modules and ~1.0 ms of the 31 — buying that back would mean a `None` sentinel in a public signature. `tests/test_hook_import_cost_1351.py` gains the gate: a driven skipped fire must load none of the twelve retrieval-subtree modules and must stay under the pinned counts, with a second test driving a retrieving fire so the absence assertion cannot pass because a name was misspelled or a deferred import deleted rather than moved.

### Performance

- **A gate-skipped hook fire stops importing the retrieval subtree it exists to skip ([#1527](https://github.com/robotrocketscience/aelfrice/issues/1527)).** The prompt-shape gate refuses trivial and system-generated prompts so they never retrieve. They never did retrieve — and imported the whole retrieval stack anyway, because the skip branch calls `_emit_user_prompt_submit_rebuild_log` unconditionally and that function reached into `aelfrice.context_rebuilder` *above* its own `session_id` and `:memory:` early returns, pulling `retrieval`, `triple_extractor`, `scoring`, `clustering`, `bfs_multihop`, `correction`, `derivation*`, `doc_linker*`, `exploration`, `compression` and `np_pattern` behind it. The import could not be gated on config either: deciding whether the log is enabled *is* `load_rebuilder_config`, which lived in the module being avoided. That circularity is why the fix is a module extraction rather than a lazy import — the same remedy #1407 applied to `sidecar_outcome`, for the same reason, that every hook fire is a fresh process. `aelfrice.rebuild_log` now holds the `[rebuilder]` / `[rebuild_log]` config resolution and the phase-1a diagnostic log, and `entity_extractor` / `triple_extractor` are function-scope imports below every early return, so a skipping fire (which passes an empty candidate list) never reaches them. `context_rebuilder` re-exports every name in `rebuild_log.__all__` except `_extracted_entities_for_log` and `_recent_turns_hash`, which nothing outside `rebuild_log.py` calls, so the CLI, the benchmarks and the existing `from aelfrice.context_rebuilder import ...` callers import what they ask for unchanged. `tests/test_rebuild_log_reexports_1527.py` holds both halves: the exception list as a set equality, and every such import under `src`, `tests`, `benchmarks` and `scripts` resolving. It is not a claim about the namespace, and an earlier draft of this entry wrongly made one. Twelve names — `Any`, `LEGACY_STRATEGY`, `VALID_STRATEGIES`, `dataclass`, `datetime`, `discover_config`, `extract_entities`, `extract_triples`, `hashlib`, `os`, `timezone`, `tomllib` — were reachable as `context_rebuilder.<name>` before this change and are not now; every one was an import that had leaked into the namespace, and no caller in the tree reaches for any of them through `context_rebuilder`. One consumer did have to move with the code: `tests/test_triple_collision_verbs_1376.py` AST-walks the module holding the `extract_triples` call, so it is repointed at `rebuild_log` here — a re-export cannot satisfy a test that looks for a `Call` node. The other half is `hook.py`'s own module scope: `retrieve`, `search_for_prompt` and four `context_rebuilder` entry points now resolve through a `_lazy()` helper that reads `globals()` before it imports — which is where `monkeypatch.setattr(aelfrice.hook, ...)` writes, so the test modules that patch those names keep working — with a PEP 562 module `__getattr__` so `from aelfrice.hook import retrieve` and `setattr(..., raising=True)` still resolve on an unresolved module. Neither half moves the number alone; the leaf extraction is worthless while `hook.py` imports `context_rebuilder` eagerly, and the deferral is worthless while the rebuild-log call re-pays it. **The measurement is the module closure, and `scripts/measure_1527_import_closure.py` is what produces it**: it exports each git ref with `git archive` so neither arm is the installed package, then probes it in cold subprocesses with every `AELFRICE_*` / `AELF_*` variable stripped and `HOME`, the dotdir and the DB pinned to a scratch directory, because the lane resolvers are env-first and opening a `MemoryStore` is a write. Against `github/main`: **`import aelfrice.hook` falls from 35 `aelfrice` modules to 18, and a driven gate-skipped fire from 40 to 26**; `aelfrice.rebuild_log` costs 12 where `aelfrice.context_rebuilder` cost 28. `tests/test_hook_import_cost_1351.py` pins 18 and 26 as ceilings and asserts that none of the twelve retrieval-subtree modules loads on a skipped fire. Two further tests stop that absence assertion from degrading quietly, and they catch different things. A second test drives a *retrieving* fire and asserts a set **equality** between the entries of the same tuple that fire loads and a separately pinned nine-name set, which fails if a deferred import was deleted rather than moved, if the retrieval lane stopped running, or if either list was edited on its own. A third asserts every entry of the tuple resolves through `importlib.util.find_spec`, which is the only check covering the three entries (`correction`, `derivation`, `triple_extractor`) that no fixture fire reaches. Neither is a claim that the ban list is complete — nothing in the repo re-derives its membership — and the `26` ceiling remains what catches a module leaking back onto the skip path under a name the tuple never held. **No millisecond figure is published.** An earlier draft of this entry carried one; independent paired re-derivations on the same tree did not reproduce its interval, and on a loaded developer machine none of them is worth publishing. The module closure is deterministic, so that is the claim. `query_understanding` stays eager: `_rebuild_and_format` binds `DEFAULT_STRATEGY` as a def-time default and `RebuilderConfig.query_strategy` binds it in a frozen dataclass field, and deferring it from `hook.py` alone saves **0** modules, because `rebuild_log` binds it too; deferring it from both files saves **5**, none of them on the retrieval path. `scripts/measure_1527_import_closure.py --marginal` re-derives both.

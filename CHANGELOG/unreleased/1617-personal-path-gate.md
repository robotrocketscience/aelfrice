### Fixed

- **No gate caught an absolute home path, and nothing stopped a host configuration directory being tracked ([#1617](https://github.com/robotrocketscience/aelfrice/issues/1617)).** PR #1610 added `.gemini/settings.json` to this public repo carrying a developer's absolute venv path eleven times, and `secrets-scan`, `pattern-scan` and `history-scan` all reported PASS. `secrets-scan` looks for credentials, and an absolute path is not one; the other two match against patterns held in the `SCAN_RULES_B64` repository secret, which — established by behavior, since the secret cannot be read — does not match a home-directory shape. A sweep of the tree found the same class of disclosure already on `main`: `docs/design/hook-injection-audit.md` carried a real `/Users/<user>/` path in two table rows, landed 2026-07-20 and still live. Both rows now use the `~/` form the same document already uses elsewhere. **Removing them clears `HEAD` only — git history retains the old blobs, and the content pushed to `refs/pull/1610/head` stays reachable regardless of the branch deletion, because GitHub pins pull-request commits permanently.** Only GitHub Support can purge that ref.

  The new gate is `scripts/check_no_personal_paths.py`, and two things about it are deliberate. It lives **in the tree rather than in a secret**, because a gate whose rules nobody can read is a gate nobody can audit, test, or regression-guard — the reason this gap stayed invisible until something slipped through. And it checks **both** halves of the failure: the path text is the disclosure, but the untracked-but-unignored host dotdir is the vector. `.gitignore` had no rule for `.claude/`, `.gemini/` or `.codex/`, and this repo's own worktrees live under `.claude/`, so the directory sat one `git add -A` away from being staged. All three are now ignored, refused if tracked, and added to the pre-push hook's banned paths, which previously knew only about `.claude/`.

  Verified rather than asserted: run against the #1610 diff the checker flags **12 added lines**, every one of which the three shipped gates passed. Across all 1,140 tracked files it reports **zero** false positives — `/home/runner` (Actions), `/Users/synthetic` (the documented fixture marker) and `C:\Users\ci\` (Windows test fixtures) are allowlisted in the diff where a reviewer can see them. `tests/test_no_personal_paths.py` pins both halves and is distinguishing: five mutations — dropping the placeholder allowlist, neutering the pattern, dropping the path-root anchor, removing `.gemini/` from the refused set, and removing `.gemini/` from `.gitignore` — were each killed, with the suite green before and after. It runs in CI inside `pattern-scan`, which is a required check, and before every push via `scripts/install-discretion-hook.sh`, which calls the same script rather than carrying a second copy of the pattern that could drift from it.

  What it does not cover: content already in git history or in a `refs/pull/*` ref; a home path that uses an allowlisted placeholder as a real username; paths in binary files; and anything outside the `/home/…`, `/Users/…` and `X:\Users\…` shapes.

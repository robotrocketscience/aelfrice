### Internal

- **The premise that an observational store open is worth optimizing is refuted, and the invariant underneath it now has a guard ([#1561](https://github.com/robotrocketscience/aelfrice/issues/1561)).** `aelf search`, `stats`, `locked`, `speculative` and `show` open through `db_paths.open_store_for_read()`, which attempts the ordinary writable open first and falls back to `mode=ro` only when that open is refused for lack of write access ([#1416](https://github.com/robotrocketscience/aelfrice/issues/1416)). Against a writable store — every ordinary store — the handle is the writable one, so an observational command pays the whole open-time write window: the schema battery, the one-shot migrations, the scope-id mint, and the [#1314](https://github.com/robotrocketscience/aelfrice/issues/1314) expired-lock sweep. **The open order is unchanged, and nothing in `src/aelfrice/` moves here.** `benchmarks/store_open_cost.py` measures what the writable-first attempt costs on an already-migrated store at the repo-store layout, by installing a SQLite trace callback on the connection `MemoryStore` opens and reading the row count off that connection's own `total_changes`: 87 statements — 56 `CREATE`, every one of them `IF NOT EXISTS`, 26 `SELECT`, and 5 `PRAGMA` — against 5 statements for a `mode=ro` handle, so 82 statements are the whole of what reversing the order could recover. The open issues 0 `INSERT`, `UPDATE` or `DELETE` statements, mutates 0 rows, and changes 0 bytes of the database file. **The counts are a property of the shipped schema and not of the corpus**, and the producer refuses to publish a figure unless the census agrees at 200, 2,000 and 20,000 beliefs, so a count that starts moving with store size fails the gate instead of being averaged into one. On one machine at 20,000 beliefs the avoidable component's median is 0.298 ms, while `aelf stats` takes 10.0 ms in process and 307.3 ms as a process — an avoidable share of 2.99% of the work the command does and 0.097% of what a user waits for. **Those latencies carry no marker, deliberately.** A wall-clock reading is a property of the machine that took it, `--emit-figures` emits none, and `docs/design/derived_figure_markers.md`'s own rule is that a marker over a value nobody can recompute publishes a second unchecked number beside the first. The statement counts are store-free instead, because the producer builds its fixture from shipped code in a temporary directory: `scripts/check_derived_figures.py --mode producers` re-runs them on every pull request and hard-fails on a difference, which is the stronger of the two marker classes and the one a count is eligible for. **`--store` has no default, and it copies what it is given.** Nothing in the file calls `db_path()`, a run with no mode selected exits 2, and a named database is copied into a temporary directory before it is opened — opening a store is a write, so measuring one in place would mutate the corpus under measurement, which is [#1328](https://github.com/robotrocketscience/aelfrice/issues/1328) exactly. **Two shapes are published, because a census taken at the wrong path disagrees with itself**: outside the repo-store layout `repo_identity_from_db_path` returns no identity, the project-context backfill's marker probe drops out, and the same open issues 86 statements rather than 87 — a one-statement gap that is the likeliest way for a re-derivation of this issue to contradict the one recorded here. **The permanent deliverable is the invariant, not the number.** `tests/test_store_open_cost_1561.py` reds if a write enters the observational path: strip the completion-marker guard from `_maybe_backfill_project_context` and the open stamps `schema_meta` on every fire, which turns every read command into a writer and which nothing else in the suite would see — `tests/test_readonly_store_1416.py` compares the file bytes only on stores frozen at 0444, where the engine forbids the write regardless. **The zero-mutation claim is conditioned on the store being already migrated, and the condition is asserted rather than hedged.** A store carrying an unrun one-shot *is* migrated by an observational open, by design — the project-context backfill was measured stamping 301 rows on a 300-belief store that had never been opened with a repo identity — so the test builds one, counts the rows it is due to stamp off the fixture, and pins the write it performs. The guard therefore cannot be misread as "an observational open never writes", and a future change making the open unconditionally read-only reds here with the semantics it drops named. AC4 needed no new prose: the `show` row of `docs/user/COMMANDS.md` already documents the writable-first mechanism, the fallback, and the stale-lock consequence in full.

### Added

- **A `[store]` table in `.aelfrice.toml` gives a folder its own store ([#1796](https://github.com/robotrocketscience/aelfrice/issues/1796)).** In a repository that holds several projects, put `[store] path = ".aelfrice/store"` in each project folder's `.aelfrice.toml`, and each folder reads and writes its own store instead of the repository's shared one. The nearest `.aelfrice.toml` that holds a `[store]` table applies. Inside a git work tree, a nearer file without the table is passed over, so a config added to a subfolder for another setting can't move that subfolder to the shared store. A file above the git work-tree root or in your home directory is never read. The store resolves in this order: `AELFRICE_DB`, the `[store]` table, `<git-common-dir>/aelfrice/memory.db`, then `~/.aelfrice/memory.db`. A relative `path` resolves from the folder that holds the file, so each worktree gets its own store; an absolute or `~` path, or `git:<name>` for `<git-common-dir>/aelfrice/stores/<name>/memory.db`, is shared by every worktree. The value names the directory that holds `memory.db`, and a value ending in `.db` is an error, so each store owns its directory. A `[store]` table that names no usable store, such as a bad `git:` name, is an error that `aelf` reports with exit status 2; it never falls back to the shared store. A marker store takes its repository identity from its folder, and a `git:<name>` store from the repository and the name, so every worktree stamps the same value. It records the identity in an `identity` file beside it, so a copied store keeps its identity. `aelf status` now prints the store path and the rule that chose it (`env`, `marker`, `git`, or `global`), and `aelf doctor` prints the rule. The turn log for a marker store sits beside that store. The git post-commit hook ingests each commit into the store of every folder whose files it changed, and skips the commit when a marker is broken or a changed file sits below a folder it can't list or search. `aelf project-warm` warms the store of the folder you move into. Repositories without a `[store]` table resolve the same store as before, but the post-commit hook there also skips a commit that changes a file below a folder it can't list or search.

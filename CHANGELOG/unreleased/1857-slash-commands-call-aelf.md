### Fixed

- **Slash commands call `aelf` directly, so they no longer write to or fail on your project ([#1857](https://github.com/robotrocketscience/aelfrice/issues/1857)).** Every bundled `/aelf:*` command called `uv run aelf`. Under a `pyproject.toml`, that created `.venv` and `uv.lock` in your project, and it stopped before aelfrice started when uv couldn't resolve the project. A read-only uv cache also stopped it, and a different aelfrice in the project's environment shadowed your `uv tool` install. After you upgrade, run `aelf setup` to replace the installed copies. If `aelf` isn't on your `PATH`, a slash command now stops with `aelf: command not found`; to fix that, run `uv tool update-shell`, then open a new terminal. In a source checkout, a slash command now runs the `aelf` on your `PATH`, not the checkout's code, and an install that exists only as a project dependency, which isn't a supported channel, needs `aelf` on your `PATH`.

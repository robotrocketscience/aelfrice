### Fixed

- **Slash commands call `aelf` directly, so they no longer create `.venv` or `uv.lock` in your project or stop at uv's resolver ([#1857](https://github.com/robotrocketscience/aelfrice/issues/1857)).** Every bundled `/aelf:*` command called `uv run aelf`. Under a `pyproject.toml`, that created `.venv` and `uv.lock` in your project, and it stopped before aelfrice started when uv couldn't resolve the project. A read-only uv cache also stopped it, and a different aelfrice in the project's environment shadowed your `uv tool` install even when that environment wasn't active. An environment you activate still comes first on your `PATH`. After you upgrade, run `aelf setup` to replace the installed copies. If `aelf` isn't on your `PATH`, a slash command now stops with a command-not-found error; to fix that, run `uv tool update-shell`, open a new terminal, and restart any running agent. `uv tool update-shell` doesn't help with only a source checkout or a project dependency: activate its `.venv` before you start the agent, or install the tool. From a project whose environment holds aelfrice, `/aelf:setup` now writes `~/.claude/settings.json` instead of the project's settings unless that environment is active; if both files end up holding `aelf-hook`, `docs/user/SLASH_COMMANDS.md` says how to keep one.

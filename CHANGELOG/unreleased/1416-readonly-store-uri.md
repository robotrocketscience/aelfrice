### Fixed

- **A `#` or a `?` in the store's path made the read-only open read a different database, and create it ([#1416](https://github.com/robotrocketscience/aelfrice/issues/1416)).** `MemoryStore`'s read-only connect built its URI by string concatenation — `sqlite3.connect(f"file:{path}?mode=ro", uri=True)` — and a filesystem path is data, not a URI. `#` starts a fragment and `?` starts a second query string, so either character truncated the path **and** discarded `mode=ro`; SQLite then opened the shorter path read-**write** and created it as a zero-byte file. The #1416 schema floor found no tables in that empty file and told the user to grant write access and migrate a store that was already current — a wrong diagnosis, a stray file in a directory nobody asked it to write to, and the real store never read. Measured on SQLite 3.50.4: `<tmp>/store#1/memory.db` and `<tmp>/store?1/memory.db` both opened an empty database and left `<tmp>/store` behind, and `<tmp>/store%41/memory.db` failed outright with `unable to open database file`, because `%41` decodes to `A`. The URI is now built by `store.read_only_uri()`, which percent-encodes through `Path.as_uri()`.

  Absolutised with `os.path.abspath` rather than `Path.resolve()`, deliberately. `resolve()` follows symlinks, while `self._db_path` keeps the caller's spelling and is what places the `.bm25f` sidecar and fills the error strings, so resolving in the URI would let the engine's path and the store's reported path drift on a symlinked store. `abspath` normalises lexically only, which leaves symlink resolution with the OS exactly where the string form left it: for every path that already worked, the bytes opened are unchanged.

  The regression matrix is narrow on purpose. A space, an apostrophe and a non-ASCII letter all open correctly with the plain concatenation, so they prove nothing about this defect and are not in the tests. Nor is a bare `%1`: an incomplete escape is malformed, SQLite leaves it alone, and such a path opens either way — which is why the cases are whole directory names rather than one metacharacter spliced into a template.

  **Not verified on Windows, and not verified on a managed Codex host.** `tests/test_readonly_store_1416.py` is skipped entirely when `os.name == "nt"` and when the test runs as root, because it works by `chmod` and root ignores permission bits. The reproduction that motivated the issue is a sandboxed agent host whose `.git/` is not writable; what the tests reproduce is that shape built locally with `chmod`, not that host.

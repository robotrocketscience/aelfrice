### Fixed

- **Every locale-dependent text boundary now pins utf-8 ([#1441](https://github.com/robotrocketscience/aelfrice/issues/1441)).** `subprocess.run(..., text=True)` decodes the child's stdout through the *process locale* — the ANSI code page on Windows — so all 14 git and `gh` call sites in the package mangled non-ascii output. Text mode also uses **strict** errors, and cp1252 leaves five bytes undefined (`0x81 0x8d 0x8f 0x90 0x9d`) that UTF-8 multibyte sequences hit routinely, so it *raised*: `'東京'.encode()` is `e6 9d b1 e4 ba ac`. `UnicodeDecodeError` is a `ValueError`, not an `OSError`, so the `except (FileNotFoundError, OSError, subprocess.TimeoutExpired)` guards at `db_paths.py` and `hook_commit_ingest.py` did **not** catch it while both docstrings promised "returns None on any failure" — and `db_paths` runs on every hook fire, while `pre_issue_create_hook.run_guard` is called unguarded from `main()` on a blocking-capable PreToolUse hook. Every site now passes `encoding="utf-8"`, with `errors="replace"` at all but one, so no caller has to handle a decode error and mangled text beats a dead hook. Both except tuples also name `UnicodeDecodeError`; those arms are unreachable under `replace`, which never raises, so they exist to keep the docstrings true if a site is ever tightened — and one is. `db_paths._git_common_dir` decodes **strict**, because it is the one site whose value is *built on* rather than merely checked: it returns `Path(raw).resolve()` with no existence test, `db_path()` appends to that, and `_open_store()` calls `mkdir(parents=True)`, so a mojibake substitution would create a real second store under a garbled directory instead of falling back to `~/.aelfrice`. The four other git calls that produce a path — `working_state._run_git`, `federation._git_toplevel`, `doctor._derive_telemetry_path`, `project_warm._git_resolve` — degrade to a path that does not exist, which their callers already handle, so they keep `replace`. The same defect on the `Path` boundary is fixed too — 8 `write_text` and 1 `read_text` call took the locale encoding, and `federation.load_peer_deps` already passed `"utf-8"` *positionally* (`Path.read_text`'s first positional **is** `encoding`), normalised to the keyword only so the AST guard can see it. Reproduced end-to-end on an ubuntu runner, no Windows host needed: with UTF-8 mode and PEP 538 C-locale coercion both disabled the locale encoding is ASCII, which fails on exactly the same bytes. AST guards — not grep, because the kwarg can be spelled across lines and `read_text("utf-8")` passes it positionally — keep the whole class closed.

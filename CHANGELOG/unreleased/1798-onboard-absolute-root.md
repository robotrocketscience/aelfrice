### Fixed

- **`aelf onboard --emit-candidates` records the folder it scanned as an absolute path ([#1798](https://github.com/robotrocketscience/aelfrice/issues/1798)).** A run on a relative path, such as `/aelf:onboard .`, stored the path as typed in its onboard session, so the session named no folder once the shell that ran it was gone, and `aelf store split` could place its beliefs only by checking that their files existed under the work-tree root. The session now records the path resolved to an absolute folder, with symlinks followed. The scanner reads the same files as before. When a relative path can't be resolved because the current folder was removed or, on macOS, can't be searched, `aelf onboard`, with or without `--emit-candidates`, exits with status 2 and a one-line error, as `aelf store split` does, and records no session. Before, it scanned nothing and recorded the path as typed. Sessions recorded earlier keep their relative path.

### CI

- **The bench-gate quality tier now runs somewhere, and its report names the modules that did not ([#1477](https://github.com/robotrocketscience/aelfrice/issues/1477), [#1456](https://github.com/robotrocketscience/aelfrice/issues/1456) AC3).** #1456 recorded that the retrieval, compression and clustering gates "run lab-side only". They did not run anywhere: the private repository has **no `.github/workflows` directory at all**, so there was no host a lab-side job could have been added to, and `scripts/run_bench_gate.sh` — which exists and works — was invoked by nothing. Several defaults are held OFF pending exactly these verdicts, so those defaults were parked on a measurement that was not scheduled to happen. Operator ruling of 2026-08-11 puts the run at the release cut: `docs/concepts/RELEASING.md` step 7 is now mandatory and its output is pasted into the release PR. That is the only moment the verdicts are consumed, and a checklist step that blocks the cut cannot die unnoticed — which is the #1423 failure mode a weekly cron on one machine would have reproduced, and the corpus is in any case too thin for a weekly cadence to produce a new verdict. **The aggregate count #1456 shipped is the right answer only while the corpus is absent.** With no corpus, "36 skipped" is the whole story; the moment one exists, a run reports a healthy "N passed" while most of the tier skipped for want of rows, which is the same misreading one level in. The `bench-gate tier` block now separates three states and names them: tests that **executed** against the corpus, tests skipped because a named corpus **module** is missing or empty, and the whole tier skipped for want of a corpus root. Only the first is a verdict. Classification is by skip *reason* rather than by re-deriving which tests carry the marker, so an unrelated skip inside a bench-gated module is not folded into the missing-rows figure; executed tests are counted off the marker, the only place that signal survives to summary time. The report is driven against the hook with constructed reports, because the states that need pinning include ones this repository cannot produce — a module present and non-empty, so its gate actually ran — and a test that could only assert the locally reachable states would pin exactly the case that was never in doubt. It was verified against a real run as well: with a stub corpus holding one module, the block names every other module as having no verdict. Mutation-checked — dropping the per-module lines reddens three tests, counting executed tests without reading the marker reddens two, and collapsing *missing* and *empty* into one bucket reddens two.

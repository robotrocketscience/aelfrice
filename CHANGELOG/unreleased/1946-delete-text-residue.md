### Security

- **`aelf delete` no longer prints the belief text, and it clears the text from the ingest log ([#1946](https://github.com/robotrocketscience/aelfrice/issues/1946)).** The confirmation prompt used to print the full text to stderr, so deleting a lock that held a secret wrote the secret into terminals, transcripts, and logs. It now shows the id, the origin, and the creation date. If stdin is at end of file at the prompt, the command now says to pass `--yes`; piped input still works. A hard delete also left the text in `ingest_log.raw_text` and `raw_meta`. Each row whose derived beliefs are all gone now has an empty `raw_text`, and its `raw_meta` holds only the text's sha256 and the time the text was cleared; a row that still derives a live or retired belief keeps its text. `aelf doctor --replay` skips cleared rows and counts them on an `excluded (deleted)` line, so a deleted belief no longer reads as a `derived_orphan`. The failed-lock check that `aelf doctor` and SessionStart run matches a deleted lock through the kept hash. `aelf delete`, `aelf retire`, and `aelf restore` now take `--user` to act on the user store, as `aelf unlock --user` does, and `retire --user` names `restore --user` as its undo. A plain `delete` or `retire` of an id that only the user store holds names the `--user` form. Backups and copies of the store made before a delete keep the text, and so do `turns.jsonl`, `feed.jsonl`, `hook_audit.jsonl`, and `command_outcomes.jsonl`. The store file can keep pieces of it in its full-text search index and in pages SQLite hasn't overwritten ([#1961](https://github.com/robotrocketscience/aelfrice/issues/1961)).

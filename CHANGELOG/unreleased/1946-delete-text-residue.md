### Security

- **`aelf delete` no longer prints the belief text, and it clears the text from the ingest log ([#1946](https://github.com/robotrocketscience/aelfrice/issues/1946)).** The confirmation prompt used to print the full text to stderr, so deleting a lock that held a secret wrote the secret into terminals, transcripts, and logs. It now shows the id, the text's length, and the first 12 characters of the text's sha256. Without a terminal, the prompt reads no input and the command now says to pass `--yes`. A hard delete also left the text in `ingest_log.raw_text` and `raw_meta`. Each row whose derived beliefs are all gone now has an empty `raw_text`, and its `raw_meta` holds only the text's sha256 and the time the text was cleared; a row that still derives a live or retired belief keeps its text. `aelf doctor --replay` skips cleared rows and counts them on an `excluded (deleted)` line, so a deleted belief no longer reads as a `derived_orphan`. The failed-lock check that `aelf doctor` and SessionStart run matches a deleted lock through the kept hash. `aelf delete` and `aelf retire` now take `--user` to act on the user store, as `aelf unlock --user` does. Backups and copies of the store made before a delete keep the text, and the store file can keep pieces of it in unused pages and in its full-text search index.

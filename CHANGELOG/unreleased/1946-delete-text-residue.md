### Security

- **`aelf delete` no longer prints the belief text, and it clears the text from the belief's own ingest log rows ([#1946](https://github.com/robotrocketscience/aelfrice/issues/1946)).** The confirmation prompt used to print the full text to stderr, so deleting a lock that held a secret wrote the secret into terminals, transcripts, and logs. It now shows the id, the origin, and the creation date. If stdin is at end of file at the prompt, the command now says to pass `--yes`; piped input still works. A hard delete also left the text in `ingest_log.raw_text` and `raw_meta`. Each row whose derived beliefs are all gone now has an empty `raw_text`, and its `raw_meta` holds only the text's sha256 and the time the text was cleared; a row that still derives a live or retired belief keeps its text. `aelf doctor --replay` skips cleared rows and counts them on an `excluded (deleted)` line, so a deleted belief no longer reads as a `derived_orphan`. The failed-lock check that `aelf doctor` and SessionStart run matches a deleted lock through the kept hash. `aelf delete`, `aelf retire`, and `aelf restore` now take `--user` to act on the user store, as `aelf unlock --user` does, and `retire --user` names `restore --user` as its undo. A plain `delete`, `retire`, or `restore` of an id that only the user store holds names the `--user` form, and the `--user` form of an id that only the repository store holds names the plain form. These lines read the other store read-only, so they no longer sweep expired user locks. A delete can still leave the text in several places. Inside the store: a copy in the next sentence's log row (`derived_from.prior_text`), which ingest writes only when short fragments that aren't stored as beliefs sit between the two sentences; edge anchor text, log rows from deletes made before this release (which `aelf doctor --replay` can print), the full-text search index and unused page space ([#1961](https://github.com/robotrocketscience/aelfrice/issues/1961)), and the `memory.db.bm25f` search sidecar until a command or hook that can write the store rebuilds it. Outside it: backups and copies of the store made before the delete, `turns.jsonl`, `feed.jsonl`, `hook_audit.jsonl`, and `command_outcomes.jsonl`.

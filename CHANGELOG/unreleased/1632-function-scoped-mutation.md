### CI

- **The per-PR mutation job mutates the functions a PR changed, not the whole files they live in ([#1632](https://github.com/robotrocketscience/aelfrice/issues/1632)).** A real change to `cli.py` still put all of its roughly 11,000 lines in `only_mutate`, and the job was cancelled at its 60-minute limit with no report. The cost is in mutant generation, not only in running mutants: mutmut 3.8.0 writes each mutant as a full copy of its function, so generating a whole large file such as `cli.py` takes minutes and produces tens of thousands of mutants, and filtering mutant names after generation leaves that cost in place. `scripts/mutation_scope.py` now maps the PR's diff hunks to the functions they touch: module-level functions and methods of module-level classes, which are the only units mutmut mutates. It then marks every other function with mutmut's documented `# pragma: no mutate block`, in the CI checkout only, so mutmut never generates their mutants; with one function of `cli.py` in scope, generation takes seconds. A touched function whose code is unchanged once docstrings and comments are set aside, such as one that only moved or sits in a renamed file, stays out of scope. Changed lines outside every function, such as module-level statements and class bodies, carry no mutant under mutmut, and neither do decorated functions or the methods mutmut skips by name. The step summary lists each of these with its reason, along with every function in scope. The per-PR job now pins mutmut to 3.8.0, the version this behavior is verified on. `--write-pragmas` edits files under `src/` in place, so it refuses to run unless `CI` is `true` or you pass `--allow-src-rewrite`. `tests/test_mutation_function_scope_1632.py` covers the mapping.

### CI

- **The per-PR mutation job mutates the functions a PR changed, not the whole files they live in ([#1632](https://github.com/robotrocketscience/aelfrice/issues/1632)).** A real change to `cli.py` still put all of its roughly 11,000 lines in `only_mutate`, and the job was cancelled at its 60-minute limit with no report. The cost is in mutant generation, not only in running mutants: mutmut 3.8.0 writes each mutant as a full copy of its function, so generating `cli.py` alone produces 16,102 mutants in a 16-million-line file, and filtering mutant names after generation leaves that cost in place. `scripts/mutation_scope.py` now maps the PR's diff hunks to the functions they touch: module-level functions and methods of module-level classes, which are the only units mutmut mutates. It then marks every other function with mutmut's documented `# pragma: no mutate block`, in the CI checkout only, so mutmut never generates their mutants. A touched function whose code is unchanged once docstrings and comments are set aside, such as one that only moved, stays out of scope. Changed lines outside every function, such as module-level statements and class bodies, carry no mutant under mutmut. The step summary lists each of these with its reason, along with every function in scope. With one function of `cli.py` in scope, generation takes 2.8 seconds and produces 34 mutants, against 477 seconds before; you can reproduce both figures by calling `mutate_file_contents` from `mutmut.mutation.file_mutation` on the plain and the annotated file. `tests/test_mutation_function_scope_1632.py` covers the mapping.

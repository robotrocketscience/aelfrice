### Fixed

- **A stored prompt keeps its inline code and URLs ([#1874](https://github.com/robotrocketscience/aelfrice/issues/1874)).** Sentence extraction removed both, which left a hole in the sentence, so a search for the command or the link found nothing. Now `` Run `zqtool --check` before the release. `` stores whole, with its backticks, and `/aelf:search zqtool` finds it. Only the stored text changes: which sentences are stored, where they split, their type, the lock prompt, and autolock all read the sentence with the spans removed, as before. Fenced code blocks stay removed, as does text between backticks paired across lines. A URL with a query string or with a username or password stays removed, and so does inline code that holds a `KEY=value` assignment, a bearer token, or an `Authorization:` header. aelfrice still has no general secret scanner. A secret in plain text is stored as before, and the rule misses other shapes, such as `https://hooks.example.invalid/services/T0/B0/zqk-1234` or `` `ZQ_API_KEY: zqk-1234` ``; see [Secrets in your prompts](docs/user/PRIVACY.md#secrets-in-your-prompts). A stored path or URL now produces `file_path` and `url` entities, and a URL entity no longer takes a closing backtick, a trailing stop, or markdown emphasis, or loses to a path inside it. Existing beliefs don't change. The next ingest of a prompt with a kept span adds a whole belief next to the holed one, because a belief's id reads its exact text.

### Fixed

- **A stored prompt keeps its inline code and URLs ([#1874](https://github.com/robotrocketscience/aelfrice/issues/1874)).** Sentence extraction removed both, which left a hole in the sentence, so a search for the command or the link found nothing. Now `` Run `zqtool --check` before the release. `` stores whole, with its backticks, and `/aelf:search zqtool` finds it. Only the stored text changes: which sentences are stored, where they split, their type, the lock prompt, autolock, and the conflict and noise flags all read the sentence with the spans removed, as before. A sentence under 10 characters without its spans still isn't stored, so a search can't find ``Use `widget.py`!``. Fenced code blocks stay removed, as does text between backticks paired across lines, any span over 256 characters, and every span in a sentence over 1,024 characters. A URL with a query string or an `@` stays removed, and so does inline code that holds an `=` or a credential word such as `token:` or `bearer`, even when it isn't a secret. Inline code or a URL with a known vendor key prefix, a JSON Web Token, a private key header, or a long run that reads as random stays removed too. aelfrice still has no general secret scanner. A secret in plain text is stored as before, and the rule misses other shapes, such as `https://hooks.example.invalid/services/T0/B0/zqk-1234` or `` `zqk-1234` ``; see [Secrets in your prompts](docs/user/PRIVACY.md#secrets-in-your-prompts). Only the default transcript path keeps spans: a transcript ingested with `--source-label` stores as before. A kept span in a short clause between two stored sentences reaches the edge between them, so ``Use this one: `zqanchor` `` on its own line makes a search for `zqanchor` return both sentences; the shapes above stay out of that text too. A lock of a sentence you already typed reads the sentence with its spans removed, so a value in a span no longer flags a conflict with `AELF_SHOW_CONFLICTS=1`, whichever way you made the lock. A lock made before you type the sentence still reads as stored and still flags it. A stored path or URL now produces `file_path` and `url` entities, and a URL entity no longer takes a closing backtick, a trailing stop, or markdown emphasis, or loses to a path inside it. Existing beliefs don't change. The next ingest of a prompt with a kept span adds a whole belief next to the holed one, because a belief's id reads its exact text. A re-ingest also splits rows that earlier releases stored as one: ``Run `aaa` now for the widget.`` and ``Run `bbb` now for the widget.`` shared one holed row, and they store as two.

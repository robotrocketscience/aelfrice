### Added

- **Codex shows that aelfrice ran, and keeps its whole block in context ([#1812](https://github.com/robotrocketscience/aelfrice/issues/1812)).** Codex adds hook stdout to the model's context without showing it, and it saves any hook output over about 2,500 tokens to a file and gives the model only a preview. `aelf setup --host codex --status-message TEXT` now writes TEXT as the Codex `statusMessage` field of the retrieval, SessionStart, and stop handlers, where it used to exit 2 under #1429; the other claude-host options are still refused. Setup also writes `"additionalContextLimit": 9500` on the SessionStart, retrieval, and search-tool handlers, the 9,500-character bound aelfrice already puts on each hook's output, so Codex no longer cuts the block to a preview. A new opt-in, `[hook] summary_line` in `.aelfrice.toml` or `AELFRICE_HOOK_SUMMARY_LINE=1`, makes the Codex SessionStart hook print JSON: the same text as `hookSpecificOutput.additionalContext`, plus a `systemMessage` such as `aelfrice: 37 beliefs injected (37 locked)`. After a compaction the line also counts the beliefs in the rebuild block, and a fire that fails says `aelfrice: hook failed (DatabaseError)` instead of the empty-store line. It's off by default, and with it off the hook's stdout is unchanged. The hook learns it runs under Codex from a `--host codex` argument that setup now adds to the SessionStart command. **After you upgrade, run `aelf setup --host codex` again** to write the new fields and argument and to refresh the `$aelf-setup` skill, whose text now names `--status-message`. Then approve the changed entries with `/hooks` in a Codex session. Until you rerun setup, the hooks keep working as before, but `aelf doctor --host codex` exits 1 and names `aelf-setup` among the installed skills that don't match this build. A SessionStart wrapper script that added its own `systemMessage` is no longer needed; `docs/user/INSTALL.md` describes how to remove it. `aelf doctor --host codex` now exits 1 when two or more handlers in one event run the same aelfrice program as the first word of their command, such as `/usr/bin/env aelf-session-start-hook` beside the handler setup writes, because Codex then injects the baseline twice. Doctor reads a prefix word with its options, the operands of `env -u`, `-C`, and `-P`, `exec -a`, and `-o` after the `time` program, such as `/usr/bin/time`, and the words of an `env -S` string. A bare `time` is the shell's own `time`, which takes no `-o`, so `time -o FILE PROGRAM` runs nothing and doesn't count. Doctor counts what a line would run with GNU `env` and `time`, though macOS's `env` and `time` reject `--split-string`, `--chdir`, and `--output`. A `command` word with a `-v` or `-V` option, as in `command -pv`, only looks the program up, so it doesn't count. Two handlers count only when one fire runs both, with each matcher read the way Codex reads it. In SessionStart, PreCompact, and PostCompact, a copy under a `fork` group doesn't count beside setup's handler. In PreToolUse and PostToolUse, groups that list exact tool names count together only when one tool call matches both, where `apply_patch` also matches `Write` and `Edit`, and `spawn_agent` also matches `Agent`. Doctor skips a group whose matcher Rust's `regex` crate rejects, such as one with a look-ahead or an `x{`, because Codex skips it too, and names the group in a `[warn]` line when it holds a handler doctor counts. A matcher that Python's `re` can't read but Rust compiles, such as `\p{L}`, counts as matching every fire, with a `[warn]` line. A handler that names the program only in a wrapper argument, an `sh -c` script, a command substitution, or a later command gets a `[warn]` line that names the event and the handler when one fire runs it beside another handler of the program, and the exit code doesn't change, because doctor can't tell running the program from checking for it with `command -v` or `test -x`.

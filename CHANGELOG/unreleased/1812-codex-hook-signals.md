### Added

- **Codex shows that aelfrice ran, and keeps its whole block in context ([#1812](https://github.com/robotrocketscience/aelfrice/issues/1812)).** Codex adds hook stdout to the model's context without showing it, and it saves any hook output over about 2,500 tokens to a file and gives the model only a preview. `aelf setup --host codex --status-message TEXT` now writes TEXT as the Codex `statusMessage` field of the retrieval, SessionStart, and stop handlers, where it used to exit 2 under #1429; the other claude-host options are still refused. Setup also writes `"additionalContextLimit": 9500` on the SessionStart, retrieval, and search-tool handlers, the 9,500-character bound aelfrice already puts on each hook's output, so Codex no longer cuts the block to a preview. A new opt-in, `[hook] summary_line` in `.aelfrice.toml` or `AELFRICE_HOOK_SUMMARY_LINE=1`, makes the Codex SessionStart hook print JSON: the same text as `hookSpecificOutput.additionalContext`, plus a `systemMessage` such as `aelfrice: 37 beliefs injected (37 locked)`. After a compaction the line also counts the beliefs in the rebuild block, and a fire that fails says `aelfrice: hook failed (DatabaseError)` instead of the empty-store line. It's off by default, and with it off the hook's stdout is unchanged. The hook learns it runs under Codex from a `--host codex` argument that setup now adds to the SessionStart command. Setup's SessionStart matcher is now `startup|resume|clear|compact|fork`, so a forked thread gets the baseline block; the earlier `startup|resume|clear|compact` left out `fork`. **After you upgrade, run `aelf setup --host codex` again** to write the new fields, argument, and matcher and to refresh the `$aelf-setup` skill, whose text now names `--status-message`. Then approve the changed entries with `/hooks` in a Codex session. Until you rerun setup, the hooks keep working as before, but `aelf doctor --host codex` exits 1, names `aelf-setup` among the installed skills that don't match this build, and reports the SessionStart group under the earlier matcher as a stale install that a setup rerun fixes. A SessionStart wrapper script that added its own `systemMessage` is no longer needed; `docs/user/INSTALL.md` describes how to remove it. `aelf doctor --host codex` now exits 1 when two or more handlers in one event have a command byte-identical to a command `aelf setup --host codex` writes for the same aelfrice program, because Codex then starts that command once for each copy. Doctor compares commands character for character with what setup would write now, at any install path, and reads no shell syntax. It compares only handlers whose `type` is `command`, and on Windows it compares `commandWindows`, or its alias `command_windows`, when a handler has one, because Codex runs that field there instead of `command`. Any other handler whose `command`, `commandWindows`, or `command_windows` field contains an aelfrice program name anywhere, in any case, gets a `[warn]` line that names the handler and the command setup writes, and doctor exits 0. That includes `/usr/bin/env aelf-session-start-hook` beside the handler setup writes, `env -Saelf-session-start-hook`, `${CMD:-aelf-session-start-hook}`, a `python3 -c` script, a command substitution, a `PATH` setting, a redirect, and a command that only prints the name, such as `echo aelf-session-start-hook`. Only a name that the command builds at run time, or a link with another name, escapes the warning. Doctor reads the `[hooks]` table in `config.toml` as well as `hooks.json`, because Codex loads and runs the handlers in both, so a copy of setup's handler in `config.toml` counts as a second run. Doctor counts handlers only under the event names Codex reads, so a handler under another key, such as `Notification`, adds no run, and a handler there that names an aelfrice program gets a `[warn]` line. When Codex rejects all of `hooks.json` or all of the `[hooks]` table, for example over a handler with no `type`, an unknown `type`, a `command` handler with no `command`, or both `commandWindows` and `command_windows`, it loads no hook from that file. Doctor then counts nothing in it, says so in a `[warn]` line, and exits 1, as it does for a `hooks.json` that isn't valid JSON. Two handlers count only when one fire runs both, with each matcher read the way Codex reads it. In SessionStart, PreCompact, and PostCompact, the matcher matches the session source or the compaction trigger, so a copy under a `fork` group counts beside setup's handler. In PreToolUse and PostToolUse, groups that list exact tool names count together only when one tool call matches both, where `apply_patch` also matches `Write` and `Edit`, and `spawn_agent` also matches `Agent`. Doctor skips a group whose matcher Rust's `regex` crate rejects, such as one with a look-ahead or an `x{`, because Codex skips it too, and names the group in a `[warn]` line when it holds a handler that names an aelfrice program. A matcher that Python's `re` can't read but Rust compiles, such as `\p{L}`, counts as matching every fire, with a `[warn]` line. Doctor's check of Rust's syntax leaves out `(?-u)` restrictions, Unicode property names, and the compiled size limit, so for such a matcher doctor may count a group that Codex skips. Doctor prints the `[warn]` line only when one fire runs the handler beside another handler of the program.

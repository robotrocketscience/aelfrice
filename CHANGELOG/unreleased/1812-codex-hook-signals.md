### Added

- **Codex shows that aelfrice ran, and keeps its whole block in context ([#1812](https://github.com/robotrocketscience/aelfrice/issues/1812)).** Codex adds hook stdout to the model's context without showing it, and it saves any hook output over about 2,500 tokens to a file and gives the model only a preview. `aelf setup --host codex --status-message TEXT` now writes TEXT as the Codex `statusMessage` field of the retrieval, SessionStart, and stop handlers, where it used to exit 2 under #1429; the other claude-host options are still refused. Setup also writes `"additionalContextLimit": 9500` on the SessionStart, retrieval, and search-tool handlers, the 9,500-character bound aelfrice already puts on each hook's output, so Codex no longer cuts the block to a preview. A new opt-in, `[hook] summary_line` in `.aelfrice.toml` or `AELFRICE_HOOK_SUMMARY_LINE=1`, makes the Codex SessionStart hook print JSON: the same text as `hookSpecificOutput.additionalContext`, plus a `systemMessage` such as `aelfrice: 37 beliefs injected (37 locked)`. After a compaction the line also counts the beliefs in the rebuild block, and a fire that fails says `aelfrice: hook failed (DatabaseError)` instead of the empty-store line. It's off by default, and with it off the hook's stdout is unchanged. The hook learns it runs under Codex from a `--host codex` argument that setup now adds to the SessionStart command. Setup's SessionStart matcher is now `startup|resume|clear|compact|fork`, so a forked thread gets the baseline block; the earlier `startup|resume|clear|compact` left out `fork`. **After you upgrade, run `aelf setup --host codex` again** to write the new fields, argument, and matcher and to refresh the `$aelf-setup` skill, whose text now names `--status-message`. Then approve the changed entries with `/hooks` in a Codex session. Until you rerun setup, the hooks keep working as before, but `aelf doctor --host codex` exits 1, names `aelf-setup` among the installed skills that don't match this build, and reports the SessionStart group under the earlier matcher as a stale install that a setup rerun fixes. A SessionStart wrapper script that added its own `systemMessage` is no longer needed; `docs/user/INSTALL.md` describes how to remove it. `aelf doctor --host codex` now exits 1 when two or more handlers in one event run the same aelfrice program, such as `/usr/bin/env aelf-session-start-hook` beside the handler setup writes, because Codex then injects the baseline twice. A handler counts as a run only when doctor recognizes its command's shape: the program first or after `VAR=value` words, after the shell's own `time`, and after the prefix words `exec`, `exec -a NAME`, `command`, `env` with `-u NAME` or `-S STRING` before any `VAR=value`, `nice`, `nice -n N`, `nohup`, `timeout DURATION`, and the `time` program with an optional `-p`, all in one simple command of plain words. bash 3.2, bash 5.2, and zsh 5.9 each run the program for every command of these shapes. Any other handler that names the program gets a `[warn]` line instead, as do shapes that a shell runs another way: bash 3.2, bash 5.2, and zsh 5.9 run `time -o FILE PROGRAM` as `-o`, zsh 5.9 runs the `-p` in `time -p PROGRAM` and stops at `X=1 time PROGRAM` with a parse error, each shell looks for a program named `X=1` in `nice X=1 PROGRAM` and `'X=1' PROGRAM`, and bash 3.2 does the same for `if time X=1 PROGRAM; then :; fi`. Two handlers count only when one fire runs both, with each matcher read the way Codex reads it. In SessionStart, PreCompact, and PostCompact, the matcher matches the session source or the compaction trigger, so a copy under a `fork` group counts beside setup's handler. In PreToolUse and PostToolUse, groups that list exact tool names count together only when one tool call matches both, where `apply_patch` also matches `Write` and `Edit`, and `spawn_agent` also matches `Agent`. Doctor skips a group whose matcher Rust's `regex` crate rejects, such as one with a look-ahead or an `x{`, because Codex skips it too, and names the group in a `[warn]` line when it holds a handler doctor counts. A matcher that Python's `re` can't read but Rust compiles, such as `\p{L}`, counts as matching every fire, with a `[warn]` line. Doctor's check of Rust's syntax leaves out `(?-u)` restrictions, Unicode property names, and the compiled size limit, so for such a matcher doctor may count a group that Codex skips. A handler that names the program only in a wrapper argument, an `sh -c` script, a command substitution, or a later command gets a `[warn]` line that names the event and the handler when one fire runs it beside another handler of the program, and the exit code doesn't change, because doctor can't tell running the program from checking for it with `command -v` or `test -x`.

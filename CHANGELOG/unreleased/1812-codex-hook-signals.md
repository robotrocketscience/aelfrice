### Added

- **Codex shows that aelfrice ran, and keeps its whole block in context ([#1812](https://github.com/robotrocketscience/aelfrice/issues/1812)).** Codex adds hook stdout to the model's context without showing it, and it saves any hook output over about 2,500 tokens to a file and gives the model only a preview. `aelf setup --host codex --status-message TEXT` now writes TEXT as the Codex `statusMessage` field of the retrieval, SessionStart, and stop handlers, where it used to exit 2 under #1429; the other claude-host options are still refused. Setup also writes `"additionalContextLimit": 9500` on the SessionStart and retrieval handlers, the 9,500-character bound aelfrice already puts on each hook's output, so Codex no longer cuts the block to a preview. A new opt-in, `[hook] summary_line` in `.aelfrice.toml` or `AELFRICE_HOOK_SUMMARY_LINE=1`, makes the Codex SessionStart hook print JSON: the same text as `hookSpecificOutput.additionalContext`, plus a `systemMessage` such as `aelfrice: 37 beliefs injected (37 locked)`. After a compaction the line also counts the beliefs in the rebuild block, and a fire that fails says `aelfrice: hook failed (DatabaseError)` instead of the empty-store line. It's off by default, and with it off the hook's stdout is unchanged. The hook learns it runs under Codex from a `--host codex` argument that setup now adds to the SessionStart command. **After you upgrade, run `aelf setup --host codex` again** to write the new fields and argument, then approve the changed entries with `/hooks` in a Codex session. Until you do, the hooks keep working as before and `aelf doctor --host codex` still passes. A SessionStart wrapper script that added its own `systemMessage` is no longer needed; `docs/user/INSTALL.md` describes how to remove it. `aelf doctor --host codex` now exits 1 when more than one handler in one event runs the same aelfrice program, such as that wrapper beside the handler setup writes, because Codex then injects the baseline twice.

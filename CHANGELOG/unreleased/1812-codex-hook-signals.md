### Added

- **Codex shows that aelfrice ran, and keeps its whole block in context ([#1812](https://github.com/robotrocketscience/aelfrice/issues/1812)).** Codex adds hook stdout to the model's context without showing it, and it saves any hook output over about 2,500 tokens to a file and gives the model only a preview. `aelf setup --host codex --status-message TEXT` now writes TEXT as the Codex `statusMessage` field of the retrieval, SessionStart, and stop handlers, where it used to exit 2 under #1429; the other claude-host options are still refused. Setup also writes `"additionalContextLimit": 9500` on the SessionStart, retrieval, and search-tool handlers, the 9,500-character bound aelfrice already puts on each hook's output, so Codex no longer cuts the block to a preview. A new opt-in, `[hook] summary_line` in `.aelfrice.toml` or `AELFRICE_HOOK_SUMMARY_LINE=1`, makes the Codex SessionStart hook print JSON: the same text as `hookSpecificOutput.additionalContext`, plus a `systemMessage` such as `aelfrice: 37 beliefs injected (37 locked)`. After a compaction the line also counts the beliefs in the rebuild block, and a fire that fails says `aelfrice: hook failed (DatabaseError)` instead of the empty-store line. It's off by default, and with it off the hook's stdout is unchanged. The hook learns it runs under Codex from a `--host codex` argument that setup now adds to the SessionStart command. Setup's SessionStart matcher is now `startup|resume|clear|compact|fork`, so a forked thread gets the baseline block; the earlier `startup|resume|clear|compact` left out `fork`. **After you upgrade, run `aelf setup --host codex` again** to write the new fields, argument, and matcher and to refresh the `$aelf-setup` skill, whose text now names `--status-message`. Then approve the changed entries with `/hooks` in a Codex session. Until you rerun setup, the hooks keep working as before, but `aelf doctor --host codex` exits 1, names `aelf-setup` among the installed skills that don't match this build, and reports the SessionStart group under the earlier matcher as a stale install that a setup rerun fixes. A SessionStart wrapper script that added its own `systemMessage` is no longer needed; `docs/user/INSTALL.md` describes how to remove it. `aelf doctor --host codex` now exits 1 when two or more handlers in one event run the same aelfrice program as the first word of their command, such as `/usr/bin/env aelf-session-start-hook` beside the handler setup writes, because Codex then injects the baseline twice. Doctor reads a prefix word with its options, the operands of `env -u`, `-C`, and `-P`, `exec -a`, `timeout -s` and `-k`, `nice -n`, and `-o` after the `time` program, the duration after `timeout`, and the words of an `env -S` string, so `timeout 30 aelf-session-start-hook` counts. A `VAR=value` word after `nice`, `nohup`, `timeout`, `command`, `exec`, or the `time` program is the program that word runs, so `nice X=1 PROGRAM` doesn't count; only `env` reads it as an assignment. Doctor reads the command the way bash 3.2, bash 5.2, and zsh 5.9 each read it and counts it only when all three run the program. When they don't agree, the handler gets the `[warn]` line described below instead of the failure. The shell's own `time`, unquoted at the start of a command, takes no `-o`, so `time -o FILE PROGRAM` runs `-o` in those three shells and doesn't count. A quoted or escaped `time`, such as `\time` or `'time'`, and `/usr/bin/time` are the `time` program, which takes `-o FILE`. bash 5.2 reads the second `time` in `time time -o FILE PROGRAM` as its own `time` too, zsh 5.9 rejects `X=1 time PROGRAM` as a parse error, and zsh 5.9 runs the `-p` in `time -p PROGRAM` as the program, so each of these gets the `[warn]` line. Doctor counts what a line would run with GNU `env` and `time`, though macOS's `env` and `time` reject `--split-string`, `--chdir`, and `--output`. A `command` word with a `-v` or `-V` option, as in `command -pv`, only looks the program up, so it doesn't count. Two handlers count only when one fire runs both, with each matcher read the way Codex reads it. In SessionStart, PreCompact, and PostCompact, the matcher matches the session source or the compaction trigger, so a copy under a `fork` group counts beside setup's handler. In PreToolUse and PostToolUse, groups that list exact tool names count together only when one tool call matches both, where `apply_patch` also matches `Write` and `Edit`, and `spawn_agent` also matches `Agent`. Doctor skips a group whose matcher Rust's `regex` crate rejects, such as one with a look-ahead or an `x{`, because Codex skips it too, and names the group in a `[warn]` line when it holds a handler doctor counts. A matcher that Python's `re` can't read but Rust compiles, such as `\p{L}`, counts as matching every fire, with a `[warn]` line. Doctor's check of Rust's syntax leaves out `(?-u)` restrictions, Unicode property names, and the compiled size limit, so for such a matcher doctor may count a group that Codex skips. A handler that names the program only in a wrapper argument, an `sh -c` script, a command substitution, or a later command gets a `[warn]` line that names the event and the handler when one fire runs it beside another handler of the program, and the exit code doesn't change, because doctor can't tell running the program from checking for it with `command -v` or `test -x`.

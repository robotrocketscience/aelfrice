### Fixed

- **Wonder GC, `aelf doctor --retire-scheduled-prompts`, and `aelf doctor --prune-noise` record each belief they retire ([#2019](https://github.com/robotrocketscience/aelfrice/issues/2019)).** These passes set `valid_to` on a belief without writing a `feedback_history` row, so nothing recorded when or why the belief left retrieval. `aelf retire` and `aelf restore` already wrote one. Each pass now writes one row of valence 0 per retired belief, in the same transaction as the retirement, so a failure leaves neither: wonder GC writes `wonder_gc:retire`, the scheduled-prompt pass writes `scheduled_prompt:retire`, and `--prune-noise` writes `prune_noise:retire`. A dry run writes nothing, and posteriors don't change. Beliefs retired before this release get no row, and `aelf migrate` writes none. The wonder GC exemption and `EXPOSURE_ONLY_FEEDBACK_SOURCES` don't change: a phantom you bring back with `aelf restore` gets a `user_restored` row, so GC doesn't collect it again. The new rows count toward the `aelf status` feedback count, the per-session `feedback_given` count in telemetry, and the health total. A belief retired by one of these passes is no longer eligible for `aelf clamp-ghosts`, which takes only beliefs with no feedback row. Every shipped restore path (`aelf restore`, `aelf doctor --restore-relay-rows`, and an explicit re-assertion) already writes its own feedback row, so the new row changes nothing for a restored belief, including its place in the exploration pool. Retrieval output doesn't change, because a retired belief isn't retrieved.

  To upgrade, you don't need to do anything.

  - On by default: yes. No setting turns the rows off.
  - Reached from the hook path: yes. The SessionStart hook runs wonder GC once per session unless `AELFRICE_WONDER_AUTOGC=0` is set. The two doctor passes run only when you invoke them.
  - Measured on: one batch of 500 retirements on a temporary store, on a loaded macOS machine. With the row, the median of 5 runs was 85 ms, against 67 ms for the retirement alone. Wonder GC and `--prune-noise` already committed once per belief, and each belief is now one transaction that holds both writes. The scheduled-prompt pass keeps its single transaction.

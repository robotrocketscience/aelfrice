### Fixed

- **A user lock inside a `<cadence-resume>` recap is a lock again, and a reference lock's only element render survives the trim ([#1570](https://github.com/robotrocketscience/aelfrice/issues/1570)).** `hook.py` recognised a user lock by the literal `lock="user"`; `context_rebuilder.py` renders one `locked="true"`. The two spellings never met on the ordinary hook path, so nothing had failed — but the [#871](https://github.com/robotrocketscience/aelfrice/issues/871) recap is rebuilder output spliced into a hook-rendered envelope, and there the ceiling's dropper could not see that an element was a lock. [#1564](https://github.com/robotrocketscience/aelfrice/issues/1564)'s lock exemption therefore never fired on shipped output, and the [#379](https://github.com/robotrocketscience/aelfrice/issues/379) always-injected contract did not hold on that path. `hook._element_is_locked` reads both spellings now. **The hook was widened and the rebuilder was left alone**, for two reasons: the rebuilder's attribute is a published output schema with consumers this module does not own — the `<aelfrice-rebuild>` block the PreCompact lane writes straight to stdout, `docs/design/context_rebuilder.md`, and the `locked="false"` half of the pair, which has no counterpart in `lock="user"` — and the recap is read out of `cadence_resume_cache.json`, which a prior session wrote and which stays injectable for an hour, so an upgrade inside that window hands the hook a recap the previous version rendered. A hook that knew only one spelling would breach #379 again one release later, whichever spelling that was. The enumeration of what reads the rebuilder's attribute outside the hook is in `tests/test_recap_lock_spelling_1570.py`, alongside the guard that pins the rebuilder's emitted schema so a later change to it reds a test that names those consumers.

  **What the exemption keys on is "the last render of a lock", not "a lock".** Exempting every recognised lock was implemented first and reverted on measurement: `<locked>` renders the same locks uncapped a few lines below in the same envelope, so on the `--resume-drop` fixture's 40 locks it pinned about 2,000 tokens of duplicate text and took the prompt's own matched beliefs from 6 of 6 to 0 — #1564's AC3 loss, restaged by the fix. `_recap_shed` now keeps a recap element only when nothing outside the recap renders that id, which is the rule its caller already applied to `dropped_ids`, and the invariant both halves serve is single: no user-locked id ever reaches `dropped_ids`. On a store of frozen locks that keeps the recap shedding whole, wrapper included, and `scripts/measure_block_ceiling.py --resume-drop` reports the same 65 → 0 elements and 6 → 6 matched beliefs as before.

  **The class this changes is the [#1558](https://github.com/robotrocketscience/aelfrice/issues/1558) reference lock**, whose `<locked>` render is a `ref` manifest line rather than an element. Its bounded-topic element in the recap is the only element render of that content in the envelope, so shedding it removed the content from the fire while leaving a manifest line naming it. That element is now kept and the wrapper with it. Reachability is narrow: cadence is `DEFAULT_ENABLED = False`, so only an opt-in install with a resume cache, a reference lock, and a block over its ceiling was affected. Guards are mutation-proven one claim at a time in `tests/test_recap_lock_spelling_1570.py` — including the reverted over-broad exemption, which reds the arm that measures the prompt's own hits.

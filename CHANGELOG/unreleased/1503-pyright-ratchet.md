### CI

- **`pyright` is enforced, and the four documents that claimed it already passed are corrected ([#1503](https://github.com/robotrocketscience/aelfrice/issues/1503)).** `RELEASING.md` step 6 ran `uv run pyright src/` with the comment `# strict`, implying it passes; the baseline that landed with #1503 — `git show ce9e5461:pyright_baseline.json` — records **987 errors over 76 files**, and no workflow anywhere ran pyright, so the tick was self-reported and unenforced. `CONTRIBUTING.md` asserted "`pyright --strict` must pass", the pull-request template carried "strict, no new errors", and the cost is on the record — `CHANGELOG/v4.md` notes a `NameError` that reached `main` behind this check. The operator ruling of 2026-08-19 was to drive the count to zero with a required CI job, and the ruling of 2026-08-26 **cancelled that burn-down**: the ratchet is the whole answer, so the count falls only as a side effect of other work and nothing drives it on a schedule. `scripts/check_pyright_baseline.py` holds a **per-file** baseline in `pyright_baseline.json` and fails when any file's count rises — a repo-wide total would let a fix in one module pay for a regression in another, by unrelated authors in unrelated changes. The `pyright-ratchet` workflow runs it on every pull request with no `continue-on-error`, because a gate that cannot fail is the self-reported tick wearing a CI badge. Scope is `pyright src/`, the command the documents named, over the code that ships: `pyproject.toml` also includes `tests`, and the count over both trees is several times the `src/` one; freezing that today would make every test edit fight the ratchet — so `tests/` is explicitly not gated and the script's docstring says so rather than letting the job name imply full coverage. No document records the wider figure, because it moves with every test edit; `uv run pyright` with no path argument reproduces it. `tests/test_pyright_ratchet_1503.py` pins that the baseline exists and is non-empty (an empty baseline passes everything), that the workflow runs the checker and can fail, and that no document re-asserts the unqualified claim. Two things are reconciled at the close.

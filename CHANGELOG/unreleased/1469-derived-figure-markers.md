### CI

- **A published figure now names the script that re-derives it, and CI checks it ([#1469](https://github.com/robotrocketscience/aelfrice/issues/1469)).** Six of eight PRs reviewed in the 2026-08-10 board sweep shipped at least one stale or false published figure; every one was caught by a reviewer re-deriving it by hand, and none by CI. A figure now carries a machine-readable marker naming its producer, the key that producer emits it under, and the published value — `<!-- derived: benchmarks/published_constants.py#stop_prompt_max_items = 20 -->` — in the same syntax in a CHANGELOG entry and in a Python comment, because six of the seven instances shipped in source as well as in the CHANGELOG and #1445's number shipped in three files. **A marker's value must also be a figure in the text it annotates**, and that is the link the rest of the gate does not make. Producer checks bind the producer to the marker; self-consistency binds markers to each other; neither reads the number a reader sees, so both stay green while the prose says something else — the failure mode this entry is about, reproduced through this entry's own gate. The session-end item cap is 20, so a marker over it is now held to a 20 being there: editing a published byte count and leaving its marker alone is a hard failure, and so is the repair path of bumping every marker to a new value while leaving the sentences around them unchanged. In a Python file the scope is the comment run the marker sits in, not the paragraph, so the assignment two lines below cannot stand in for the sentence above. The direction is marker → prose only; an unmarked figure stays grandfathered. **Scoping is per file type.** A `- ` line anywhere in a file used to put the whole file into changelog-bullet mode, which silently switched the overclaim rule off on 228 of the 929 scanned files and discarded every line above the first bullet; bullets are now markdown-only, and every non-blank line lands in exactly one entry, asserted over the whole corpus rather than claimed. **The gate is split, and the marker says which half a figure is in.** A marker with no `corpus=` is store-free: `scripts/check_derived_figures.py --mode producers` runs the producer and hard-fails on any difference between what it emits and what the prose published. A marker carrying `corpus=<label>@<date>` is store-backed — `stop_prompt_block_bounds.py`, `scan_admission_funnel.py` and `sidecar_rebuild_rate.py` read a real belief store, a public runner has none, and the lab corpus does not go there (#1456) — so the marker records which store on which day, and CI checks the two things it still can: that every file publishing one figure agrees on its value (**hard**; this is the check #1449 needed for its 44,683-against-44,687 in one PR, and no store is needed to run it — though neither of those two figures is annotated yet, so that instance is still only in `--list-unmarked`), and whether the producer's source has moved since the figure was stamped (**advisory**; a producer edit does not prove the figure moved, and #1445 is the clean example of one that did). **Running the store-backed producers in public CI is not attempted rather than attempted and skipped.** A job that fails for want of a corpus gets switched off within a week, and a check that reports a pass it did not run is the #1160 defect this repo has already paid for. **An unmarked figure stays legal**, because the annotation backlog is the whole corpus and a gate that failed on it would last a day — but `--list-unmarked` enumerates it, so grandfathered is not the same as invisible. **The one claim that is not grandfathered is the overclaim sentence.** The shape `` `<script>` re-derives every figure here `` shipped in #1445 and #1447 over scripts emitting about a third of the entry's numbers; it is now permitted only in an entry where every figure carries a marker, and that check is hard. The one live instance in `CHANGELOG/v4.md` did not survive it: `benchmarks/spine_fan_in_baseline.py` emits six of that entry's figures and not the rest, and the sentence now says so. Quoting the sentence inside backticks is how it stays discussable: inline code is a citation, not a claim, and this entry would otherwise fail its own gate -- which is how the exemption was found. **The stamp is excluded from the bytes it stamps** — found by running `--restamp` twice and getting two different hashes, because a producer that documents its own figures has no fixed point otherwise. The seven #1469 figures were re-verified rather than taken from the issue: five had already been corrected on `main`, `RetrievalCache`'s ship version was still wrong in five places in `docs/design/bfs_multihop.md` (v1.0.1 is what its spec targeted; `class RetrievalCache` is absent at v1.0.2 and present at v1.0.3, added by `0c27a937`) and is corrected, and the two belief-count figures need a store to re-derive and are left as measured, now carrying the corpus and date that distinguish them.

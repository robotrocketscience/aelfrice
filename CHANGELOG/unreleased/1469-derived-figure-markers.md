- **A published figure now names the script that re-derives it, and CI checks it ([#1469](https://github.com/robotrocketscience/aelfrice/issues/1469)).** Six of eight PRs reviewed in the 2026-08-10 board sweep shipped at least one stale or false published figure; every one was caught by a reviewer re-deriving it by hand, and none by CI. A figure now carries a machine-readable marker naming its producer, the key that producer emits it under, and the published value — `<!-- derived: benchmarks/published_constants.py#stop_prompt_max_items = 20 -->` — in the same syntax in a CHANGELOG entry and in a Python comment, because six of the seven instances shipped in source as well as in the CHANGELOG and #1445's number shipped in three files. **A marker's value must also be a figure in the text it annotates**, and that is the link the rest of the gate does not make. Producer checks bind the producer to the marker; self-consistency binds markers to each other; neither reads the number a reader sees, so both stay green while the prose says something else — the failure mode this entry is about, reproduced through this entry's own gate. The session-end item cap is 20, so a marker over it is now held to a 20 being there: editing a published byte count and leaving its marker alone is a hard failure, and so is the repair path of bumping every marker to a new value while leaving the sentences around them unchanged. In a Python file the scope is the comment run the marker sits in, not the paragraph, so the assignment two lines below cannot stand in for the sentence above. The direction is marker → prose only; an unmarked figure stays grandfathered. **Scoping is per file type.** A `- ` line anywhere in a file used to put the whole file into changelog-bullet mode, so a list in a Python docstring switched the overclaim rule off for that whole file, and every line above the first bullet was discarded. **How many files that was is deliberately not published**: the only honest denominator is the scanned corpus, which moves on every merge, so the share would be stale the day after it was written — which is the defect this entry exists to stop. Bullets are now markdown-only, and every non-blank line lands in exactly one entry, asserted over the whole corpus rather than claimed. **The gate is split, and the marker says which half a figure is in.** A marker with no `corpus=` is store-free: `scripts/check_derived_figures.py --mode producers` runs the producer and hard-fails on any difference between what it emits and what the prose published. A marker carrying `corpus=<label>@<date>` is store-backed — `stop_prompt_block_bounds.py`, `scan_admission_funnel.py` and `sidecar_rebuild_rate.py` read a real belief store, a public runner has none, and the lab corpus does not go there (#1456) — so the marker records which store on which day, and CI checks the two things it still can: that every file publishing one figure agrees on its value (**hard**; this is the check #1449 needed for its 44,683-against-44,687 in one PR, and no store is needed to run it — though neither of those two figures is annotated yet, so that instance is still only in `--list-unmarked`), and whether the producer's source has moved since the figure was stamped (**advisory**; a producer edit does not prove the figure moved, and #1445 is the clean example of one that did). **Running the store-backed producers in public CI is not attempted rather than attempted and skipped.** A job that fails for want of a corpus gets switched off within a week, and a check that reports a pass it did not run is the #1160 defect this repo has already paid for. **An unmarked figure stays legal**, because the annotation backlog is the whole corpus and a gate that failed on it would last a day — but `--list-unmarked` enumerates it, so grandfathered is not the same as invisible. **That last clause was false as first written, and a code span whose whole content is a number is now a figure.** Inline code was masked before extraction, so the hard overclaim rule below was satisfiable by typing two backticks, and the two headline shares of `CHANGELOG/v4.md`'s #1356 entry — published in code font, which is this repo's style for a measured value — appeared in nothing `--list-unmarked` printed. A span carrying anything else stays masked, because a false positive there makes the overclaim rule unsatisfiable, which is the same as deleting it. The narrowing is priced rather than asserted: `--mask-delta` reports how many figures each candidate rule makes visible on the tree it is run against, and no share is published here because that denominator moves on every merge. **The residue is documented, not closed**: a figure inside a span that also carries words is still invisible. **The one claim that is not grandfathered is the overclaim sentence.** The shape `` `<script>` re-derives every figure here `` shipped in #1445 and #1447 over scripts emitting about a third of the entry's numbers; it is now permitted only in an entry where every figure carries a marker, and that check is hard.

### Internal

- **A fire census reports which features have fired in copies of your stores ([#1887](https://github.com/robotrocketscience/aelfrice/issues/1887)).** `python -m benchmarks.real_store_fire_census` runs one read-only probe per feature on `main` and reports one of five statuses for each store, with integer counts only: `fired` (a trace only this feature leaves), `ambiguous` (a trace another writer also leaves), `silent` (no trace where one would be), `untraceable` (the store can't show whether the feature ran), or `error` (an exception, or a trace that breaks the feature's own contract). It reads only copies that `python -m benchmarks.real_store_fire_census.copy_store` made. The helper reads the source as plain bytes without following symlinks, retries only when a writer changes a db while it reads, exits with status 1 after 20 busy attempts, and writes a copy manifest last that lists every file it copied with its inode, link count, size, and mtime. Every file the runner reads must be listed in that manifest and still match it, or the run exits with status 2; `--global-dir` must hold its own manifest. The checks prevent accidents, such as a live store, a stale path, or a symlink, and don't defend against a hand-written manifest. Stores appear in the output as opaque labels such as `store01`; the map from labels to paths is written only to the file that you name with `--labels-out`, which must sit outside the repository and outside every copy. Tests build stores with aelfrice's own code. Every traceable probe has a test in which it reports `fired` or `ambiguous` except the 9 listed in `benchmarks/real_store_fire_census/README.md`, which also lists the 7 that no test sees report `silent` and says how to run the census.

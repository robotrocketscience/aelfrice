### Internal

- **A fire census reports which features have fired in copies of your stores ([#1887](https://github.com/robotrocketscience/aelfrice/issues/1887)).** `python -m benchmarks.real_store_fire_census` runs one read-only probe per feature on `main` and reports `fired`, `silent`, or `untraceable` for each store, with integer counts only. It reads copies, never live stores: it refuses any path that resolves, through symlinks and in any letter case, into a `.git` folder, under `~/.aelfrice`, to the `$AELFRICE_DB` store, or to a `[store]` marker store, and it opens each `memory.db` with `mode=ro` and `immutable=1`, so it changes no byte beside the store. `python -m benchmarks.real_store_fire_census.copy_store` copies a store folder without writing under it, falls back to sqlite's backup API when a writer keeps the store busy, and folds the WAL into the copy. Stores appear in the output as opaque labels such as `store01`; the map from labels to paths is written only to the file that you name with `--labels-out`, which must sit outside the repository. Tests build stores with aelfrice's own code. Every traceable probe has a test in which it reports `fired` except the 12 listed in `benchmarks/real_store_fire_census/README.md`, which also lists the 7 that no test sees report `silent` and says how to run the census.

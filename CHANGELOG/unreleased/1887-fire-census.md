### Internal

- **A fire census reports which features have fired in copies of your stores ([#1887](https://github.com/robotrocketscience/aelfrice/issues/1887)).** `python -m benchmarks.real_store_fire_census` runs one read-only probe per feature on `main` and reports `fired`, `ambiguous`, `silent`, or `untraceable` for each store, with integer counts only. `ambiguous` means the probe found a trace that another writer also leaves. It reads only copies that `python -m benchmarks.real_store_fire_census.copy_store` made: the helper writes a copy token that records each db's device, inode, size, mtime, and link count, and the runner refuses any store folder without a token that matches. It opens each db through a descriptor whose inode it checks against the token, with `mode=ro` and `immutable=1`, so it changes no byte beside the store. The copy helper reads the source as plain bytes without following symlinks, retries only when a writer changes a db while it reads, and exits with status 1 after 20 busy attempts. Stores appear in the output as opaque labels such as `store01`; the map from labels to paths is written only to the file that you name with `--labels-out`, which must sit outside the repository. Tests build stores with aelfrice's own code. Every traceable probe has a test in which it reports `fired` or `ambiguous` except the 9 listed in `benchmarks/real_store_fire_census/README.md`, which also lists the 7 that no test sees report `silent` and says how to run the census.

### Fixed

- **`aelf doctor --host codex` fails when the installed wiring can't reach `aelf`, and the Codex hooks feature is named correctly ([#1413](https://github.com/robotrocketscience/aelfrice/issues/1413), partial).** `uv tool install aelfrice` is the one supported channel and it puts `aelf` in a bin directory, so a host whose `PATH` doesn't resolve `aelf` has that directory off `PATH` and can't run any documented `aelf …` command by name — and doctor, the one surface that could have said so, exited 0. It now appends a `[FAIL]` line naming the `uv tool install aelfrice` and `uv tool update-shell` remedy, and exits 1, under the operator ruling of 2026-08-12: the check fires only when `launcher.which_on_path("aelf")` is `None` **and** `report.owned_handler_count` is greater than zero. That gate is the same one [#1430](https://github.com/robotrocketscience/aelfrice/issues/1430) already ratified for this command — absent wiring stays exit 0, so a source checkout and this repo's own CI, neither of which has a `uv tool` install, stay green. The line reports the `PATH` state itself and claims nothing beyond it: the generated skills still route through `uv run aelf`, and `aelf setup --host codex` pins each hook handler to an absolute `aelf-*` path whenever it can resolve one, so neither surface necessarily breaks the moment `aelf` leaves `PATH`. `docs/user/SLASH_COMMANDS.md` also told you to turn on a `codex_hooks` feature flag that Codex retired after 0.12x; `codex features list` on codex-cli 0.145.0 reports one row for it, `hooks stable true`, and no `codex_hooks` row at all. The caveat now names `hooks`, says it's on by default, points at `[features].hooks = false` as the only setting you need to act on, and records that doctor treats that setting as a `[FAIL]` and exit 1 once the handlers are installed; doctor keeps honoring the legacy key when an old `config.toml` carries it, and the doc says so. The rest of the issue — replacing the `uv run aelf` invocations in the generated skills, re-derived on this branch as 96 of them across all 31 skills — stays open, because changing the generated skill bytes makes every already-installed Codex skill differ from the build and needs a Codex host to verify.

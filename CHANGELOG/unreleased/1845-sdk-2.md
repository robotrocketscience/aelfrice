### Changed

- **The LLM classifier runs on SDK 2.x, sends the key as a bearer token, and sets no temperature ([#1845](https://github.com/robotrocketscience/aelfrice/issues/1845)).** This is breaking for gateway users, as the migration notes below describe. A 401 or 403 now prints the status and the error type, if it's one the API documents, instead of the response's text, which can echo the key. The classifier makes its own retries: up to 3 attempts on a 408, 409, 429, 5xx, refused connection, or timeout, or on any status whose response sends `x-should-retry: true` except a 401 or 403. Where SDK 2.x waits as long as `Retry-After` asks, the classifier obeys a wait of up to 60 seconds and backs off for 0.5 seconds, then 1 second, past that, as SDK 0.97.0 did. A wait longer than 1 second prints one line on stderr. The `requests` value in the telemetry line counts each attempt that sent a request. During the call, aelfrice holds the SDK's and the HTTP library's loggers, child loggers included, at `WARNING` and then restores each level, so `ANTHROPIC_LOG=debug` prints nothing during the call. The consent prompt no longer cites a macro-F1 figure that no in-tree measurement backs, and it says that labels can vary between runs.

  Migration, classification: the classifier used to send temperature 0. SDK 2.x doesn't take the keyword, so the API's default sampling applies, and two onboard runs can label a sentence differently, including whether to keep it. A belief already in the store keeps its label when you onboard again. To get repeatable labels, use `--llm-classify=false`, which runs the regex classifier.

  Migration, gateways: SDK 2.x sends the API key as `Authorization: Bearer <key>` and sends no `X-Api-Key`. If you set `ANTHROPIC_BASE_URL` to a gateway that reads only `X-Api-Key`, onboard stops with exit 1 on the gateway's 401 until you change the gateway or set `ANTHROPIC_CUSTOM_HEADERS="X-Api-Key: <key>"`, which sends the key in both headers. With that setting, a gateway that redirects to another host, port, or scheme sends your key to the redirect's target, because the HTTP library drops `Authorization` on such a redirect and keeps `X-Api-Key`. The gateway must also accept the newer API version header and a body with no `temperature`. `ANTHROPIC_AUTH_TOKEN` is no longer sent alongside the key. For the full list, see `docs/design/llm_classifier.md`, section Gateway requirements.

### Changed

- **The `[onboard-llm]` extra moves to SDK 2.x, and the classifier no longer sets a temperature ([#1845](https://github.com/robotrocketscience/aelfrice/issues/1845)).** The extra now requires SDK `>=2,<3`. The previous release allowed any SDK from 0.40 up, so a new install could resolve 1.0 or later, where every classifier request raised `TypeError` before it was sent and `aelf onboard --llm-classify` fell back to the regex classifier without an error ([#1844](https://github.com/robotrocketscience/aelfrice/issues/1844)). If you installed the extra with `uv tool install "aelfrice[onboard-llm]"`, run `uv tool upgrade aelfrice`. A 401 or 403 now prints the status and the error type instead of the response's text, which can echo the key. aelfrice also holds the SDK's and the HTTP library's loggers at `WARNING`, so `ANTHROPIC_LOG=debug` no longer prints anything during an aelfrice run.

  Migration, classification: the classifier used to send temperature 0. SDK 2.x doesn't take the keyword, so the API's default sampling applies, and two onboard runs can label a sentence differently, including whether to keep it. A belief already in the store keeps its label when you onboard again. To get repeatable labels, use `--llm-classify=false`, which runs the regex classifier.

  Migration, gateways: SDK 2.x sends the API key as `Authorization: Bearer <key>` and sends no `X-Api-Key`. If you set `ANTHROPIC_BASE_URL` to a gateway that reads only `X-Api-Key`, onboard stops with exit 1 on the gateway's 401 until you change the gateway or set `ANTHROPIC_CUSTOM_HEADERS="X-Api-Key: <key>"`, which sends the key in both headers. The gateway must also accept the newer API version header and a body with no `temperature`. `ANTHROPIC_AUTH_TOKEN` is no longer sent alongside the key. For the full list, see `docs/design/llm_classifier.md`, section Gateway requirements.

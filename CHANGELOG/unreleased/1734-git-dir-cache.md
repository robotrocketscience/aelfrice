### Performance

- **The prompt hook asks git for the repository's location once per prompt instead of five times ([#1734](https://github.com/robotrocketscience/aelfrice/issues/1734)).**
  - **Before:** every lookup of the store, the repository identity, and the turn log ran its own `git rev-parse --git-common-dir`. One prompt ran it 5 times, or 6 times on the first prompt that creates the store. Each call took about 44 ms on a loaded machine.
  - **Now:** the answer is cached for the life of the process, keyed on the working directory and the environment variables that choose which repository git finds (`GIT_DIR`, `GIT_COMMON_DIR`, `GIT_WORK_TREE`, `GIT_CEILING_DIRECTORIES`, and `GIT_DISCOVERY_ACROSS_FILESYSTEM`). A "not in a repository" answer is cached too, so the fallback stays the same on every call. A lookup that times out is not cached: the next call asks git again, because a loaded machine can answer it.
  - **Measured:** over 15 interleaved runs of the prompt hook in one repository, the median wall time fell from 458 ms to 256 ms.
  - **Limits:** the key leaves out other inputs, such as `PATH` and git's config variables, which aelfrice never changes mid-process. A process that runs `git init` in a directory it has already looked up keeps the old answer until it calls `db_paths.clear_git_common_dir_cache()`. No aelfrice command does either; the test suite clears the cache before each test.

### Fixed

- **`BASH_FIRE_CAP_PER_TURN` now binds, because its counter moved to the session ring ([#1522](https://github.com/robotrocketscience/aelfrice/issues/1522)).** The declared ceiling of three retrieval-performing Bash searches per turn could not be reached in any deployed configuration. `aelf-search-tool-hook` is registered as a `"type": "command"` hook, so the host spawns one OS process per fire; the counter was a module-level dict, empty at the start of every one of them. Five processes in one session performed five retrievals where one process performed three, and the source comment naming it a "per-process per-turn" counter stated the assumption that fails: per-process and per-turn are not the same scope here. The count now lives in `session_ring.py` — already flock-guarded, atomically written and per-session — as `bash_turn_id` / `bash_fires` / `bash_fires_turn_id`, and the `UserPromptSubmit` hook stamps the turn boundary, being the only hook guaranteed to fire exactly once per turn. The count names the turn it was taken in and a reader reports zero fires as soon as the two disagree, so the reset is a consequence of that comparison rather than a second write a crash between the two could skip — the cap resets each turn instead of becoming the permanent per-session cap of three that a naive move-it-to-a-file fix would have shipped. Every ring failure (absent, malformed, unwritable, cross-session, a partial install) degrades to "no cap", never to "cap reached": a hook that suppressed retrieval because it could not read a file would be worse than the unbounded firing this bounds. The cap check also moved behind `_extract_bash_query`, which imports nothing: consulting the ring pulls `session_ring` -> `db_paths` -> `store`, +17.6 ms median on a whole hook process, and ordered ahead of extraction that landed on *every* Bash tool call in the session rather than on the few that are searches. After the reorder a non-search Bash call is unchanged at 38.9 ms median (n=30, against 38.9 ms with the ring read compiled out), and the ring read itself costs 0.038 ms. Measured against a 223.1 ms median saving per suppressed fire — 275.3 ms firing vs 52.3 ms suppressed, 20 interleaved pairs of real hook processes against an empty store, where a populated store makes the firing arm heavier still. A ten-`rg` turn stops paying about 1.6 s of hook latency serialized ahead of the user's own tool calls. The regression test is subprocess-driven, one process per fire with a distinct search token each, because an in-process test structurally cannot observe this defect — it passes against the dead counter and the wired ring alike, which is how the cap shipped non-functional.

### Fixed

- **`aelf lock --reference` now bounds a lock on a session's first prompt too ([#1558](https://github.com/robotrocketscience/aelfrice/issues/1558)).** The reference tier exists so long-form locked material costs one `ref <id>: "<topic>"` line and is read on demand ([#1016-B](https://github.com/robotrocketscience/aelfrice/issues/1016)). Two of the three renderers honoured it — `_split_belief_lines` and `_core_belief_line` both divert a reference lock to `retrieval.lock_manifest_line` — and the `<locked>` loop of `_build_session_start_subblock` rendered every row through `b.content` with no `is_reference_lock` branch anywhere in it. That sub-block is what a session's **first** prompt carries, so the tier was a measured no-op exactly where a lock-only store overruns the block ceiling, and on the retrieval branch the envelope carried the full text **and** a `ref` pointer to that same text a few lines below it. Measured on one 30,026-character lock: the gate-skip branch of a first prompt goes from 7700 estimated tokens at either tier to 7700 frozen against 273 reference, and the retrieval branch from 7796 at either tier to 7796 against 273. Turn two (256 against 7683) and the `session_start` baseline (233 against 7660) already bounded and are unchanged. Re-derive the table with `uv run python scripts/measure_block_ceiling.py --reference-tier`; `--emit-figures` publishes the same numbers so CI re-runs them.

  **The row is diverted, not the element's content swapped.** A reference lock leaves the `<belief>` loop entirely and becomes one entry in an `<aelfrice-locks-manifest>` block emitted inside `<session-start>`, through the same `_manifest_block_lines` wrapper every other manifest goes through. The alternative — keeping the element and putting the manifest line in it — would have put the id into `_ids_rendered_verbatim_in`, whose contract is that the full text is in this context window. It is not, so [#1547](https://github.com/robotrocketscience/aelfrice/issues/1547)'s dedupe would have downgraded the per-turn copy to a `seen` pointer claiming text nobody sent, and the [#1382](https://github.com/robotrocketscience/aelfrice/issues/1382) ledger would have recorded an exposure that never happened. Diverting the row keeps both of those true with no second edit.

  **The duplicate pointer is dropped, and it was not free.** With the sub-block emitting its own `ref` line, the per-turn pack reached the same id through the same `_renders_as_manifest` predicate and pointed at it again, so the retrieval envelope carried the identical line twice under two copies of the manifest's framing note — #1547's duplicate in its manifest form. `_drop_duplicate_ref_lines` removes the second one by id, after the split rather than before it, so the hit stays in `hits` and the ledger, the audit row and the exposure writes are unchanged. `seen` lines are not matched and pass through: they name an element rendered verbatim in this window, which is a different claim with its own drop accounting in `enforce_block_ceiling`.

  **A store with no reference lock is byte-identical.** `_manifest_block_lines([])` emits nothing, so the wrapper and its note cost nothing until someone runs `aelf lock --reference`, and a frozen lock's `<belief>` element is unchanged to the byte — `test_a_frozen_lock_renders_the_bytes_it_rendered_before_1558` compares against a golden captured from the pre-change renderer rather than asserting a shape. `_write_memory_block`'s overrun note prescribes `aelf lock --reference` again, which [#1552](https://github.com/robotrocketscience/aelfrice/pull/1552) had withdrawn for being a no-op on exactly the writes most likely to reach it, and the producer's vacuity guard is now per write rather than over the set — until this change the two first-prompt columns were equal while turn two differed, so an "equal on every write" guard was satisfied by the defect it was meant to catch.

  `tests/test_reference_lock_manifest_1558.py` holds fourteen tests, one per emit path — the gate-skip branch, the retrieval branch and the `session_start` baseline — because the defect is that two of three call sites agreed and the third was never asked. Six mutations were run and all six go red: disabling the diversion (6 failed here, plus `test_the_repo_passes_the_producer_checks`, which reports the producer exiting 1 with `the two lock tiers agree on gate_skip_first, retrieval_first`), dropping the manifest block from the sub-block (5), emptying the already-pointed-at set in the dedupe (2), removing the escaping from the manifest entry (1), widening the dedupe pattern to match `seen` as well (1), and pinning `lock_attr` to `"none"` in the frozen render (2, one of them the golden). The tree was verified clean by checksum after each revert.

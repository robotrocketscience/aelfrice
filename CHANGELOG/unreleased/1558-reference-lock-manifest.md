### Fixed

- **`aelf lock --reference` now bounds a lock on a session's first prompt too ([#1558](https://github.com/robotrocketscience/aelfrice/issues/1558)).** The reference tier exists so long-form locked material costs one `ref <id>: "<topic>"` line and is read on demand ([#1016-B](https://github.com/robotrocketscience/aelfrice/issues/1016)). Two lanes render a lock and only one honoured the tier: `_split_belief_lines` diverts a reference lock to `retrieval.lock_manifest_line`, while the `<locked>` loop of `_build_session_start_subblock` rendered every row through `b.content` with no `is_reference_lock` branch anywhere in it. The third `<belief>` renderer, `<core>`'s `_core_belief_line`, has no such branch either and is not a third instance of the defect: it is never handed a lock, because `_build_session_start_subblock` filters every id in `store.list_locked_beliefs()` out of `core_candidates`. `<core>` is covered by **exclusion**, `_split_belief_lines` by **diversion**, and the `<locked>` loop had neither. That sub-block is what a session's **first** prompt carries, so the tier was a measured no-op exactly where a lock-only store overruns the block ceiling, and on the retrieval branch the envelope carried the full text **and** a `ref` pointer to that same text a few lines below it. Measured on one 30,026-character lock: the gate-skip branch of a first prompt goes from 7700 estimated tokens at either tier to 7700 frozen against 273 reference, and the retrieval branch from 7796 at either tier to 7796 against 273. Turn two (256 against 7683) and the `session_start` baseline (233 against 7660) already bounded and are unchanged. Re-derive the table with `uv run python scripts/measure_block_ceiling.py --reference-tier`; `--emit-figures` publishes the same numbers so CI re-runs them.

  **The row is diverted, not the element's content swapped.** A reference lock leaves the `<belief>` loop entirely and becomes one entry in an `<aelfrice-locks-manifest>` block, through the same `_manifest_block_lines` wrapper every other manifest goes through. The alternative — keeping the element and putting the manifest line in it — would have put the id into `_ids_rendered_verbatim_in`, whose contract is that the full text is in this context window. It is not, so [#1547](https://github.com/robotrocketscience/aelfrice/issues/1547)'s dedupe would have downgraded the per-turn copy to a `seen` pointer claiming text nobody sent, and the [#1382](https://github.com/robotrocketscience/aelfrice/issues/1382) ledger would have recorded an exposure that never happened. Diverting the row keeps both of those true with no second edit.

  **The duplicate pointer is dropped, and it was not free.** With the sub-block emitting its own `ref` line, the per-turn pack reached the same id through the same `_renders_as_manifest` predicate and pointed at it again, so the retrieval envelope carried the identical line twice — #1547's duplicate in its manifest form. `_drop_duplicate_ref_lines` removes the second one by id, after the split rather than before it, so the hit stays in `hits` and the ledger, the audit row and the exposure writes are unchanged. `seen` lines are not matched and pass through: they name an element rendered verbatim in this window, which is a different claim with its own drop accounting in `enforce_block_ceiling`.

  **One manifest wrapper per envelope.** The sub-block wraps its own entries, which is right when it is read alone and redundant once it is embedded, so a first-prompt envelope could open `<aelfrice-locks-manifest>` twice and repeat its 233-character framing note — on the very write this entry exists to shrink. It happens whenever the sub-block has a reference lock and the per-turn pack has a pointer of its own, which a store of one frozen and one reference lock reproduces: two wrappers before, one after. `_lift_manifest_block` cuts the sub-block's wrapper out and its entries lead the per-turn entries under the envelope's single wrapper. It extracts on the tag constants, which belief content cannot forge — `_escape_for_hook_block` entity-escapes every angle bracket before content reaches a rendered block.

  That also settles the dedupe's missing element-span guard. `enforce_block_ceiling` has to ignore `seen` matches that fall inside a `<belief>` element, because escaped content keeps its newlines and can hold a line shaped like a manifest entry; `_drop_duplicate_ref_lines` needs no such guard because it is no longer handed a rendered block at all, only the lifted entries. The old whole-block scan did match a forged line: on a lock whose content is `  ref <id>: "topic"` for the per-turn hit's id, `_REF_MANIFEST_RE.findall` over the rendered sub-block returned that id and would have dropped the live pointer. `test_belief_content_shaped_like_a_ref_line_cannot_drop_a_pointer` fires that fixture through the envelope and both pointers survive.

  **A store with no reference lock is byte-identical.** `_manifest_block_lines([])` emits nothing, so the wrapper and its note cost nothing until someone runs `aelf lock --reference`, and a frozen lock's `<belief>` element is unchanged to the byte — `test_a_frozen_lock_renders_the_bytes_it_rendered_before_1558` compares against a golden captured from the pre-change renderer rather than asserting a shape.

  **This reverses a decision [#1552](https://github.com/robotrocketscience/aelfrice/pull/1552) made.** That PR deleted `_write_memory_block`'s "move long-form locks to `aelf lock --reference`" sentence rather than qualifying it, because #1551 had measured the remedy a no-op on exactly the writes most likely to reach the note. The sentence is back, with the clause that makes it checkable: it now says the tier bounds a lock on *every write this hook makes*, and the table above is those four writes — 273 / 273 / 256 / 233 estimated tokens at reference tier against 7700 / 7796 / 7683 / 7660 frozen. It claims nothing about whether demoting will bring a given block under the ceiling; a store of ordinary short locks overruns at 66 of them and a reference entry is not free. The producer's vacuity guard is what keeps the claim honest, and it is now per write rather than over the set: until this change the two first-prompt columns were equal while turn two differed, so an "equal on every write" guard was satisfied by the defect it was meant to catch. Disabling the diversion makes that guard exit 1 with `the two lock tiers agree on gate_skip_first, retrieval_first`.

  `tests/test_reference_lock_manifest_1558.py` holds 26 tests, one per emit path — the gate-skip branch, the retrieval branch and the `session_start` baseline — because the defect is that one of the two lock-rendering call sites diverted and the other was never asked, plus the `<core>` exclusion, the single wrapper and the producer's guard. Ten mutations were run on this tree and all ten go red, by failing test count: disabling the `<locked>` diversion (7), dropping the manifest block from the sub-block (5), emptying the already-pointed-at set in the dedupe (2), removing the escaping from the manifest entry (1), widening the dedupe pattern to match `seen` as well (1), pinning `lock_attr` to `"none"` in the frozen render (3, one of them the golden), neutering the `<core>` locked-id filter (2), giving `_core_belief_line` an `is_reference_lock` branch (1), skipping the lift so the envelope wraps twice (3), and returning the producer guard to the over-the-set form (4). The tree was verified clean by SHA-256 after each revert and `__pycache__` cleared before each run.

### Fixed

- **Onboarding reads git's file dates without guessing ([#1629](https://github.com/robotrocketscience/aelfrice/issues/1629), [#1621](https://github.com/robotrocketscience/aelfrice/issues/1621)).** The scanner split `git log` output into dates and paths by looking at each line. A path that began with four digits and a hyphen, such as `2026-01-15-retro.md`, was read as a date: that file got no date, and the files after it in the same commit got the filename as their `created_at`. A path with non-ASCII characters, a quote, or a backslash arrived C-quoted, so it never matched the file and fell back to the ingest time. The scanner now reads git's NUL-separated output, where dates are framed and paths are raw, so every tracked path gets the date of the last commit that changed it. It's still one `git log` per scan. On this repository, no file's date changes, because it has no such names.

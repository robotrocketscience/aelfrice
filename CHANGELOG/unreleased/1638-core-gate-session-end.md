### Added

- **The Stop hook runs the core admission gate's session-end batch ([#1638](https://github.com/robotrocketscience/aelfrice/issues/1638)).** "Session end" means after the session's beliefs are ingested. The transcript logger folds a session's turns into beliefs every 12 turn lines by default, and at a compaction, so the batch fires on the first Stop after each ingest flush, not once per session (operator ruling, 2026-10-06). On every Stop, the hook runs one indexed query for the session's core candidates: active, unlocked beliefs whose `session_id` is this session, that meet the core rule without the gate, that have no label under the current classifier version, and whose content hash no open batch claims. An open batch claims a hash when it is under the current version and is either this session's own session-end batch or a doctor batch, so a Stop never asks about a belief an earlier Stop asked about. If there is at least one candidate, the hook records one batch with origin `session_end`, holding the newest candidates that fit, up to 50 beliefs and 9,500 characters, and writes `{"hookSpecificOutput": {"hookEventName": "Stop", "additionalContext": ...}}` to stdout. The host inlines at most 10,000 characters of a hook's output, and the hook never cuts a snippet, because the label is keyed to the whole content; a candidate that doesn't fit waits for the next Stop or the backlog drain. The host continues the conversation once with the context, which holds the classifier prompt and the `aelf core-gate accept <batch-id>` command to run with the reply on stdin. The query, the batch record, and the context are one `BEGIN IMMEDIATE` transaction, so two Stops at once can't batch the same belief and a failure leaves no batch behind. aelfrice calls no model.

  The context asks the host to use its smallest model, but that's a request, not a guarantee. If a larger model labels the batch, the labels are kept under the same classifier version, and nothing checks them automatically: the accept self-check runs on doctor batches only, and `aelf doctor core-gate --rerun` refuses a session-end batch. Beliefs from earlier sessions that reach core in this one, and beliefs in a session-end batch nobody answered, stay unlabeled and keep the earlier rule until `aelf doctor core-gate --emit` batches them.

  The hook writes nothing while the host's `stop_hook_active` is set, in a headless session ([#1634](https://github.com/robotrocketscience/aelfrice/issues/1634)), or on the Codex host, which documents `decision` for Stop but not `additionalContext`. The batch is on by default. To turn it off, set `[core_gate] session_end = false` in `.aelfrice.toml` or export `AELFRICE_CORE_GATE_SESSION_END=0`; the environment variable overrides the key in both directions. The lock-prompt listing still goes to stderr, and a failure in the batch is logged to stderr without affecting the listing or the hook's exit code. On a synthetic store of 5,200 beliefs with a 200-belief session, half of which never qualify for core, a Stop that finds nothing new took about 1 ms longer than before (median, in process); the query re-reads the session's beliefs that never qualify on every Stop, at about 6 µs each.

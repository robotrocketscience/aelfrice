### Added

- **The Stop hook runs the core admission gate's session-end batch ([#1638](https://github.com/robotrocketscience/aelfrice/issues/1638)).** "Session end" means after the session's beliefs are ingested. On a Stop, the transcript logger starts a background ingest of the session's turns once 12 turn lines have built up, by default, and the batch fires on the first Stop that finds the ingested beliefs, so at most once per ingest, not once per session (operator ruling, 2026-10-06). The host runs a Stop's hooks in parallel, so the ingest usually lands after that Stop's hook has looked, and the batch fires a turn later; a session's last ingest can land after its last Stop, and the backlog drain covers those beliefs. On every Stop, the hook runs one indexed query for the session's core candidates: active, unlocked beliefs whose `session_id` is this session, that meet the core rule without the gate, that have no label under the current classifier version, and whose content hash no open batch claims. An open batch claims a hash when it is under the current version and is either this session's own session-end batch or a doctor batch, so a Stop never asks about a belief an earlier Stop asked about. If there is at least one candidate, the hook records one batch with origin `session_end`, holding the newest candidates that fit, up to 50 beliefs and 9,500 characters, and writes `{"hookSpecificOutput": {"hookEventName": "Stop", "additionalContext": ...}}` to stdout. The host inlines at most 10,000 characters of a hook's output, and the hook never cuts a snippet, because the label is keyed to the whole content; a candidate that doesn't fit waits for the next Stop or the backlog drain. The host continues the conversation once with the context, which holds the classifier prompt and the `aelf core-gate accept <batch-id>` command to run with the reply on stdin. The query, the batch record, and the context are one `BEGIN IMMEDIATE` transaction, so two Stops at once can't batch the same belief and a failure before the commit leaves no batch behind. The context is written after the commit, so the hook never asks about a batch that doesn't exist; a failure between the two, such as a closed pipe or a host timeout, leaves an open batch nobody was asked about, whose beliefs later Stops don't ask about either. Those, and the beliefs in a batch the model declined, stay unlabeled and keep today's rule until `aelf doctor core-gate --emit` batches them again; the hook doesn't retry, because a retry window would also re-ask a model that declined on purpose, and the drain already covers every case. aelfrice calls no model.

  The context asks the host to use its smallest model, but that's a request, not a guarantee. If a larger model labels the batch, the labels are kept under the same classifier version, and nothing checks them automatically: the accept self-check runs on doctor batches only. To relabel an accepted session-end batch, run `aelf doctor core-gate --rerun <batch-id>` (operator ruling, 2026-10-06). It drops only the labels that still carry the batch's id and puts the beliefs still in core into a new doctor batch, stamped with the time of the re-run, which starts an emit run of its own. A session-end batch belongs to no emit run, so the new batch joins none; as a run of one batch, it's below the self-check's minimum of four, and the command says so. Beliefs from earlier sessions that reach core in this one, and beliefs in a session-end batch nobody answered, stay unlabeled and keep the earlier rule until `aelf doctor core-gate --emit` batches them.

  The hook writes nothing while the host's `stop_hook_active` is set, in a headless session ([#1634](https://github.com/robotrocketscience/aelfrice/issues/1634)), or on the Codex host, which documents `decision` for Stop but not `additionalContext`. The batch is on by default. To turn it off, set `[core_gate] session_end = false` in `.aelfrice.toml` or export `AELFRICE_CORE_GATE_SESSION_END=0`; the environment variable overrides the key in both directions. The lock-prompt listing still goes to stderr, and a failure in the batch is logged to stderr without affecting the listing or the hook's exit code. On a synthetic store of 5,200 beliefs with a 200-belief session, half of which never qualify for core, a Stop that finds nothing new took about 1 ms longer than before (median, in process); the query re-reads the session's beliefs that never qualify on every Stop, at about 6 µs each. The query parses the items of open doctor batches only when they were created at or after the session's earliest belief, since an older batch can't hold the session's beliefs; the timestamps are compared as instants with `julianday()`, because the hook's `...Z` form and the `+00:00` form `--emit` writes don't order correctly as strings. Measured on the session-end path alone, with the session's 200 beliefs already batched and open doctor batches of 50 items: with no doctor batches, 0.28 ms before the bound and 0.29 ms after; with 100 batches older than the session, 5.0 ms before and 0.33 ms after; with 1,000 older, 57.9 ms before and 1.1 ms after. Batches newer than the session are still parsed: 5.1 ms for 100 and 57.1 ms for 1,000, which needs a drain run during the session to leave that many open.

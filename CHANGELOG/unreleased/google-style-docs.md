### Changed

- **The public documentation follows the Google developer documentation style guide.** Twenty-three files — `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `docs/README.md`, everything under `docs/user/` and `docs/concepts/`, and the four index `README.md` files — are written to [Google's style guide](https://developers.google.com/style): second person, present tense, active voice, sentence-case headings, the condition stated before the instruction, serial commas, US spelling, descriptive link text, and the guide's [word list](https://developers.google.com/style/word-list). Table cells were converted as well as paragraphs, 236 of 390 rows, the remainder being data cells that hold a flag, a default, a type, a path, or a version. British spellings outside code fall from 92 to 9, and those 9 are `analysis` and its inflections, which is already US spelling, plus one verbatim quote of a shipped CLI string. Records stay out of scope, because rewriting one changes what it says happened: `CHANGELOG/`, `docs/audits/` bodies, `docs/design/historical/`, and the numbered ADRs. `CODE_OF_CONDUCT.md` stays out too, as adopted normative text attributed to the Contributor Covenant. No fact changes: every numeric literal, URL, link target, fenced code block, inline code span, table row and section that appears in the pre-conversion file still appears, verified per file by `scripts/check_doc_preservation.py`. The one deliberate exception is `CONTRIBUTING.md`, whose `Documentation style` section now names this guide and so no longer carries the two sentence-length limits it used to state; that is a content change rather than a conversion, and the checker reports it rather than being loosened to permit it.

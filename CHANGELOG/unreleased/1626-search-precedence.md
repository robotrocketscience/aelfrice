### Added

- **`aelf search` now runs before the web search tools, not just the local ones ([#1626](https://github.com/robotrocketscience/aelfrice/issues/1626)).** The value of the search hook is *ordering*: aelfrice runs first, so the model already holds the relevant brain-graph context before it chooses grep, the web, or anything else. A search the model runs afterwards, or not at all, is worth much less. Coverage was partial — `SEARCH_TOOL_MATCHER` was `Grep|Glob` plus a separate `Bash` matcher — so a model reaching for `WebSearch` or `WebFetch` proceeded with no brain-graph context at all, and whether it took that path was exactly the model choice aelfrice exists to remove. Both now trigger the lane, and the query comes from each tool's own field: `pattern` for Grep and Glob, `query` for WebSearch, and `prompt` for WebFetch. The prompt, not the URL: a bare URL tokenises into host fragments that match nothing useful, so searching it would satisfy the matcher while defeating the point. Widening is bounded — `Read`, `Write`, `Edit` and `TodoWrite` are asserted *not* to trigger the lane, so every tool call does not now pay for retrieval, and the web tools join the uncapped Grep/Glob path rather than the Bash per-turn fire cap. **Upgrading an existing install no longer leaves a duplicate hook entry.** `_install_or_replace_entry` keys on `(command, matcher)`, so widening the matcher appended a second entry rather than replacing the first; both then matched Grep and Glob, firing the hook twice per call — two store opens, two retrievals, and the locked block injected twice, since `filter_against_ring` lets locked beliefs through as new every time. `prune_broken_aelf_hooks` did not clean it either, because the entry was superseded rather than broken, and **every existing install was the affected case**. Installation now retires entries on a superseded matcher first, scoped to this hook's own command and compared by basename, so a user's own `PreToolUse` entry on the same matcher is left alone and a changed install prefix cannot strand the old one. Nine tests transcribed the matcher as a literal `"Grep|Glob"` and went stale the moment it widened; they now derive `SEARCH_TOOL_MATCHER` from the source, because a transcribed constant is a second copy free to drift from the one that ships.

### Added

- **`benchmarks/scored_query_census.py` makes the #1516 population gate re-runnable ([#1516](https://github.com/robotrocketscience/aelfrice/issues/1516)).** #1516 parked a re-measurement of #1348's top-10 movement behind a threshold committed before any measurement was taken — run it when `input.scored_query` holds **>= 500 distinct queries spanning >= 30 days** — and the only way to decide that was a hand-written scan that went stale between askings. The census scans every `rebuild_logs/*.jsonl` reachable from a root and reports the six numbers the bound needs kept apart: rows scanned, rows carrying `input.scored_query`, **distinct** scored queries, days with at least one, the calendar span, and a per-day breakdown of rows against distinct. Both halves of the bound have a cheaper neighbour that would pass the gate early — row count is not distinct queries, and active days are not a calendar span — so `tests/test_scored_query_census_1516.py` feeds synthetic rows in which those numbers deliberately differ and pins each separately. The two bounds are module constants with **no CLI flag**, because a flag lets a re-run lower the bar it is checking and still look like the same census; a test asserts the flags do not exist. Exit codes separate "could not census" (2) from "censused, a bound is unmet, do not measure" (3). The logs are repo-local — `<git-common-dir>/aelfrice/rebuild_logs/` per repo, plus `~/.aelfrice/rebuild_logs` for work outside any work-tree — so `--discover` finds both layouts; a census that knew only about `~/.aelfrice` would report a near-empty population. Rows are read through `rebuild_log_query_population.load_rows` so the two censuses cannot drift on what counts as a parseable row, and nothing here opens a `MemoryStore`, since opening one runs pending migrations.

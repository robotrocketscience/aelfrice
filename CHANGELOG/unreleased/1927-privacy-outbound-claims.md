### Documentation

- **PRIVACY.md no longer denies day-to-day outbound calls or calls the uv migration an explicit command ([#1927](https://github.com/robotrocketscience/aelfrice/issues/1927)).** The onboard section said no day-to-day operation makes an outbound call, while its own table lists two default-on paths that transmit data: the pre-issue guard and background labeling. It now points to that table. The one-shot uv-tool migration shared a row with `aelf upgrade` and was called an explicit command, but it runs inside `aelf setup` when the machine has no uv-tool install of aelfrice and `uv` is on `PATH`. It now has its own row and bullet as a fourth default-on path, which say that it sends only the package request, replaces the `aelf` command in `~/.local/bin`, writes `~/.aelfrice/migrated-to-uv` on success, and stops after its first success. The path count goes from seven to eight.

### Documentation

- **PRIVACY.md no longer denies day-to-day outbound calls or calls the uv migration an explicit command ([#1927](https://github.com/robotrocketscience/aelfrice/issues/1927)).** The onboard section said no day-to-day operation makes an outbound call, while its own table lists two default-on paths that transmit data: the pre-issue guard and background labeling. It now points to that table. The one-shot uv-tool migration shared a row with `aelf upgrade` and was called an explicit command, but `aelf setup` runs it when the machine has no uv-tool install of aelfrice and `uv` is on `PATH`; `aelf setup --host codex` doesn't. It now has its own row and bullet as a fourth default-on path, which say that it sends only package requests for aelfrice and its dependencies, installs every aelfrice command into uv's tool bin folder, writes `~/.aelfrice/migrated-to-uv` on success, and runs again only when both that file and the uv-tool install are gone. The `aelf upgrade` row now says that the command makes an in-process GET to PyPI and installs nothing, so four rows, not five, reach the network through a program other than aelfrice. The update notifier runs its GET in a detached Python process, and the page now says so and says that the in-process grep finds that GET. The path count goes from seven to eight.

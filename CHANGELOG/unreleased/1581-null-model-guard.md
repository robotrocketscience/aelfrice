### Added

- **A bench-gate corpus counts only when it defeats its own null model ([#1581](https://github.com/robotrocketscience/aelfrice/issues/1581)).** The quality tier's headline number is "N tests executed against the corpus", and that number was not evidence: a corpus can pass its gate while being unable to represent the distinction the gate claims to measure. Measured on the mounted lab corpus, `query_strategy` has `len(expected_top_k) == len(beliefs)` on 30 of 30 rows and `k < len(beliefs)` on 2 of 30, so a deterministic shuffle of each row's own candidate pool scores **P@10 0.9933 / NDCG@10 0.8525** against a gate whose floor is `> 0.0`. Operator ruling 2026-09-20 makes the check a precondition to counting rather than an advisory: a corpus counts only when the gate's own metric, recomputed with the shipped implementation replaced by the module's declared null model, **fails** the gate's bar. `tests/bench_gate/test_directive_detection.py::test_directive_corpus_defeats_a_first_token_baseline` ([#374](https://github.com/robotrocketscience/aelfrice/issues/374), [#1349](https://github.com/robotrocketscience/aelfrice/issues/1349)) already did exactly this for one module over K=200 salted partitions, and is the reason `directive_detection` is the one module in the tier anyone should currently believe; this generalises that test rather than inventing a second mechanism.

  Every module under `tests/bench_gate/` now declares its family and its null model in one place, `GATE_DECLARATIONS` in `tests/bench_gate/null_model.py`, and the declared null model runs **inside the gate, on the same rows, every time the gate runs**. Ranking gates are scored against the row's candidate pool in deterministic shuffled order; classification gates against a constant predictor returning the corpus's majority label; ablation gates against the ablated arm plus a requirement that the ablated arm reaches the gold on at least 10% of rows, which is what rejects "the feature is the only path to the gold" — a corpus shaped that way reports +1.000 uplift and proves the weight table rather than the feature. `Family.EXEMPT` is available where no null model is constructible from the rows, and it has to state the reason, so an exemption is visible rather than silently counted as validated. Two enforcement tests make the declaration unskippable: one fails when a module under `tests/bench_gate/` has no entry, the other parses each gate file and fails when a module declares a family but never calls a guard.

  **Both scores now reach the release record.** Only `test_directive_detection.py` recorded anything before, so every other gate printed its number solely inside a failure message and a green run left no evidence — which makes a degenerate +1.000 uplift indistinguishable from a real +0.06 to a reviewer reading a passing run. Each guard records the shipped score, the null score, the bar, whether the null cleared it, and the verdict through `record_property`, before the assertion. The `null_clears_bar` field is why the no-regression gates stay honest: a zero uplift clears a `>= 0` bar by construction, so `retrieve_uplift` and `compression_a4_fidelity` record that their green is regression evidence and not positive evidence about the feature.

  **The tier summary reports rejection as its own state**, distinct from executed and from no-verdict, and a rejected gate is not counted as executed — it graded nothing. Two structural pre-filters run before the null model because they cost milliseconds against a driver that rebuilds a store per row, and the rejection names which one fired: `len(gold) < len(pool)` and `k < len(pool)` on at least 90% of rows, and `max(len(gold)) <= 3 * median(len(gold))` — a micro-averaged metric lets one 60-target row supply most of the denominator of a 30-row corpus, which a `MIN_ROWS` floor does not defend against.

  Verified against every corpus on disk with the lab corpus mounted: `query_strategy` **REJECT** (separability pre-filter, 0.0% of 30 rows; shuffle NDCG@10 0.8525 against a `> 0.0` floor); `directive_detection` ACCEPT (majority constant scores −0.800 headroom against the P≥0.80/R≥0.60 conjunction); `sentiment` ACCEPT (majority constant 0.4182 against a 0.500 bar); `contradiction` ACCEPT (majority constant 0.3418 against 0.500); `compression_a2_recall` ACCEPT (ablated arm reaches the gold on 72.0% of rows, uplift +0.3733); `compression_a4_fidelity` ACCEPT (100% of rows, uplift +0.0159); `multi_fact` ACCEPT (100% of rows, uplift +0.0357). `retrieve_uplift`, `doc_linker`, `reasoning`, `wonder_online` and the five Track A edge modules have no rows anywhere on this machine and are reported as having no verdict, which is the state they were already in.

  **A half-built module no longer vanishes from the summary.** `_MODULE_SKIP_RE` in `tests/conftest.py` matched only `missing|empty`, so a module that skipped for being under its row floor printed neither "executed" nor "no verdict" and disappeared — eleven such skip sites across ten gate modules, plus one in `compression_uplift` for a corpus it cannot grade. Every corpus-state skip now goes through `skip_corpus_module` or `require_min_rows`, an enforcement test fails on a bespoke `pytest.skip` that mentions a corpus, and the summary maps the state to a sentence: `underfilled` and `ungradeable` report as `UNVERIFIED`, and a state nobody has written a sentence for still prints rather than disappearing. Observed on the real corpus: `contradiction_v3` skips with 27 `contradicts`-labelled rows against its floor of 30, and now says so.

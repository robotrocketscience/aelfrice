### Added

- **A bench-gate corpus counts only when it defeats its own null model ([#1581](https://github.com/robotrocketscience/aelfrice/issues/1581)).** The quality tier's headline number is "N tests executed against the corpus", and that number was not evidence: a corpus can pass its gate while being unable to represent the distinction the gate claims to measure. Measured on the mounted lab corpus, `query_strategy` had `len(expected_top_k) == len(beliefs)` on 30 of 30 rows and `k < len(beliefs)` on 2 of 30, so a deterministic shuffle of each row's own candidate pool scored **P@10 0.9933 / NDCG@10 0.8525** against a gate whose floor was `> 0.0`. Both halves of that are fixed below, and the corpus half alone would not have been enough. Operator ruling 2026-09-20 makes the check a precondition to counting rather than an advisory: a corpus counts only when the gate's own metric, recomputed with the shipped implementation replaced by the module's declared null model, **fails** the gate's bar. `tests/bench_gate/test_directive_detection.py::test_directive_corpus_defeats_a_first_token_baseline` ([#374](https://github.com/robotrocketscience/aelfrice/issues/374), [#1349](https://github.com/robotrocketscience/aelfrice/issues/1349)) already did exactly this for one module over K=200 salted partitions, and is the reason `directive_detection` is the one module in the tier anyone should currently believe; this generalises that test rather than inventing a second mechanism.

  Every module under `tests/bench_gate/` now declares its family and its null model in one place, `GATE_DECLARATIONS` in `tests/bench_gate/null_model.py`, and the declared null model runs **inside the gate, on the same rows, every time the gate runs**. Ranking gates are scored against the row's candidate pool in deterministic shuffled order; classification gates against a constant predictor returning the corpus's majority label; ablation gates against the ablated arm plus a requirement that the ablated arm reaches the gold on at least 10% of rows, which is what rejects "the feature is the only path to the gold" — a corpus shaped that way reports +1.000 uplift and proves the weight table rather than the feature. `Family.EXEMPT` is available where no null model is constructible from the rows, and it has to state the reason, so an exemption is visible rather than silently counted as validated. Three enforcement tests make the declaration unskippable: one fails when a module under `tests/bench_gate/` has no entry, one parses each gate file and fails when a module declares a family but never calls a guard, and one compares each declaration against the module name the gate passes to `load_corpus_module` — `test_edge_rerank_potentially_stale` declared `rerank_relevance` while grading `bfs_potentially_stale`, and nothing consumed the field, so the two names printed side by side in the tier block unnoticed.

  Omitting `gold_key` and `pool_key` turns the structural pre-filters off, which is a claim about the corpus, so the guards check it rather than trust it: a gate whose rows carry gold entries drawn from a candidate pool must wire the keys. The condition tested is that the gold entries *are* pool ids, not that a pool-shaped key is present — `compression_a4_fidelity` seeds a store from `beliefs` and scores free-text answers against it, so its gold and its pool are different populations. `test_intentional_clustering` was the one gate using the switch and was wrong about its rows: all 14 `multi_fact` rows carry `beliefs`, and it now declares the keys along with `k_key`, because the guard's `default_k` of 10 exceeds every `multi_fact` pool and would reject a corpus that is separable on all 14 rows at the cutoff the gate scores with.

  **Both scores now reach the release record.** Only `test_directive_detection.py` recorded anything before, so every other gate printed its number solely inside a failure message and a green run left no evidence — which makes a degenerate +1.000 uplift indistinguishable from a real +0.06 to a reviewer reading a passing run. Each guard records the shipped score, the null score, the bar, whether the null cleared it, and the verdict through `record_property`, before the assertion. The `null_clears_bar` field is why the no-regression gates stay honest: a zero uplift clears a `>= 0` bar by construction, so `retrieve_uplift` and `compression_a4_fidelity` record that their green is regression evidence and not positive evidence about the feature.

  **The headline count now requires a verdict.** Every bench-gated report used to increment "N tests executed against the corpus", so a gate that graded nothing was reported as evidence it never produced: the verdict was recorded after the shipped arm, and any exception in that arm discarded it. The verdict is a finding about the corpus and never depended on the shipped score, so it is settled first. A rejected corpus no longer drives the shipped arm at all, and an arm that raises records `UNVERIFIED` with the null score it did produce, then re-raises unchanged. A scored module's test counts as executed only when it recorded `ACCEPT`; every other bench-gated report is listed by test ID under a `UNVERIFIED` heading. That requirement is also what closes the limit of the wiring test: parsing the file shows a `guard_*_gate(...)` call that is present, not one that is reachable, and a guard that does not run leaves no verdict.

  **The tier summary reports rejection as its own state**, distinct from executed and from no-verdict, and a rejected gate is not counted as executed — it graded nothing. Two structural pre-filters run before the null model because they cost milliseconds against a driver that rebuilds a store per row, and the rejection names which one fired: `len(gold) < len(pool)` and `k < len(pool)` on at least 90% of rows, and `max(len(gold)) <= 3 * median(len(gold))` — a micro-averaged metric lets one 60-target row supply most of the denominator of a 30-row corpus, which a `MIN_ROWS` floor does not defend against.

  Verified 2026-09-20, before the corpus replacement and the floor raise described above, against the 12 corpus modules that have rows anywhere on the author's machine, mounted as one root. Seven of them have a scored gate, and all seven produced a verdict: `query_strategy` **REJECT** (separability pre-filter, 0.0% of 30 rows; shuffle NDCG@10 0.8525 against a `> 0.0` floor — the state the two changes above fix, and the only verdict in this paragraph they move); `directive_detection` ACCEPT (majority constant scores −0.800 headroom against the P≥0.80/R≥0.60 conjunction); `sentiment` ACCEPT (majority constant 0.4182 against a 0.500 bar); `contradiction` ACCEPT (majority constant 0.3418 against 0.500); `compression_a2_recall` ACCEPT (ablated arm reaches the gold on 72.0% of rows, uplift +0.3733); `compression_a4_fidelity` ACCEPT (100% of rows, uplift +0.0159); `multi_fact` ACCEPT (100% of rows, uplift +0.0357). Of the remaining five mounted modules, `compression_uplift` and `wonder_consolidation` belong to gates declared `Family.EXEMPT`, and `dedup`, `enforcement` and `promotion_trigger` have no gate at all since [#1579](https://github.com/robotrocketscience/aelfrice/issues/1579) retired the three that graded absent code. The run reports 11 tests executed, one module rejected, and five bench-gated tests with no verdict — the four corpus round-trip and latency smoke tests that call no guard, plus the K=200 first-token baseline, which is an assertion beside the gate rather than a guard inside it.

  **`query_strategy`'s floor is raised into the measured window, and the rebuilt rows alone would not have cleared it.** The gate stated `> 0.0` twice — as the bar the declared null model must fail and as the assertion the shipped arm must clear — and `> 0.0` is a tripwire for "retrieval returned nothing", not a null-model trap: every null model clears it, so the #1581 bar could only ever reject on a structural pre-filter. The 30 rows are replaced lab-side by 40 that pass both pre-filters (gold == pool on 0 of 40, `k < len(pool)` on 40 of 40, max gold 1.33x the median), and on those rows the declared null still scores **NDCG@k 0.1499** — which clears `> 0.0`, so the rebuild on its own leaves the gate reporting REJECT. The floor is now `_NULL_FLOOR = 0.35`, and it is derived rather than picked: `benchmarks/query_strategy_null_distribution.py` re-shuffles every row's pool under 200 independent seeds (min 0.0607, mean 0.1346, **max 0.2307**) and the floor is that maximum times 1.5, rounded up to two decimals — half again above the worst draw, because a sweep maximum is an empirical maximum and not a bound. The producer imports `null_model.shuffled_pool` rather than reimplementing it, so the canonical figure it publishes is computed by the code the gate runs. It is store-backed in the #1469 sense — the rows are lab-side and do not go to a public runner ([#1456](https://github.com/robotrocketscience/aelfrice/issues/1456)) — so its four markers carry `corpus=` and `producer-sha=` and CI holds them to self-consistency and staleness rather than re-running them. On the other side the floor leaves room: shipped `legacy-bm25` measures **0.8716** (+0.5216, 2.49x the floor) and the losing `stack-r1-r3` measures **0.6508** and clears it too, deliberately, since a floor only the current default could pass would pre-judge the re-flip this gate's comparison exists to detect.

  **The raised floor is proven load-bearing rather than asserted to be.** Substituting the declared null model for the shipped arm — `dataclasses.replace` on the runner's result, both arms set to the shuffled-pool score — fails on `assert scores[DEFAULT_STRATEGY] > _NULL_FLOOR` at `0.14988237797810616 > 0.35`, and specifically not on the arm comparison, which a tie satisfies (`uplift=+0.0000`). The counterfactual is the point of the change: with the assertion's floor alone put back to `0.0` and the bar left at 0.35, that same substitution passes green and the tier counts the test as executed against an ACCEPT verdict. Mounted against the rebuilt corpus the tier reports `query_strategy: family=ranking shipped=0.8716 null=0.1499 bar=> 0.35 null_clears_bar=False verdict=ACCEPT n_rows=40`, and the run moves from 5 executed with one module rejected to 6 executed with none.

  Eleven further modules have no rows anywhere on this machine — `bfs_potentially_stale`, `bfs_relates_to`, `derived_from_edge`, `doc_linker`, `implements_edge`, `reasoning`, `rerank_relevance`, `retrieve_uplift`, `temporal_next_edge`, `tests_edge` and `wonder_online`. They are reported as having no verdict, which is the state they were already in.

  **A half-built module no longer vanishes from the summary.** `_MODULE_SKIP_RE` in `tests/conftest.py` matched only `missing|empty`, so a module that skipped for being under its row floor printed neither "executed" nor "no verdict" and disappeared — eleven such skip sites across ten gate modules, plus one in `compression_uplift` for a corpus it cannot grade. Every corpus-state skip now goes through `skip_corpus_module` or `require_min_rows`, an enforcement test fails on a bespoke `pytest.skip` that mentions a corpus, and the summary maps the state to a sentence: `underfilled` and `ungradeable` report as `UNVERIFIED`, and a state nobody has written a sentence for still prints rather than disappearing. Observed on the real corpus: `contradiction_v3` skips with 27 `contradicts`-labelled rows against its floor of 30, and now says so.

### Added

- **`aelf doctor --retire-relay-rows` retires beliefs stored from relay text as your words ([#1877](https://github.com/robotrocketscience/aelfrice/issues/1877)).** Before [#1875](https://github.com/robotrocketscience/aelfrice/pull/1875), ingest stored relay text that opened a user record, such as another session's message, as words you typed, with the `user_transcript` origin. The pass takes what #1875's cut takes from the raw record, and only where the store shows the raw record. Before [#1649](https://github.com/robotrocketscience/aelfrice/issues/1649), ingest split the raw record into rows and anchored the DERIVED_FROM edge to your next turn on it, up to 1,000 characters with its line breaks. From #1649 on, both use the speech left after reminders, host marker lines, harness blocks, and pasted output are filtered out. So the pass reads only rows whose id carries a time before 2026-09-30 21:52:33 UTC, the time of #1649's first commit. A row written at or after that time never adds to what the pass takes. A stored row holds one sentence, and a row starts its turn when the row before it has another session, timestamp, or source label. The pass takes a row that starts its turn and holds a relay opening tag alone, in the host's form: tag and attribute names in lower case, one space before each attribute, each value double-quoted with a character other than whitespace and no line break, and the attributes the host writes on that tag. A bare tag such as `<agent-message>` doesn't count. It also takes the rows of a record that the anchor shows opening with relay text, when every relay tag in the part #1875 cuts is in the host's form and every notice line in it, ended by LF or CRLF, ends at its template's fixed words. Those rows form a run that opens at a row that starts its turn, takes that row, and stays in its group, in a turn that could have written the edge: the turn derived the edge's earlier end, and the next turn in the session that produced a belief derived its later end. A notice row is taken only this way. Rows keep no closer, so when records in two turns have the same rows and both fit one edge, the pass takes neither one's rows through it. An anchor is skipped when a row written after the cutoff holds its first sentence in that session. When the anchor shows a record #1875 keeps whole, such as one whose first line the sentence splitter dropped or one with a reminder before the relay, the record's rows aren't taken, and no other anchor takes them. A relay record whose first row continues the group of the row before it, as in a bulk ingest that gives several records one timestamp, isn't taken. When no later turn in the session produced a belief, there's no anchor, and only an opener row can be taken. The pass misreads some rows. A tag in the host's form that you typed or pasted reads as relay text, and so does a notice line you typed with exactly its fixed words. Rows that an install from before #1649 wrote after the cutoff are skipped, and rows that a later install wrote with its clock set before the cutoff are read as raw records. When the turn that wrote an edge has no rows from before the cutoff, another turn with the same rows that fits the edge is read through that edge's anchor. A belief is retired only when every row that derived it is relay text. A locked belief is kept, as is one you promoted, confirmed, restored or kept in `aelf review`, one another source corroborated, and one a federation peer owns. The report counts rows and beliefs by shape and lists belief ids without their text. It's a dry run unless you add `--apply`. `aelf doctor --restore-relay-rows --apply` restores each belief the pass retired that nothing has retired again since, and `aelf restore <id>` restores one. Undo leaves an audit trail: each restored belief keeps a `relay_rows:retire` feedback row of valence 0 and gains a `user_restored` row of valence 1, which keeps it on a later run, its version counter and search index row change, and the store generation moves.

### Fixed

- **`graph`, `stale`, `introspect` and `core` dumped a traceback against a store they couldn't write ([#1416](https://github.com/robotrocketscience/aelfrice/issues/1416)).** These four still called `_open_store()`, so on a non-writable store they died in `MemoryStore.__init__` with a raw `sqlite3.OperationalError: attempt to write a readonly database`. The CLI catches `ReadOnlyStoreUnavailable` and nothing else, so the exception escaped the command entirely rather than becoming the one actionable line the already-routed commands give. They now open through `open_store_for_read()`, which attempts the ordinary writable open first and falls back to `mode=ro` only when that open is refused for lack of write access.

  Four handlers, each audited on its own, which is what the 2026-08-09 ruling asked for in place of a blanket change. `graph` resolves seeds and walks `expand_bfs`; `stale` runs one `SELECT` with two date thresholds; `introspect` hands the store to `introspect.build_report`; `core` composes `list_locked_beliefs`, `list_belief_ids` and `get_belief`. All four read only, proved by the database file staying byte-identical across each command on a frozen store rather than by reading the code. `stale --locked-only` and `core`'s locked arm carry one finding: on the read-only fallback no expired-lock sweep has run (#1314), so a belief past its `lock_expires_at` still counts as locked there, the same staleness `locked` already carries on that path.

  The issue comment's line numbers point one handler off — at `_cmd_confirm`, which calls `apply_feedback(..., respect_lock=False)`, and `_cmd_resolve`, which calls `auto_resolve_all_contradictions`. Both are writers, and routing either onto a read-only handle would have shipped a bug. Every edited call site was mapped back to its enclosing `def` by an abstract-syntax-tree walk before the edit, and the scope test now names those two writers explicitly, so an edit that lands one line off fails there rather than in a user's store.

  What the routing does **not** buy is a cheaper open. Against a writable store the handle is the writable one, so these four still pay the schema battery, the migrations, the scope-id mint and the expired-lock sweep, exactly as every other command does. That cost is tracked separately, over every read-only verb.

  **Not verified on Windows, and not verified on a managed Codex host.** `tests/test_readonly_store_1416.py` is skipped entirely when `os.name == "nt"` and when the test runs as root, because it works by `chmod` and root ignores permission bits. The reproduction that motivated the issue is a sandboxed agent host whose `.git/` is not writable; what the tests reproduce is that shape built locally with `chmod`, not that host.

### Fixed

- **Commit ingest now sees the commits a session makes, and an amend no longer counts twice ([#1698](https://github.com/robotrocketscience/aelfrice/issues/1698)).** The commit-ingest hook acted only on a command that started with `git commit`, and it read the commit hash from the `[branch hash]` line that `git commit -q` doesn't print. In this project's sessions it ingested about 2 of 399 commits ([#1683](https://github.com/robotrocketscience/aelfrice/issues/1683)). Now it reads the commit entries from the last 2 minutes of `HEAD`'s reflog, in the directory of a leading `cd <path> &&` if there is one. That covers a commit chained after `git add`, a quiet commit, a call that makes several commits, and a commit in another worktree. A commit older than the window is never read, and re-reading a recent commit writes nothing. A commit's session is keyed on its parent and author date, which an amend keeps, and a commit session never corroborates a belief it created itself. So an amend, a second hook fire, or a retry after a crash adds no corroboration. A new commit with the same message still corroborates. A rebased or cherry-picked commit gets a new parent and counts as new. A commit made with `git -C <path>` into another repository, or with a past `GIT_COMMITTER_DATE`, isn't seen.

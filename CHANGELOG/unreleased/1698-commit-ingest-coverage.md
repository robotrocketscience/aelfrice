### Fixed

- **Commit ingest now sees the commits a session makes, and an amend no longer counts twice ([#1698](https://github.com/robotrocketscience/aelfrice/issues/1698)).** The commit-ingest hook acted only on a command that started with `git commit`, and it read the commit hash from the `[branch hash]` line that `git commit -q` doesn't print. In this project's sessions it ingested about 2 of 399 commits ([#1683](https://github.com/robotrocketscience/aelfrice/issues/1683)). Now it reads `HEAD`'s reflog and ingests every commit written in the last 2 minutes. That covers a commit chained after `git add`, a quiet commit, and a call that makes several commits. A call that only mentions `git commit`, such as a pull request body, finds no recent commit and ingests nothing. A commit's session is now keyed on its parent and author date, which an amend keeps, and a commit session never corroborates a belief it created itself. An amend, a second hook fire, or a retry after a crash adds no corroboration. A new commit with the same message still corroborates. A commit made with `git -C <path>` into another repository isn't seen.

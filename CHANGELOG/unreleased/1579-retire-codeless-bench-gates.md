### Removed

- **Three v2.0 bench gates graded code that does not exist, and they are retired rather than left in the denominator ([#1579](https://github.com/robotrocketscience/aelfrice/issues/1579)).** The bench-gate tier scaffolded 20 modules reporting "no verdict", which reads as *unfunded labelling*. For `dedup`, `enforcement`, and `promotion_trigger` it was not: there is no function to grade, so no corpus of any size could produce a verdict, and the count overstated how much of the tier a labelling push could recover. The denominator is now 17 and every module in it names work a corpus would actually unblock. **`enforcement` was dropped, not deferred.** `docs/design/v2_enforcement.md` records the disposition in its status line — "H2 dropped per § H2 below" — and § H2 states the wording is deliberate: "Final decision: drop, not defer. Removing the temptation to revisit 'just port the safe predicates' prevents incremental erosion of the security stance." The dropped predicate set included `command_succeeds:cmd`, which would have executed arbitrary shell from belief content with no allowlist and no sandbox. The gate was scaffolding for a capability the project decided on security grounds not to ship, so keeping it implied a reopening that is not coming. **`promotion_trigger` graded the rule [#229](https://github.com/robotrocketscience/aelfrice/issues/229) rejected, and the rule it ratified is already covered on every public CI pass.** #229 ratified that a phantom's origin advances only through explicit user acknowledgment, and it named three count-based triggers — N positive feedback events, retrieval count, and `user_corrected` adjacency — as *non-triggers*. That rule shipped at v2.1 via [#550](https://github.com/robotrocketscience/aelfrice/issues/550): Surface A is `aelf promote <id>`, and Surface B auto-promotes a phantom whose text matches an `aelf lock` statement (`aelfrice.promotion.find_phantom_lock_matches`, Jaccard >= 0.9). The retired gate graded `promotion_trigger.decide(row["belief_sequence"])` against `should_promote` / `should_not` labels — a function that infers promotion from a sequence of beliefs, which is the shape #229 ruled out. A perfectly labelled corpus would therefore have certified the rejected design, not the shipped one. `tests/test_promotion_adversarial.py` covers Surface B on every public CI run, rather than once per release cut. Do not read `find_promotable_phantoms(min_corroborations=..., min_sessions=...)` as the #229 trigger: that method is [#1132](https://github.com/robotrocketscience/aelfrice/issues/1132) Q2, and its docstring states it is a read-only detector that never promotes, because a corroboration count is the non-trigger. **`dedup` was the live landmine.** Its guard caught `ModuleNotFoundError`, but `aelfrice.dedup` imports — the module is real, and ships `jaccard`, `levenshtein_ratio`, `cluster_pairs`, `find_near_duplicate_locks`, and `dedup_audit`. What it has never had is `classify`, which the gate called on the next line, so the first row mounted under `<corpus>/dedup/` would have turned a clean skip into an `AttributeError` at a release cut. There is a second mismatch underneath: the corpus label set is ternary (`duplicate` / `near-duplicate` / `distinct`) while the shipped predicate is one binary threshold, and nobody has defined the `near-duplicate` band — so anyone labelling rows today would be labelling to a boundary that does not exist. If `dedup` is ever revived, define the band and write `classify` first, then re-mount rows; do not author new ones.

  The reason this cost anything is that nothing failed at authoring time. The whole tier skips without `AELFRICE_CORPUS_ROOT`, so a gate against a module that was never written is indistinguishable from a gate waiting on rows, and the bill arrives at the release cut — the one place [#1477](https://github.com/robotrocketscience/aelfrice/issues/1477) made the tier mandatory, and where [#1502](https://github.com/robotrocketscience/aelfrice/issues/1502) already showed that a check nobody can turn green teaches readers to skip the reds beside it. `tests/test_bench_gate_graded_code_exists_1579.py` closes that: it walks every file under `tests/bench_gate/`, asserts each `aelfrice.*` module it imports has a file under `src/aelfrice/`, and asserts each attribute read off one of those modules exists on it. The second assertion is the one `dedup` needed — an importable module is not a gradable one, and a module-existence check alone passes the exact case that broke. Shadowing is resolved per scope rather than per file, so one unrelated `dedup = {...}` inside a helper cannot disarm the attribute check for the rest of the file. A third check pins the three retired names out of the tier, but only while the function their gates called is still missing, so the revival route `docs/design/dedup.md` prescribes retires the pin instead of tripping it. It all runs unmarked and corpus-free, so the next scaffold-before-code gate reds on its own pull request. Mutation-checked five ways: a planted gate importing `aelfrice.nonexistent_module` reds the module check; one importing a missing name off the package reds the member check; one reproducing the `dedup` shape — a real module, an absent attribute — reds the attribute check, and still reds with an unrelated same-name local assignment elsewhere in the file; a planted file in a subdirectory of the tier reds too, which it does not under a non-recursive glob; and re-adding `tests/bench_gate/test_dedup.py` reds the pin until a hand-added `dedup.classify` turns it into a skip.

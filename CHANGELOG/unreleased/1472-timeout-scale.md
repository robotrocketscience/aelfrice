### Fixed

- **Test timeouts scale to the machine instead of losing the PR gate ([#1472](https://github.com/robotrocketscience/aelfrice/issues/1472)).** The suite's wall-clock budgets were sized for an idle machine, so a loaded one failed tests that had no defect; `aelf-pr-open.sh` runs pytest with `-x`, so the first such loss ended the run, and twelve gate attempts went that way. Raising the ini `timeout` could not fix it: 179 tests carry their own `@pytest.mark.timeout`, and `pytest_timeout` resolves the closest marker first and only falls back to the ini value in its absence, so that value governs a minority of the suite. A `pytest_collection_modifyitems` hook in `tests/conftest.py` now re-adds each item's resolved budget multiplied by `AELF_TEST_TIMEOUT_SCALE`, which reaches both populations, including the handful of markers built from a module constant that a static census misses. The base moves from 5 to 30, the scale defaults to 4 for developers, and all five workflows that invoke pytest pin it to 1 — explicitly per workflow rather than inferred from `CI` being set, because `CI` is commonly exported in local shells and because `ci.yml` and `publish.yml` carry no `timeout-minutes` backstop, so there the scale is the only thing bounding a hang. A malformed or non-positive scale falls back to the default rather than raising; a scale of zero would read as *disabled* to pytest-timeout and silently remove every budget in the suite. The guard test derives the workflow list from the workflows themselves, so a new one that runs pytest without the pin fails rather than inheriting the developer scale. Twelve stale comments naming the old value are corrected; two that asserted an unmeasured inequality against it lost the figure rather than gaining a new one, and one that records a past incident keeps its original number, now labelled as the then-current default.

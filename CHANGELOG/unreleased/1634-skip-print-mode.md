### Fixed

- **Transcript capture no longer stores a headless host session as user knowledge ([#1634](https://github.com/robotrocketscience/aelfrice/issues/1634)).** An evaluation harness drives the host headlessly (`claude -p`, or an Agent SDK app), with one scripted prompt per session. aelfrice stored each run's prompt as if a user had typed it, so one scripted run counted as many independent sessions of corroboration. On one store, a single afternoon of such runs put 67 beliefs into `aelf core` (#1635). The host names how a session started, as its entrypoint, in the session log's records and in a hook's `CLAUDE_CODE_ENTRYPOINT`. The headless entrypoints are `sdk-cli`, `sdk-ts`, and `sdk-py`. `ingest_jsonl`, which `aelf ingest-transcript` uses, now skips a record with a headless entrypoint and counts it as a skipped line. The transcript logger records neither the prompt nor the reply when its hook runs under one. A log with no `entrypoint`, and every interactive entrypoint, is captured as before. The host's `CLAUDE_CODE_SESSION_ATTENDED` flag is not used, because the host also sets it to `0` for background, daemon, and teammate sessions. The entrypoint is the host's label, and a process started inside a host session can inherit it. On a non-interactive start, the host turns an inherited `cli` into `sdk-cli` but keeps an IDE, desktop, or `sdk-*` label, so `claude -p` run inside an IDE or desktop session can be captured, and an interactive session started from an SDK process can be skipped. This covers the two transcript-capture paths only; the memory-mirror and commit-ingest hooks do not check the entrypoint. If you drive aelfrice through the SDK on purpose, set `[ingest] capture_print_mode = true` or `AELFRICE_CAPTURE_PRINT_MODE=1` to restore capture. aelfrice-format text pasted into an ordinary prompt (#1620) is not part of this change.

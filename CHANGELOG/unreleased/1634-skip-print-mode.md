### Fixed

- **Transcript capture no longer stores a headless host session as user knowledge ([#1634](https://github.com/robotrocketscience/aelfrice/issues/1634)).** An evaluation harness drives the host headlessly (`claude -p`, or an Agent SDK app), with one scripted prompt per session. aelfrice stored each run's prompt as if a user had typed it, so one scripted run counted as many independent sessions of corroboration. On one store, a single afternoon of such runs put 67 beliefs into `aelf core` (#1635). The host names how a session started, as its entrypoint, in the session log's user and assistant records and in a hook's `CLAUDE_CODE_ENTRYPOINT`. The headless entrypoints are `sdk-cli`, `sdk-ts`, and `sdk-py`. A `claude -p` probe on host version 2.1.284 carried `sdk-cli` in both places. A scan of 1,836 local session logs found no interactive session or subagent with a headless entrypoint. `ingest_jsonl`, which `aelf ingest-transcript` uses, now skips a record with a headless entrypoint and counts it as a skipped line. The transcript logger records no prompt when its hook runs under one. A log with no `entrypoint`, and every interactive entrypoint, is captured as before. The host's `CLAUDE_CODE_SESSION_ATTENDED` flag is not used, because the host also sets it to `0` for background, daemon, and teammate sessions. This covers the two transcript-capture paths only; the memory-mirror and commit-ingest hooks do not check the entrypoint. If you drive aelfrice through the SDK on purpose, set `[ingest] capture_print_mode = true` or `AELFRICE_CAPTURE_PRINT_MODE=1` to restore capture. Pasted aelfrice-format text inside an ordinary prompt, which #1620's prefix filter catches only in a block's first sentence, is not part of this change.

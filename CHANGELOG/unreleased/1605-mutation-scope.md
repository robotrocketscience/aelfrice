### CI

- **The per-PR mutation job no longer spends its whole budget mutating a module you only commented on ([#1605](https://github.com/robotrocketscience/aelfrice/issues/1605)).** `.github/workflows/mutation.yml` scopes mutmut with `only_mutate`, whose entries are file paths, so a file enters the mutant set whole. A comment-only edit to a large module therefore cost as much as rewriting it: on PR #1603, whose diff changed **zero** non-comment lines of `cli.py`, all 11,048 lines entered the mutant set, the job hit its 60-minute limit twice in a row, and it was cancelled before writing a report — rendering as a red X indistinguishable at a glance from a surviving mutant, on an advisory check that still turns the PR `BLOCKED`. `scripts/mutation_scope.py` now decides the scope by comparing each changed file's AST **with docstrings stripped** between base and head, rather than by classifying lines: two versions whose stripped ASTs are equal differ only by comments, docstrings, blank lines, or formatting, none of which mutmut can mutate. The dump carries no attributes, so a comment added above a statement does not read as a change through its line numbers. It fails open — a file that will not parse on either side is mutated rather than skipped, because mutating one needlessly costs runner time while skipping one wrongly costs an unmeasured mutant. The decision lives in a script rather than in the workflow because the workflow cannot be tested in CI ([#1436](https://github.com/robotrocketscience/aelfrice/issues/1436) — PyYAML is not importable there); `tests/test_mutation_scope.py` covers it, including the control that a real `a + b` to `a - b` change is **not** skipped, since a scoper that skips everything passes the comment-only arm on its own. On PR #1603's diff the script keeps `host_codex.py` and drops `cli.py`. The weekly full-tree run is unchanged — it is the arm that gates, and this is only the per-PR advisory arm.

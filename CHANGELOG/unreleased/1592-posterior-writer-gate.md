### Added

- **`scripts/check_posterior_writers.py` gates the set of code paths that can write a belief's posterior ([#1592](https://github.com/robotrocketscience/aelfrice/issues/1592)).** #1592 AC2 asks which paths write `beliefs.alpha` / `beliefs.beta`, and [#1359](https://github.com/robotrocketscience/aelfrice/issues/1359) established that writing the answer down is not enough — that enumeration surfaced a new unguarded writer every review round, because nothing stopped one being added between rounds. The checker enumerates writers from the AST and fails when the set changes without its manifest changing with it. It finds 21: **12 that can move a posterior mean, of which exactly one is the evidence path.** The other eleven are callers of `update_belief`, which is a whole-row write of an in-memory snapshot, so promotion, unlock, devalidate, scope change, review, orphan reclassification, autolock, and four sites inside the lock command each load a belief, change one unrelated field, and write `alpha`/`beta` back along with it — the shape [#1168](https://github.com/robotrocketscience/aelfrice/issues/1168) found losing 180 of 240 concurrent feedback events. The remaining nine are three creation paths, the dedupe summing path, one identity copy, and four fixture or benchmark writers that never touch a user store. Detection is AST-based rather than textual for a concrete reason: `clamp_ghosts` documents the SQL that reverses a clamp inside its module docstring, and a regex sweep reports that as a writer which does not exist. Restricting to strings in argument position excludes docstrings structurally, and f-strings are read through their literal parts. The one writer no static check can classify — `_rebuild_beliefs_table`, whose column list is interpolated at runtime — is recorded in an explicit `UNDETECTABLE` list so the manifest cannot quietly start reading as exhaustive. `benchmarks/posterior_prior_grid_sweep.py --sources` measures the other half: on 26 real stores, the `hook` source accounts for 84,416 of 86,723 feedback events (97.3%) and every one carries a valence that could move a posterior, yet 6,220 beliefs carrying such events still sit exactly on their insertion prior, because `apply_feedback` drops the bump when `update_posterior=False`.

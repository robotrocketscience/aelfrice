### Documentation

- **`benchmarks/retrieval_metrics.py` no longer claims its metrics are monotone in the token budget ([#1574](https://github.com/robotrocketscience/aelfrice/issues/1574)).** The module reasoned that "retrieval fills the budget in rank order, so cutting the budget truncates the tail", and concluded that every metric is monotone non-decreasing in the budget. `clustering.pack_with_clusters` does not truncate: stage 1 abandons on the first representative it cannot afford, and stage 2 skips an over-budget belief and keeps filling. The budget therefore **selects** rather than truncating, and raising it by one token can evict a belief the lower budget admitted. With the gold-bearing belief cheap and ranked second, that takes `recall_at_k` and `reciprocal_rank` from 1.0 to 0.0. The skip-and-continue fill is deliberate — it delivers at least as many beliefs as stopping at the first unaffordable one, though it is greedy in rank order and not count-maximal — so the docs now record the non-monotonicity as an accepted property rather than a defect, and name the tests that pin each half. The guard that appeared to cover this was `test_shrinking_the_budget_never_raises_a_metric`, which truncates a list and never sets a budget, prices a belief, or calls the packer; it is renamed to `test_truncating_the_tail_never_raises_a_metric`, scoped to tail truncation because dropping an item from the *head* promotes everything below it and can raise `reciprocal_rank`. The same false premise was corrected in `docs/concepts/BENCHMARKS.md` and in the four benchmark adapters, all of which told the reader a smaller budget "can only lower" these metrics.

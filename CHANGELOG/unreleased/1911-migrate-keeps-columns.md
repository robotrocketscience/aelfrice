### Fixed

- **`aelf migrate --apply` copies every column of each belief ([#1911](https://github.com/robotrocketscience/aelfrice/issues/1911)).** The copy built each target belief from 13 fields, so `valid_to`, `lock_tier`, `lock_expires_at`, `session_id`, `retention_class`, and `last_confirmed_at` took their defaults in the target store. A retired belief was active in the target store, a `reference` lock became `frozen`, and a time-boxed lock became permanent. The command also did not copy the `belief_corroborations` rows, which reset each copied belief's corroboration count to 0, and it dropped the anchor text of each copied edge. The copy now carries every column of each belief that the source store has, copies the corroboration rows of each belief it inserts, and keeps edge anchor text. A retired belief stays retired and stays out of keyword search. Each belief is copied in one transaction, so a rerun after a migrate that stopped partway copies the beliefs that run did not. A corroboration row with a source type or speaker that this version does not know is skipped, and the report and the command output count copied and skipped corroboration rows. A source store from before v3.8.0 can hold duplicate corroboration rows for one source, and the target keeps one of them, which is the count the source store reports once a current version opens it. A source store from an older version that lacks some of these columns still migrates, and the missing columns take their defaults as before.

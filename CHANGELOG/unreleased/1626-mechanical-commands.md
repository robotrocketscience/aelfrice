### Added

- **A typed `/aelf:` command now runs itself, instead of depending on the model to invoke it ([#1626](https://github.com/robotrocketscience/aelfrice/issues/1626)).** aelfrice's promise is that memory does not depend on the model choosing to act — beliefs are injected every prompt precisely so that locked ground truth cannot be lost or ignored. A slash command broke that promise, because a slash command is a *skill*: nothing runs it unless the model decides to, and when the model does not, the command silently does not happen. A user's `/aelf:lock` was lost exactly that way; they restated the same instruction twelve times over six weeks without it binding, and `lock_level='user'` was set on one belief out of 20,176 ([#1620](https://github.com/robotrocketscience/aelfrice/issues/1620)).

  The `UserPromptSubmit` hook now parses the prompt, runs the command, and writes the belief. Verified end to end through the real entry point: a typed `/aelf:lock <statement>` leaves the statement in `aelf locked`, with nothing invoking a skill.

  **The allowlist is narrow, and the boundary is "additive and idempotent" rather than "useful":** `lock`, `confirm`, `promote`, `scope-out`. Read-only commands are absent because the model running `aelf search` or not costs nothing durable. Destructive and environment-changing commands — `delete`, `retire`, `unlock`, `restore`, `uninstall`, `upgrade`, `setup` — are absent and must stay absent: running one off raw prompt text that no human confirmed, and which the model may merely be quoting, is a worse failure than the one being closed. Seven are asserted inert, and the executable set itself is pinned so that list cannot go vacuous by deletion.

  The hook is **authoritative**: it injects a line telling the model the command already ran, so the command runs exactly once, from the path that cannot forget. A prompt that merely *mentions* a command is inert — "the command `/aelf:lock` did not take effect yesterday" is a claim about the world, not a request.

  Failure is loud on both paths. A missing argument and an exception each report to stderr and to the model; a silent failure here would reproduce the defect inside its own fix. The executor never raises, because a command must not cost the prompt its memory injection, and that is asserted rather than assumed.

- **`aelf search` now precedes the web tools, not just the local ones.** The value of the search hook is *ordering*: aelfrice runs first, so the model already holds the relevant brain-graph context before it chooses grep, the web, or anything else. Coverage was partial — `SEARCH_TOOL_MATCHER` was `Grep|Glob` plus a separate `Bash` matcher — so a model reaching for `WebSearch` or `WebFetch` proceeded with no brain-graph context at all. Both now trigger the lane, and the query comes from each tool's own field: `pattern` for Grep and Glob, `query` for WebSearch, and `prompt` for WebFetch. The prompt, not the URL: a bare URL tokenises into host fragments that match nothing useful, so searching it would satisfy the matcher while defeating the point. Widening is bounded — `Read`, `Write`, `Edit` and `TodoWrite` are asserted *not* to trigger the lane, so every tool call does not now pay for retrieval.

  Nine tests transcribed the matcher as a literal `"Grep|Glob"` and went stale the moment it widened. They now derive `SEARCH_TOOL_MATCHER` from the source, because a transcribed constant is a second copy free to drift from the one that ships.

  The executed-command note is bounded by `COMMAND_BLOCK_CHAR_CAP`; it carries the command's own stdout and a command may print as much as it likes. Two existing guards found that for us rather than the other way round: `test_the_stdout_writer_enumeration_is_re_derived_from_the_source` parses `user_prompt_submit` and rejects an unregistered writer, and `_PAD_CHARS` in `test_render_cost_1526` discovers the largest shipped character cap and refuses to be dominated by a new one.

  Eleven mutations were run and all eleven fail the suite. Two are recorded as **equivalent** rather than as gaps: dropping `^` from the command pattern, and swapping `.match` for `.search`, each survive alone, because anchoring is carried by both mechanisms independently. Only removing both changes behaviour, and that kills the mention arms.

  **What this does not do:** the destructive commands still depend on the model, by design. [#1622](https://github.com/robotrocketscience/aelfrice/issues/1622) — reconciling "a command was requested" against "a command ran" — remains the backstop for everything this does not cover.

### Added

- **A typed `/aelf:` command now runs itself, instead of depending on the model to invoke it ([#1626](https://github.com/robotrocketscience/aelfrice/issues/1626)).** aelfrice's promise is that memory does not depend on the model choosing to act — beliefs are injected every prompt precisely so that locked ground truth cannot be lost or ignored. A slash command broke that promise, because a slash command is a *skill*: nothing runs it unless the model decides to, and when the model does not, the command silently does not happen. A user's `/aelf:lock` was lost exactly that way; they restated the same instruction twelve times over six weeks without it binding, and `lock_level='user'` was set on one belief out of 20,176 ([#1620](https://github.com/robotrocketscience/aelfrice/issues/1620)). The `UserPromptSubmit` hook now parses the prompt, runs the command, and writes the belief, verified end to end through the real entry point. **The allowlist is narrow, and the boundary is "additive and idempotent" rather than "useful":** `lock`, `confirm`, `promote`, `scope-out`. Read-only commands are absent because the model running `aelf search` or not costs nothing durable. Destructive and environment-changing commands — `delete`, `retire`, `unlock`, `restore`, `uninstall`, `upgrade`, `setup` — are absent and must stay absent: running one off raw prompt text that no human confirmed, and which the model may merely be quoting, is a worse failure than the one being closed. Seven are asserted inert with arguments attached, because three of them used to be tested bare and were refused by the empty-argument guard rather than by the allowlist — passing on the wrong rule. The executable set itself is pinned so the list cannot go vacuous by deletion. The hook is **authoritative**: it injects a line telling the model the command already ran, so the command runs exactly once, from the path that cannot forget. A prompt that merely *mentions* a command is inert. **The argument is the first line only** — an earlier revision matched under `re.DOTALL`, so `/aelf:lock Always use uv.` followed by any further prose locked the entire message as one user-locked belief, re-injected as standing ground truth on every later turn; typing a command and then continuing the message is the most natural thing a user does. **The argument may not begin with `-`**, because `argv` is `[command, argument]` and a leading dash reaches argparse: `/aelf:lock --help` emitted 2,265 characters of usage onto this hook's stdout protocol channel, outside the character cap and outside the writer enumeration meant to prevent exactly that, and `/aelf:lock --advanced` exited 0 and reported a lock that never happened. The CLI call additionally runs under a stdout redirect, because argparse writes to the real `sys.stdout` and that stream *is* the protocol. Failure is loud on every path — a missing argument, a flag, an exception, and a non-zero exit each report to stderr and to the model — while a clean `SystemExit(0)` is no longer mis-reported as failure, which `int(exc.code or 1)` used to do. The executor never raises, because a command must not cost the prompt its memory injection, and that is asserted rather than assumed. Seventeen mutations were run and all seventeen fail the suite, including removing the note's character cap, making the `AELF_SESSION_ID` restore a no-op, and restoring each of the defects above.

### Added

- **A typed `/aelf:` command now runs itself, instead of depending on the model to invoke it ([#1626](https://github.com/robotrocketscience/aelfrice/issues/1626)).** aelfrice's promise is that memory does not depend on the model choosing to act — beliefs are injected every prompt precisely so that locked ground truth cannot be lost or ignored. A slash command broke that promise, because a slash command is a *skill*: nothing runs it unless the model decides to, and when the model does not, the command silently does not happen. A user's `/aelf:lock` was lost exactly that way; they restated the same instruction twelve times over six weeks without it binding, and `lock_level='user'` was set on one belief out of 20,176 ([#1620](https://github.com/robotrocketscience/aelfrice/issues/1620)). The `UserPromptSubmit` hook now parses the prompt, runs the command, and writes the belief, verified end to end through the real entry point. **The allowlist is narrow, and the boundary is "additive and idempotent" rather than "useful":** `lock`, `confirm`, `promote`, `scope-out`. Read-only commands are absent because the model running `aelf search` or not costs nothing durable. Destructive and environment-changing commands — `delete`, `retire`, `unlock`, `restore`, `uninstall`, `upgrade`, `setup` — are absent and must stay absent: running one off raw prompt text that no human confirmed, and which the model may merely be quoting, is a worse failure than the one being closed. Seven are asserted inert with arguments attached, because three of them used to be tested bare and were refused by the empty-argument guard rather than by the allowlist — passing on the wrong rule. The executable set itself is pinned so the list cannot go vacuous by deletion. The hook is **authoritative**, and it is authoritative in both directions: on success it injects a line telling the model the command already ran, so the command runs exactly once from the path that cannot forget — and on a refusal, a missing argument, an exception or a non-zero exit it injects a *different* block saying the command did **not** take effect. A single unconditional frame was #1620's own failure class reproduced inside its fix: nothing had been written, yet the model was told the work was done and instructed not to redo it, which disabled the one remaining fallback for exactly the cases that needed it. **`/aelf:scope-out` also had to move.** The executor originally ran ahead of `is_session_first_prompt`, which is the only writer of the key `aelf scope-out` resolves its target session from — so the exclusion attached to whichever session most recently *started*, `load_exclusions` returned `[]` on the mismatch, and the model was told it had applied. On a session's genuine first prompt the state file did not exist yet and the command failed outright, then the same turn created the file, so it worked on the retry and looked like a flake. This was a regression introduced by executing early: a model-invoked `aelf scope-out` necessarily ran after the hook. The session stamp is now taken first. A prompt that merely *mentions* a command is inert. **An argument over `COMMAND_ARGUMENT_CAP` is refused, not truncated** — the CLI has always accepted an arbitrarily long statement, but nothing confirms a Bash call any more, so a 200,000-character paste beginning with `/aelf:lock` reached the highest-trust tier in one turn and could crowd the whole lock budget; truncating instead would store something the user never typed. **The argument is the first line only** — an earlier revision matched under `re.DOTALL`, so `/aelf:lock Always use uv.` followed by any further prose locked the entire message as one user-locked belief, re-injected as standing ground truth on every later turn; typing a command and then continuing the message is the most natural thing a user does. "First line" means every terminator `str.splitlines` recognises, not just `\n`: the first fix for this excluded `\n` alone, which left the entire defect reachable from a CR-only client, from `\v`/`\f`, and from the Unicode separators `\x1c`-`\x1e`, NEL, U+2028 and U+2029 — ten of the eleven terminators still swallowed the rest of the prompt, so the fix closed one case out of eleven and read as if it had closed all of them. **The argument may not begin with `-`**, because `argv` is `[command, argument]` and a leading dash reaches argparse: `/aelf:lock --help` emitted 2,265 characters of usage onto this hook's stdout protocol channel, outside the character cap and outside the writer enumeration meant to prevent exactly that, and `/aelf:lock --advanced` exited 0 and reported a lock that never happened. The CLI call additionally runs under a stdout redirect, because argparse writes to the real `sys.stdout` and that stream *is* the protocol. Failure is loud on every path — a missing argument, a flag, an exception, and a non-zero exit each report to stderr and to the model — while a clean `SystemExit(0)` is no longer mis-reported as failure, which `int(exc.code or 1)` used to do. The executor never raises, because a command must not cost the prompt its memory injection, and that is asserted rather than assumed. A blind adversarial review then retracted three claims made here, and each retraction is recorded rather than quietly fixed. "Seventeen mutations, all killed" was **false**: removing the stdout redirect and dropping the install's `and not removed_superseded` term both left the suite green. The redirect arm was vacuous for a specific reason worth naming — two guards covered one path, so mutating either was survived by the other, and the leak is only reachable with both gone. "Never raises" was also false; the executor raises if its own `stderr` is closed, so the caller keeps its guard and the docstring now says so. And the cap's stated justification, that `aelf lock` echoes the statement back, was wrong in three places: `aelf lock` prints `locked: <id>`, 25 characters whatever the statement's length, which is exactly why the first cap arm proved nothing. A second blind pass then upheld all eight claims but found four more things worth fixing before merge, two of which contradicted rules this change had just written down. **The report now echoes what was stored**, because `/aelf:lock Always use uv` followed by U+2028 and more prose stores `Always use uv` and `aelf lock` prints only `locked: <id>` — so a sentence that looked like one line to the person typing it was silently halved. The length cap can refuse, since "too long" is decidable; "they meant this to be one line" is not, so the answer there is to show the result rather than guess at it. **A mistyped command name is no longer a command**: `[a-z0-9-]*` stops at the first character outside the class, so `/aelf:lockFOO bar` parsed as `lock` with argument `FOO bar` and wrote it at the highest trust tier. No destructive command was ever reachable that way — none has an allowlisted prefix — but a user-locked belief from a typo is its own defect. **The writer-enumeration gate now keys on the block's tag, not only on the variable written**, which matters because this change is what first put two blocks under one key: the executed and failed frames both write `command_note`, the table recorded the first tag alone, and a third block reusing that local passed the gate while the ceiling docstring claimed a sixth writer would red it. And a hand-edited settings file that stores an inner hook as a bare string rather than an object now has its superseded entry retired too. The hook's import of `cli` also **closed an import cycle**, which CodeQL caught and which this change created: `cli` imported one constant back from `hook`, `AELFRICE_SESSIONSTART_RECAP`, used only to interpolate its name into a help string. Both edges were function-local, so nothing failed at interpreter start — which is why it went unnoticed, and is not a defence, since a cycle that survives only because every edge is deferred fails the first time one is needed at module scope. The constant moved to a new `aelfrice.env_names`, which imports nothing from `aelfrice` by construction and so cannot be part of a cycle; `cli` no longer imports `hook` at all, and a test asserts that in the cheap direction rather than permitting "only lazily", which is how this accumulated. `hook` reads the name through a function rather than re-exporting it, because a module-scope import would take the modules loaded by `import aelfrice.hook` from 18 to 19 — a ceiling pinned deliberately, since every process importing the hook pays it. Measured at ~1.0 ms over 9 fresh interpreters, inside the run-to-run spread and not cleanly separable from noise; paid anyway rather than spent on a string constant with one reader. **Thirty-two mutations now run and all thirty-two fail the suite** — seventeen original, eleven for the first review round, four for the second, each killed by the test written for it rather than by a neighbour.

### Internal

- **Tests now pin which directory a prompt's store comes from ([#1630](https://github.com/robotrocketscience/aelfrice/issues/1630)).** The UserPromptSubmit hook reads the store from its own working directory, and the payload's `cwd` field doesn't change that. Until now, no test held that choice, so a change could split one prompt across two stores without failing anything. New behavioral tests give the hook a payload `cwd` that names a different repository. They check that the shared store handle, the typed `/aelf:` command, the command-outcome row, and the session-state files still use the hook's own directory, that a typed `/aelf:scope-out` still takes effect on the next prompt, and that an explicit `AELFRICE_DB` still overrides both directories. A structural test covers the store consumers that a default prompt doesn't reach: it requires every `db_path()` call in the hook modules to take no arguments, rejects `chdir`, git-directory lookups at another directory, and any `AELFRICE_DB` override, and holds every `db_path()` call, every store construction in `hook.py`, and every store-layout path join to an explicit inventory. One pre-existing exception is listed in that inventory: the conversation-aware query and the context rebuilder read the transcript log under the payload `cwd`. No behavior changed. The host runs hooks in the session's current directory, and the [measurement on #1630](https://github.com/robotrocketscience/aelfrice/issues/1630#issuecomment-5974623437) found no genuine divergence between the two directories.

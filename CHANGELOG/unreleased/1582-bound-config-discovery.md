### Fixed

- **`.aelfrice.toml` discovery no longer escapes the project ([#1582](https://github.com/robotrocketscience/aelfrice/issues/1582)).** The shared walk ascended to the filesystem root, so from any directory under `$HOME` it found `$HOME/.aelfrice.toml` — per-user configuration, from a code path `docs/user/CONFIG.md` documented as having none. The walk now stops at the first of: your home directory (checked before the probe, so `~/.aelfrice.toml` is never read), a directory holding `.aelfrice.toml`, a directory holding `.git`, or the filesystem root. Every reader funnels through `config_discovery.discover_config`, so all of them are bounded identically, and a new AST guard fails if a module grows a walk of its own. **Behavior change:** a `~/.aelfrice.toml` that used to apply to every project under your home directory is now ignored. Copy the keys into each project's own `.aelfrice.toml`, or export the matching `AELFRICE_*` environment variable, which still outranks the file.

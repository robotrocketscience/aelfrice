### Fixed

- **Retiring a locked belief ends its lock ([#1945](https://github.com/robotrocketscience/aelfrice/issues/1945)).** Before this fix, `aelf retire --force` on a locked belief set only `valid_to` and left `lock_level = 'user'` on the retired row, so `aelf status` counted the lock, `aelf locked` didn't list it, and `aelf unlock` reported `belief not found`. Every soft-delete now clears `lock_level`, `locked_at`, and `lock_expires_at` on a locked row and writes one `lock:retire` audit row (valence 0) stamped with the retire time. This covers `aelf retire`, the `/aelf:review` remove verdict, and the other soft-delete paths. `count_locked` filters `valid_to IS NULL`, as `list_locked_beliefs` does, so the `aelf status` lock count matches `aelf locked`. `aelf unlock` reaches a retired row and leaves it retired. A one-time migration on store open unlocks each retired row that an earlier release left locked and writes one `lock:retire` row for each, stamped with the migration time; the `retired_lock_cleanup_complete` marker in `schema_meta` keeps it from running again. `aelf restore` brings a formerly locked belief back unlocked; to lock it again, run `aelf lock` with its text. Before this fix, restoring such a belief brought its lock back too.

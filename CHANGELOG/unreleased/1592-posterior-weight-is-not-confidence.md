### Documentation

- **`docs/user/CONFIG.md` no longer presents `posterior_weight` as a confidence signal ([#1592](https://github.com/robotrocketscience/aelfrice/issues/1592)).** The key blends `log(posterior_mean)` into the L1 BM25 score, and a reader would reasonably expect that posterior to reflect how a belief has performed. On a real store it mostly does not: aelfrice sets `(α, β)` at ingest from the belief's type and source, and about 95% of beliefs across a measured 26-store population still sit on exactly that value, so for most of a store the blend term is a fixed function of `(type, source)`. The new subsection tabulates every path that moves a posterior with its direction and default — `aelf confirm`, which is exempt from the [#1168](https://github.com/robotrocketscience/aelfrice/issues/1168) lock floor and so moves a locked belief; `aelf feedback`, which is not and so needs `aelf unlock` first; propagation of either, on by default; sentiment from prose, off unless enabled by environment variable **or** the `[feedback] sentiment_from_prose` key; the manual `aelf clamp-ghosts` sweep, which lowers α on exactly the beliefs that have no feedback and no corroborations; and store deduplication, which merges beliefs sharing a content hash and **sums** their `(α, β)` when the store is opened, so a merged belief's mean shifts with no user action at all. Retrieval exposure used to add `+0.1` per surfacing until [#1086](https://github.com/robotrocketscience/aelfrice/issues/1086) made it audit-only in July 2026, having measured that it promoted junk above real knowledge. The tuning advice is corrected in both directions: raising the weight makes retrieval more type-aware rather than more confidence-aware, and the two prior axes are not jointly ordered — an agent-inferred requirement (0.783) outranks a user-stated fact (0.750), so "user content ranks above agent content" holds only within a single type. The clustering onto a handful of posterior values that the staircase section already describes is now connected to its cause, rather than left reading as a quirk of a particular corpus. The sample TOML comment next to `posterior_weight = 0.5`, where someone tuning the key actually looks, carries the same correction.

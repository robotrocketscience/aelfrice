### Fixed

- **Files that changed in a merge commit get that merge's date ([#1612](https://github.com/robotrocketscience/aelfrice/issues/1612)).** git lists no paths for a merge commit by default, so a file that arrived only through a merge, such as a history import, had no git date and fell back to the ingest time, and a conflict resolved to new content kept the date of the last edit before the merge. The scanner now asks git for the paths a merge changed relative to every parent (`--cc`), which matches the per-path `git log -1 -- <path>` answer: on a merge-heavy repository it agreed on all 576 tracked files, where first-parent attribution got 364 wrong. It's still one `git log` per scan. One case still differs from the per-path answer: a side-branch edit that a merge discarded can still date the file.

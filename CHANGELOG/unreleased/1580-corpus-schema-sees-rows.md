### Fixed

- **The corpus schema validator read an empty scaffold, so no corpus row had ever been checked ([#1580](https://github.com/robotrocketscience/aelfrice/issues/1580)).** `tests/test_corpus_schema.py` pinned its root to `tests/corpus/v2_0/`, the public scaffold, which holds 17 module directories, a `.gitkeep` in each, a README, and no rows at all. All 19 modules the table parametrizes resolved against it. Every per-module assertion skipped on every run, and the skip said nothing, so a green tail was indistinguishable from a validated corpus. The root now resolves from `AELFRICE_CORPUS_ROOT` when you set it and falls back to the public tree otherwise; a skip names the root it inspected and where that root came from, a module that runs reports how many rows it validated, and zero rows fails rather than passes. The reported count prints in a `corpus schema` section of the terminal summary, next to the bench-gate tier's own block, and it prints for a test that errored as well as one that passed or failed, since a run that died is the one where the number is most missing. The module records that count from a `finally`, so it survives the walk's own failures — an unparseable line or a row that is not an object both raise partway through, and a failure with no count leaves you unable to tell whether validation read 3 rows or 500 before it stopped. An aborted walk says so, since its count is a floor rather than the module's size. **Turning it on is what found the violations, and the violations are recorded rather than repaired,** because relabelling a corpus is the corpus owner's decision and not this change's: `KNOWN_FAILURES` carries a reason per module and per rule, and the list is a ratchet in both directions — an unrecorded violation fails its module, and a recorded one that stops reproducing fails it too, so a repair forces the entry out instead of leaving a permanent exemption behind. Every reproducing entry prints alongside the row count, because a green run plus a waiver nobody reads is the quiet exemption this was meant to avoid, and it prints how many rows it covers, because a waiver is per module and per rule and a later batch carrying the same violation would otherwise land inside it silently. Against the mounted lab corpus that is 510 `directive_detection` rows validated, breaking two recorded rules: the v0_1 batch carries no `provenance` at all, and both batches spell the negative class `not-directive` where the schema declares `not_directive` (304 of 510 rows). **A second gap was that two corpora were not merely failing but invisible:** the per-module test parametrizes over the `MODULES` table, so `compression_uplift` and `query_strategy` — which hold rows, carry no envelope of any kind, and have no public scaffold directory — contributed no rows, no failure and no skip. A new check compares the directories holding rows against the table and fails on any that is neither declared nor recorded in `KNOWN_UNDECLARED_MODULES` with a reason. Holding rows means at least one non-blank line, not merely the presence of a `*.jsonl`: a half-built module is the normal state of this corpus, the public tree ships scaffolding for modules nobody has labelled yet, and zero rows cannot go unvalidated — so an empty scaffold is not the gap this guards against, and does not have to be enumerated to keep the suite green. The label rules gain the case the issue names: where a consuming detector exposes its own label constant, the module's vocabulary is checked against it and a row label the scorer can never return is rejected at validation, since such a row is graded wrong however the detector behaves. `relationship_detector.VERDICT_LABELS` is the worked case and `contradiction`'s `compatible` is the label — verified against a lab corpus copy of 79 rows, 27 of them labelled that way; no `contradiction/` module is mounted under the canonical lab root today, so that entry is recorded but does not yet execute. Each rule is mutation-proven on its own arm, `duplicate-id` included: it compares a row against the rows before it rather than against the schema, so the walk is extracted into a helper a unit test can hand two rows that agree on `id`. The scoreability arm widens the module's declared set so the vocabulary rule passes and only scoreability can fire — on the shipped table the two always agree, so an arm that did not separate them would prove nothing. `MODULES['contradiction']` spells its three labels out rather than deriving them from `VERDICT_LABELS`, because a table derived from the constant is the same object as the constant and the drift check between them could then never fail. One adjacent correction in `tests/conftest.py`: the bench-gate tier counted any skip whose reason mentioned `AELFRICE_CORPUS_ROOT`, and the schema walk names that variable in twenty skips of its own (19 module parametrizations plus the undeclared-module check), which would have been attributed to the retrieval, compression, and clustering gates. Classification now matches the tier's shared skip reason instead of the substring.

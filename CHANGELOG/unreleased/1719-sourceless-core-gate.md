### Fixed

- **A missing classifier source no longer drops the session-start block ([#1719](https://github.com/robotrocketscience/aelfrice/issues/1719)).** `aelfrice.core_gate` derives `CLASSIFIER_VERSION` from the source of its prompt builder and reply parser. On an install that ships only bytecode, `inspect.getsource` raises `OSError`, so the import failed. The SessionStart hook imports the module whenever there are core candidates, and its fail-soft wrapper then dropped the whole session-start block, including `<locked>`. Now `CLASSIFIER_VERSION` is `None` when the source is missing, and the failure stays in the core lane. The gate admits no unlocked belief to `<core>`, no stored label matches a `None` version, and nothing writes a batch or a label: `aelf core-gate accept` and `aelf doctor core-gate --emit` exit 1 with a message, `--rerun` refuses, the Stop hook emits no session-end batch, and `aelf doctor core-gate` reports that no candidate is admitted. When the source is present, the version is unchanged.

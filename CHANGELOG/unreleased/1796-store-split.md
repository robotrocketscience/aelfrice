### Added

- **`aelf store split` copies beliefs into the stores that `[store]` markers select ([#1796](https://github.com/robotrocketscience/aelfrice/issues/1796)).** When you add a marker to a folder of a repository that already has beliefs, run `aelf store split` to see which beliefs the folder's store would receive, and `aelf store split --apply` to copy them. A belief qualifies when onboarding read it from a document paragraph or a Python docstring under the folder; the command finds the file from the belief's ingest records and the folder its onboard session scanned. The command copies and never moves: it opens the repository store read-only. A copy keeps its id, takes the target store's identity, and brings its document anchors, feedback history, corroborations, and the edges and support-evidence rows whose two beliefs both land in the target. Injection events, belief touches, the deferred-feedback queue, sessions, and ingest records aren't copied. A belief the target already holds, by id or by content, is skipped, so a second `--apply` copies nothing. Locked beliefs, retired beliefs, and superseded beliefs whose superseding belief stays behind are skipped and reported. Each target store's copy runs in one transaction. A broken marker anywhere in the work tree stops the command with exit status 2 before it writes, and so does a folder in the work tree that it can't list or search, which the error names. Also, `--apply` refuses to run while `AELFRICE_DB` is set. A dry run with that variable set reads no marker, so it doesn't report a broken one. Beliefs that `aelf onboard <path>` ingested without `--emit-candidates`, or that `/aelf:onboard` ingested with the regex classifier, record no onboard folder, so the command skips them as `no_root`, and so does an onboard run on a relative path such as `.`. A belief whose onboard folder no longer exists, such as a removed worktree, is skipped as `missing_root`, because the command can't tell whether that folder was a worktree.

### Fixed

- **The injected memory block is bounded again, and user locks are exempt from the bound ([#1551](https://github.com/robotrocketscience/aelfrice/issues/1551)).** `DEFAULT_HOOK_TOKEN_BUDGET = 1500` is passed to `retrieve()` and the packers in `clustering.py` honour it, but `<locked>`, `<core>`, `<recent-work>` and the retrieval hits are packed independently and concatenated, so no budget bounded the block that reached the model. `_write_hook_audit_record` already measured the result with the same 4-chars-per-token estimator the budgeter uses and wrote the overrun to `hook_audit.jsonl`; nothing acted on it.

  **One write path.** Every `<aelfrice-memory>` write now goes through `_write_memory_block`, which trims, notes and emits. Three sites emit that envelope — `user_prompt_submit`'s retrieval branch, its `elif gate_skip:` branch, and `session_start` — and only the first was ever bounded. The gate-skip branch ships a session's whole `<locked>` and `<core>` sub-block whenever the #674 prompt-shape gate refuses BM25 on a first prompt (a first prompt under 12 characters, an acknowledgement), which on shipped defaults is routine: measured at 16,526 estimated tokens from a 300-lock store against a 6,000-token ceiling, with nothing on stderr.

  **The drop policy: both bounds stop at `lock="user"`.** `enforce_block_ceiling` drops whole `<belief>` elements until the body fits `HOOK_BLOCK_TOKEN_CEILING`, and never drops a user-locked one; `_cap_belief_content` truncates one belief's content at `BELIEF_CONTENT_CHAR_CAP = 1200` at each render site — the retrieval hits, `<core>`, and the non-locked entries of `<locked>` — and never truncates user-locked content. That is the #379 / #1016-B contract: locks are the always-injected pool, and a bound that deleted them would have been the thing that broke it. An earlier revision of this change did exactly that — on a 300-lock store all 300 locked elements were removed, leaving an empty `<locked>` section under 300 dangling `seen <id>` manifest pointers. A block that cannot fit without dropping a lock is emitted over the ceiling with a one-line note on stderr naming the overrun and pointing at `aelf lock --reference`, which is the bounded form of a long lock. The only spans ever removed are complete elements and the `seen` pointers that name them — the paragraph below is why the pointer goes with its element — so every framing tag, including the `<aelfrice-locks-manifest>` wrapper, is untouched and the block stays well-formed, and the ids of anything dropped are returned so the audit record, the `injection_events` rows, the session ring, `belief_touches` and the #1382 ledger credit only what was actually emitted.

  **The shed order is by lane, so the prompt's own hits go last.** The lanes are emitted `<locked>`, `<core>`, `<recent-work>`, per-turn hits, so a dropper that took the end of the body took the retrieval hits *this prompt* selected and kept the `<core>` pool the prompt had no part in choosing — `<core>` ranks by corroboration and posterior, `<recent-work>` by the git state of the checkout, and neither consults the prompt. The removal order is now `<core>` tail-first, then `<recent-work>`, then the hits, with locks undroppable throughout; within a lane it is still tail-first, because each lane is already sorted worst-last. Measured on 50 user locks of 150 characters, 20 `<core>` beliefs without the query term and 20 hits with it — re-derive with `uv run python scripts/measure_block_ceiling.py --lanes` — the block carried 6/20 hits and 19/20 core untrimmed, 0/20 and 17/20 under the old order, and 6/20 and 7/20 under the new one: every hit the untrimmed block had, and the bytes taken out of the lane the prompt did not choose.

  **A dropped element takes its `seen` pointer with it.** The dangling pointers above were an instance of a wider class, not a locks-only accident: any dropped element that another line points at leaves the pointer behind. `retrieval.seen_manifest_line` states the contract — the entry exists because "the full text is already in this context window, above" — so a `seen <id>` line whose element the trim deleted tells the model to look up text that is not in the block. On a session's first prompt #1547's dedupe puts both halves in one envelope, rendering a belief verbatim in `<core>` and as a pointer among the per-turn hits, and a `<core>` element carries no `lock="user"`. Measured against the shipped 6,000-token ceiling: 55 user locks of 200 characters plus 40 corroborated beliefs of 2,000 gave 57 `seen` ids against 55 elements, 2 dangling; 80 locks plus 20 such beliefs gave 82 against 80. `enforce_block_ceiling` now removes the pointer with the element rather than exempting a pointed-at element from the drop, because exempting it would let a size optimisation pin bytes in place — on a first prompt where every `<core>` entry is also a hit, that is the whole droppable set. A pointer to a belief rendered on an earlier turn is untouched: no element in this body carries its id.

  **The ceiling is a real limit, not an unreachable one.** An earlier revision of this entry and of the constant's docstring said it was "set well above the sum of the per-lane budgets so it does not fire on a healthy store". That was not measured and is false: on a session's first prompt, where the `<locked>` sub-block and the per-turn hits share one envelope, it first reports at 66 user locks of 150 characters and at 58 of 200 — re-derive with `uv run python scripts/measure_block_ceiling.py --lock-chars 150 200`. Override with `AELFRICE_HOOK_BLOCK_CEILING`; only a literal `0` disables it, and a negative or unparseable value falls back to the default with a note rather than silently removing the backstop, which `-1` used to do.

  The UserPromptSubmit lane also charges the line it renders. It passes `hook._ups_belief_line_cost` to `retrieve()` as `belief_cost_fn`, the counterpart of `hook_search_tool._belief_line_cost` on the PreToolUse lane (#1526 item 4). Without it the packer charged the whole of a belief's content while the renderer emitted at most `BELIEF_CONTENT_CHAR_CAP` of it, so a 35,000-character belief cost 8,763 tokens against a budget of 1,500, was rejected outright, and the fire injected an **empty block** — the cap never ran, on the lane the cap was added for. It now costs 321 and is admitted, capped.

  Re-tuning `DEFAULT_HOOK_TOKEN_BUDGET` itself is still not attempted: that needs a retrieval-quality gate rather than a byte count, as that constant's docstring already flags. A capped belief keeps its id, so its full text stays reachable through `aelf search` or an anchored document.

### Added

- **`--host gemini` connects aelfrice to Gemini CLI ([#1812](https://github.com/robotrocketscience/aelfrice/issues/1812)).** `aelf setup --host gemini` adds aelfrice hooks to Gemini's user `settings.json`, in `~/.gemini`, or in `$GEMINI_CLI_HOME/.gemini` when that variable is set, and writes each `/aelf:*` command as a TOML file under `commands/aelf/` beside it, so Gemini runs them as `/aelf:search` and so on. Every hook runs one new console script, `aelf-gemini-hook`, at the absolute path setup resolves on your machine, quoted for the shell Gemini runs hooks under when the path holds a space, and nothing is written into the project. At session start the hook injects your locked beliefs; on each prompt it injects retrieval results and logs the turn; at the end of each turn it logs the reply and runs the lock prompt; and before compression it logs the turn. The Stop hook's core-gate follow-up turn and its background labeler don't run on this host. Restart Gemini CLI after setup to load the hooks. On a machine whose Claude settings carry no aelfrice hook, setup also opts the Claude host out of auto-install, as `--host codex` does. `aelf doctor --host gemini` checks the hooks, the commands, the `hooksConfig.enabled` setting, and that `aelf` is on `PATH`, and exits 1 only when installed wiring is broken. `aelf unsetup --host gemini` and `aelf uninstall --host gemini` remove only the aelfrice hooks and commands, delete a `settings.json` or `commands/` directory that this leaves empty, and leave the Claude and Codex hosts untouched. `aelf setup --host gemini` accepts only `--force`, which replaces a `settings.json` that isn't plain JSON, such as one with comments, and `aelf unsetup --host gemini` accepts only `--host`; any other option exits 2 and changes nothing. `--host` still defaults to `claude`. The hooks don't act on Gemini's tool calls yet, so the search, issue-duplicate, and commit hooks of the Claude host have no Gemini counterpart.

### CI

- **The per-PR mutation job runs its mutants again, and says when a run tested nothing ([#1746](https://github.com/robotrocketscience/aelfrice/issues/1746)).**
  - **The cause:** mutmut first runs the suite unmodified inside `mutants/`. If any test fails there, mutmut stops before running a mutant, and every mutant stays `not checked`. Seven tests failed there, and one more failed only because of test order. The Report step exits 0 by design, so the PR showed a green tick over runs that executed nothing.
  - **Copied files:** `SECURITY.md` and `pyright_baseline.json` are now in `[tool.mutmut] also_copy`. The guard that derives that list from the suite missed both, because it didn't recognize a bare `REPO` constant. It does now.
  - **Source-scanning tests:** 75 tests read `src/aelfrice` as text. Inside `mutants/` they read mutmut's mutated copies, which hold each function once per mutant, and fail or time out. They now carry a `source_scan` marker, and the mutation run leaves them out with `-m "not source_scan"`.
  - **Guard:** `tests/source_scan_guard.py` fails any test that reads a `.py` file under `src/aelfrice` without the marker, and fails collection of a test module whose import reads one, so a new source scan fails in the ordinary suite instead of stopping the next mutation run. It ignores imports, traceback, warning, and stack rendering, `runpy`, and Hypothesis sampling constants from imported modules. It clears the test module's caches before each test, so a cached scan is seen in every test that uses it. It can't see a read in a subprocess, a scan memoised by hand, or one cached in a fixture or a shared helper module.
  - **Other exclusions:** `tests/e2e` is left out, as CI's pytest job already does, because it runs the installed `aelf` in a subprocess and can't kill a mutant. Nine test functions are left out through `--deselect`, each with its reason stated in `[tool.mutmut]`:
    - two scans that list tracked files with `git ls-files`, which finds none in the untracked `mutants/` copy;
    - a producer subprocess that inherits mutmut's stats mode;
    - six `insert_belief` gate cases, which name the calling module and see mutmut's trampoline instead.
  - **Test order:** `tests/test_budget_aa_replicate.py` failed when `tests/test_budget_census.py` loaded the census first in the same process, as mutmut's collection pass does. Its loader now drops the cached census.
  - **Warning:** when every mutant is `not checked`, or mutmut lists none, the Report step now emits a `::warning::` and puts a warning at the top of the step summary. A failing clean run is one cause; mutmut also stops early when it finds no test for any mutant, or when its forced-fail check fails. The job still exits 0.
  - **Measured locally:** with mutmut 3.8.0 scoped to `src/aelfrice/db_paths.py`, all 275 mutants were `not checked` before the fix. After it, on the current `db_paths.py`, 242 of 316 mutants were killed and 74 survived, with none left `not checked`. Then mutmut 3.8.0 ran on a git clone of the branch, with `only_mutate` set to the six files whose mutants broke the most tests (`hook.py`, `store.py`, `ingest.py`, `core_gate.py`, `scanner.py`, and `triple_extractor.py`, 11,865 mutants) and CI's unscaled test timeouts. Its stats pass, clean run, and forced-fail check all passed, and it judged 3,839 mutants (2,771 killed, 1,065 survived, 3 timed out) before the run was stopped.
  - **Subprocess race test:** `test_two_concurrent_accepts_of_one_batch_have_exactly_one_winner` started two `aelf core-gate accept` processes that imported the unmutated package while the test imported `mutants/src`. Their classifier versions, a digest of `core_gate`'s source, didn't match, so both were refused and mutmut's stats pass stopped. The children now get the test's own package path.
  - **Temporary files:** mutmut runs a pytest session per mutant in a forked worker. pytest keeps a session's numbered temporary root while its lock file exists and removes the lock at exit, which those workers never reach, so a long run filled the disk. Under mutmut, `tests/mutation_tmp.py` now removes each session's own root when the session ends. pytest's `tmp_path_retention_policy = "none"` isn't used: it deletes every other session's root, live ones included.
  - **Pinned list:** a test now asserts the exact `pytest_add_cli_args` list, so dropping a `--deselect` or changing its flag fails the suite instead of the next mutation run.

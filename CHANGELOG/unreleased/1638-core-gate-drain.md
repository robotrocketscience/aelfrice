### Added

- **`aelf doctor core-gate` drains the core admission gate's backlog ([#1638](https://github.com/robotrocketscience/aelfrice/issues/1638)).** The backlog is the active, unlocked beliefs that meet the core rule without the gate and have no label under the current classifier version. `aelf doctor core-gate` counts the core candidates with each label and with none, and writes no batch or label. With `--emit`, it splits the backlog evenly, in belief id order, into as few batches of up to 50 beliefs as it can, with sizes that differ by at most one (151 beliefs make 38, 38, 38, and 37, not 50, 50, 50, and 1, because a one-snippet batch can only score a C share of 0 or 1 and would trip the self-check). It records each batch and prints each batch's id, its full classifier prompt, and the `aelf core-gate accept <batch-id>` command that takes the model's reply. `--out DIR` writes each prompt to a file instead, `--limit N` prints at most N batches, and `--json` prints the result as one object. Each emit is its own run for the accept self-check, so emitting with a small `--limit` and accepting between emits gives runs of fewer than four batches, which the check skips; the `--limit` output advises accepting all batches of one emit before emitting again. The batch records are the only writes, and the whole emit, reads included, runs under one write lock, so two emits at once can't batch the same beliefs twice. If `--out` can't write a prompt file, the command exits 1, but the recorded batches stay and the next emit prints them again.

  An emit doesn't batch a belief twice. If a batch from an earlier emit isn't accepted yet, and all of its beliefs are still unlabeled, unchanged, and in core, the next emit prints that batch again, with the same id and prompt. Otherwise the emit sets the batch aside and puts its unlabeled beliefs in a new batch. A set-aside batch stays open, since its beliefs can return to the backlog, for example when a lock is lifted. Accepting it is harmless, because each label is keyed to the content the model judged, but it replaces a label a newer batch wrote for the same belief, and that label then counts toward the set-aside batch's emit run in the self-check.

  `aelf core-gate accept` now runs the spec's self-check after it accepts a batch from `aelf doctor core-gate --emit`. Over the accepted batches of the same emit run, it names on stderr each batch whose share of C labels differs by more than 0.25 from the median share of the other batches. The check reports only: the labels stay cached, and the exit code is unchanged. All the batches of one emit share one creation time, which identifies the run, so the check needs no new column. The check runs only when the run has at least four accepted batches; with three, each batch's median of the others is the mean of two shares, so one failed batch flags the healthy ones too. Below four, the command says on stderr that it skipped the check.

  `aelf doctor core-gate --rerun <batch-id>` re-runs one accepted batch, which is the spec's step 2 for a flagged batch. In one transaction, it deletes the labels the batch still owns, so a label that a later batch wrote for the same belief stays, and batches again the beliefs whose labels it deleted and that are still in core and unchanged. The new batch carries the original creation time, so it stays in the original emit run. Until it's accepted, the re-run beliefs have no label and follow today's core rule, including the ones the batch had labeled C, and the command's output says so. When every belief is kept, the new batch would derive the original's id, so the command reopens the original batch instead, and the self-check checks it as usual. When some beliefs drop out, the smaller batch is left out of the self-check: it isn't checked when accepted, and it isn't a sibling for the run's other batches, because it isn't comparable with its full-size siblings, and the operator ruled it out on 2026-10-05. A subset re-run is recognized as a batch whose content hashes are a strict subset of another batch's in the same run, so no new column is needed and the store-open statement counts are unchanged. It prints the batch like `--emit` does, and supports `--out` and `--json`. It exits 1 and writes nothing for an unknown batch, one never accepted, one from an earlier classifier version, or a batch that owns no labels any more, and exits 2 when combined with `--emit` or `--limit`.

  The graph report of `aelf doctor`, and `aelf health`, now include a `core admission gate` block with the same counts as `aelf doctor core-gate`, and `aelf health --json` adds them under a `core_gate` key. The counts never change the exit code. Counting them walks every belief, and no read the graph report already makes carries what the core rule needs. On one machine, on a synthetic 20,000-belief store, the walk took 0.24 seconds, and `aelf health` took 0.51 seconds instead of 0.25.

### Fixed

- **A statement locked in both scopes is reported, not hidden ([#1947](https://github.com/robotrocketscience/aelfrice/issues/1947)).** Locking one statement with and without `--user` gives two copies, usually under one id, and the repository copy is injected in place of the user copy. Before this fix, nothing said so, and unlocking one copy left the other in force. `aelf lock` now checks the other scope by id and by the near-duplicate test the injection merge applies, and prints a warning that names up to three ids and the `aelf unlock` commands that remove them. `aelf locked` tags both rows `[also locked in the other scope]`, prints the two unlock commands on stderr, and its `--json` rows carry `in_both_scopes`. `aelf unlock` and `aelf unlock --user` say on stderr when the other scope still locks the statement. The checks read the other store read-only and never create it; when it can't be read, `aelf lock` prints one stderr line and the lock still succeeds. The read-only lock reader that `aelf doctor` shares with these checks now percent-encodes the store path, so a `#` or `?` in it no longer creates an empty file at the path's prefix.

### Fixed

- **A statement locked in both scopes is reported, not hidden ([#1947](https://github.com/robotrocketscience/aelfrice/issues/1947)).** A lock's id is derived from its text, so locking one statement with and without `--user` gives one id in two stores, and the repository copy is injected in place of the user copy. Before this fix, nothing said so, and unlocking one copy left the other in force. `aelf lock` now checks the other scope for the same id or a near-duplicate, by the test the injection merge applies, and prints a warning with the `aelf unlock` command that removes the other copy. `aelf locked` tags both rows `[also locked in the other scope]`, prints the two unlock commands on stderr, and its `--json` rows carry `in_both_scopes`. `aelf unlock` and `aelf unlock --user` say on stderr when the other scope still holds the id. The checks read the other store read-only and never create it; when it can't be read, `aelf lock` prints one stderr line and the lock still succeeds.

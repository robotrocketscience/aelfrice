### Fixed

- **An SDK mismatch in the LLM classifier stops with an error, and other classifier failures print a warning ([#1846](https://github.com/robotrocketscience/aelfrice/issues/1846)).** `aelf onboard` and `aelf doctor --classify-orphans` treated every exception from the SDK call as a transient fault, so a `TypeError` from an SDK that no longer takes a keyword the classifier sends looked like a network error. Onboard fell back to the regex classifier with exit 0 and no message saying the model was never called. Both commands now exit 1 without inserting or updating a belief, as they do for an auth failure, when the call doesn't fit the installed SDK: a `TypeError` or `AttributeError` before the request is built, or a keyword the SDK doesn't take. A failed SDK import behaves as before: `--llm-classify` and `aelf doctor --classify-orphans` exit 1 and say the `[onboard-llm]` extra is required, and a default `aelf onboard` uses the regex classifier. Network faults and rate limits still fall back with no message. These still fall back and exit 0, and now print one warning on stderr: a 400, 404, 413, or 422 response, with the status, the error type, and what to check, and never the response's text; a malformed or undecodable response; and a proxy, URL, or key setting that stops the classifier from running, by exception class only. On `aelf doctor --classify-orphans`, which has no regex path, a fallback skips every orphan. If you see the SDK error, reinstall the `[onboard-llm]` extra, or pass `--llm-classify=false` to `aelf onboard` to use the regex classifier. The `requests` value in the telemetry line now counts only requests that were sent, so a refused connection prints `requests=0`.

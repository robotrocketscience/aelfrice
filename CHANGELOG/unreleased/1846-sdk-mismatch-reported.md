### Fixed

- **An SDK mismatch in the LLM classifier stops with an error ([#1846](https://github.com/robotrocketscience/aelfrice/issues/1846)).** `aelf onboard` and `aelf doctor --classify-orphans` treated every exception from the SDK call as a transient fault, so a `TypeError` from an SDK that no longer takes a keyword the classifier sends looked like a network error. Onboard fell back to the regex classifier with exit 0 and no message saying the model was never called. Both commands now print the exception and exit 1 without inserting or updating a belief, as they do for an auth failure. Network faults and rate limits still fall back. A 400, 404, 413, or 422 response also still falls back and exits 0, and it now prints one warning on stderr with the status and the error. On `aelf doctor --classify-orphans`, which has no regex path, that warning comes with every orphan skipped. If you see the SDK error, reinstall the `[onboard-llm]` extra, or pass `--llm-classify=false` to `aelf onboard` to use the regex classifier. The `requests` value in the telemetry line now counts only requests that were sent, so a refused connection prints `requests=0`.

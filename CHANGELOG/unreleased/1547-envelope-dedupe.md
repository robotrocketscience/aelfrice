### Fixed

- **A belief shown in the session-start sub-block is no longer shown again below it in the same envelope ([#1547](https://github.com/robotrocketscience/aelfrice/issues/1547)).** `_format_hits_with_session_start` builds one `<aelfrice-memory>` envelope out of two halves — the embedded session-start sub-block, with its `<locked>` and `<core>` sections, and the per-turn retrieval hits — and nothing stopped the same belief appearing in both. Measured over 1,127 live `UserPromptSubmit` rows: **1,589 redundant `<belief>` elements**, **164 of 1,124 rows (14.6%)** carrying at least one, and the pairings concentrated in `<core>` against a per-turn hit (829) and `<locked>` against a per-turn hit (740), with 13 more against `<retrieved-beliefs>` and 2 appearing three times. The duplicate copies were **729,527 of 17,179,106 characters, 4.25%** of everything those rows emitted. The sub-block's own ids now count as already rendered for the hits below them, so a repeat renders through the existing `_renders_as_manifest` path as a `seen <id>: "<topic>"` pointer rather than a second full copy. No new file, no lock, no flag, no turn key: both halves are written by one call from one frame, so the ids are simply read off the block that is already in hand. **This recovers bytes, not budget** — the pack loop has spent its budget before anything renders, so the freed space admits no further belief; the envelope gets shorter and the tail does not grow. The id scan deliberately matches `id="[^"]+"` rather than a hex class, because live stores carry two id forms — 16-character hex and 26-character ULID — and a hex-only pattern silently skips the ULIDs, which sit on the largest elements in the corpus; four independent readers of this code made exactly that mistake before the comment at the pattern existed, and `test_a_ulid_id_dedupes_too` is the guard. `tests/test_envelope_dedupe_1547.py` holds fourteen tests, and the one that matters most is the neutrality contract: a store whose sub-block shares no id with its hits emits a **byte-identical** block, which is what stops this being a cut rather than a de-duplication. Four mutations were run and all four go red: removing the union (8 failed), narrowing the pattern to hex (4 failed), replacing the union with an assignment so the [#1382](https://github.com/robotrocketscience/aelfrice/issues/1382) ledger set is discarded (1 failed), and dropping the duplicate silently instead of leaving a pointer (5 failed). The tree was verified clean after each revert.

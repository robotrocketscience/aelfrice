### Fixed

- **The commit hook reads only a lowercase relation on one line ([#1874](https://github.com/robotrocketscience/aelfrice/issues/1874)).** The hook ignored case in the verb, so an uppercase edge-type name used as a noun, such as "the SUPERSEDES writer", wrote a false edge. Its matches also crossed line breaks, so a commit's subject and body could join into one belief. The verb now has to match in lowercase, so "SUPERSEDES" and "Supersedes" no longer count. Each match stays on one line of the message. A phrase that wraps to the next line is cut at the line break, and a relation is lost when the break touches the verb. A match with a side that's only function words, such as "the", "this", "it", "which", or "all", now stores nothing, so "This supersedes the old parser" and "the new parser supersedes that" write no belief or edge. Those phrases had one belief id across all commits, so they collected edges from unrelated commits. The words stored from a match can still fail to form a complete phrase, such as "the old". Beliefs and edges already in your store don't change: their log rows hold the stored phrases, so they replay as they were written, and `aelf doctor` doesn't report them as out of date. The comment in the `post-commit` block now says the hook stores the words on each side of a phrase, not the commit's message, and `aelf setup` updates it the next time it runs in a repository. Retrieval's query building and the entity index don't change.

### Documentation

- **The read-only routing criterion says what it can truthfully assert ([#1571](https://github.com/robotrocketscience/aelfrice/issues/1571)).** [#1416](https://github.com/robotrocketscience/aelfrice/issues/1416)'s expanded matrix asked that a routed read command perform no preliminary writable open *and* emit no failed-write warning. Those two halves are in tension, and nothing in the code was wrong. On a store whose directory is frozen but whose write-ahead log sidecars are live, the writable open **succeeds**, so `open_store_for_read()` never reaches its `mode=ro` fallback, `aelf search` goes on to attempt its `.bm25f` sidecar write, and that write fails with a non-fatal warning. Both halves are unsatisfiable together while the writable-first order stands — and that order stands by the 2026-08-09 ruling, because preferring `mode=ro` unconditionally imposes degraded semantics (no migration, no expired-lock sweep) on every user whose store is perfectly writable. The criterion is therefore narrowed to the `mode=ro` fallback handle, where it holds, and the reasoning lands at `open_store_for_read()` rather than in a closed issue, so the next reader meets it at the code. Making the sidecar write conditional on directory writability was considered and declined: it silences an accurate message — a write genuinely was attempted and genuinely failed — at the cost of a writability probe on a hot path that nobody has measured. Whether a frozen directory with live sidecars occurs in the field is unrecorded, and does not matter here, because the chosen disposition changes no design.

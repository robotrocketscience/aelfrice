### Fixed

- **`aelf locked` and `aelf unlock --user` report a user lock store they can't check as unreadable, not as missing ([#1772](https://github.com/robotrocketscience/aelfrice/issues/1772)).** When the user store's directory denied search permission, the presence check used `Path.is_file()`. On Python 3.14 that returns False, so `aelf locked` listed no user locks with no warning and `aelf unlock --user` said there was no user lock store. On Python 3.12 and 3.13 it raises `PermissionError`, and `aelf unlock --user` exited with a traceback. The check now stats the path: only a missing file, or a parent that is a file, counts as absent, so a directory or other non-file at the user store path now reads as unreadable instead of missing. `aelf locked` prints its "cannot read the user lock store" warning and lists the repository locks, and `aelf unlock --user` prints one line and exits 1.

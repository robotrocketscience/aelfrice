### Added

- **`scripts/repair_onboard_dates.py` re-dates a collapsed onboard session and rebuilds its temporal spine ([#1609](https://github.com/robotrocketscience/aelfrice/issues/1609), [#1611](https://github.com/robotrocketscience/aelfrice/issues/1611), [#1612](https://github.com/robotrocketscience/aelfrice/issues/1612)).** The onboard handshake can stamp every belief accepted in one `accept_classifications` call with that call's single wall-clock timestamp instead of each belief's real content date (#1609): `derivation_worker.py` sets `created_at=inp.ts` for every derived belief, so a whole session collapses onto one `created_at` and its `TEMPORAL_NEXT` spine encodes scan order rather than chronology. This one CLI tool replaces four one-off scripts with a single, tested repair path. Without `--session` it auto-detects an affected session — every belief sharing one `created_at`, with `ingest_log` sources shaped like scanner output — then re-dates each belief from `ingest_log.source_path`: a `git:commit:<sha>` source takes that commit's own author date, and a file source takes the path's most recent commit, falling back to a per-path `git log -1 -- <path>` for a file that entered history only through a merge (#1612), which a repo-wide `git log --name-only` without `-m` never lists. Every date is normalized to fixed-width UTC before it is written back (#1611), because `backfill_temporal_spine` orders a session by the raw `created_at` string and mixed local offsets otherwise sort out of real-time order even when each date is individually correct. `--dry-run` (the default) runs the exact same write path against a throwaway scratch copy of the database, so its report is exact rather than estimated; `--apply` writes for real, optionally after `--backup PATH` copies the database first. `--check` runs a read-only pass over `TEMPORAL_NEXT` edges and exits non-zero if any successor predates its predecessor in real time. Every write goes through `MemoryStore.update_belief`, `MemoryStore.delete_edge`, and `backfill_temporal_spine` — never raw SQL. `tests/test_repair_onboard_dates.py` reproduces the collapse with the real handshake against a scratch git repository whose commits carry mixed UTC offsets chosen so that raw ISO-8601 text order disagrees with real time order, and checks that the repair dates every belief correctly, rebuilds a spine that passes `--check`, and is idempotent under a second `--apply`.

### Removed

- **The store drops the unused `hibernation_score` and `activation_condition` columns from `beliefs` ([#1658](https://github.com/robotrocketscience/aelfrice/issues/1658)).** The two columns were the storage half of a hibernation lifecycle (v2.0, #196) that was never built: no code path wrote a non-NULL value, and measurement later found that a cold-decay sink does not help this workload. The first open after you upgrade runs two `ALTER TABLE beliefs DROP COLUMN` migrations, the same shape as the `demotion_pressure` drop in #814. Each drop rewrites the `beliefs` table, which took under 0.1 s per column on a copy of a 101 MB store. The `Belief` dataclass loses both fields, `aelf doctor --replay` stops comparing them, and the design memo moves to `docs/design/historical/hibernation_lifecycle.md`. **Upgrade note:** stop any `aelf` command that is still running an older version before the first open by the new version. A process running older code that already has the store open fails on its next belief read or write after the drop: a read raises `IndexError: No item with that key`, an update raises `no such column: hibernation_score`, and an insert raises `table beliefs has no column named hibernation_score`. Hooks open and close the store on each fire, so the exposure is a command that holds the store for its whole run, such as `aelf onboard` during a scan, or your own script that keeps a `MemoryStore` open. An older version that opens the store after the drop re-adds both columns as NULL and works. If two versions alternate on one store, for example an installed hook and a development checkout, each switch rewrites `beliefs` again, and the same failure applies to any process of the other version that is open at that moment. The #814 `demotion_pressure` drop had the same failure for a running process.

## [Unreleased]

## [5.0.0] - 2026-09-18

The major bump is for three removals, not for a redesign: `src/aelfrice/uri_baki.py`
leaves the shipped package, `hook.DEFAULT_SESSION_START_TOKEN_BUDGET` and the
`token_budget` parameter of `hook.session_start()` are deleted, and the unwired
posterior-decay surface is deleted with every documentation statement that rested on it.
Each was provably unreachable — no module in the package ever imported `uri_baki`, the
deleted budget could not bind on the lane it governed at any value, and nothing had ever
moved a stored posterior toward a prior — so no working configuration changes behaviour
here. The version reflects that the package surface shrank, which is what semantic
versioning asks it to reflect.

**The theme of this release is measuring what the project had been asserting.** Several
long-standing claims turned out to be false when someone finally derived them, and the
fixes are mostly the instruments that make the claim checkable rather than the claim
restated. A published figure now names the script that re-derives it and CI runs that
script ([#1469](https://github.com/robotrocketscience/aelfrice/issues/1469)); the gate
enforcing it was itself blind to most of the corpus until a real block scanner replaced a
backtick-pairing regex ([#1556](https://github.com/robotrocketscience/aelfrice/issues/1556));
`pyright` is enforced and the four documents claiming it already passed are corrected
([#1503](https://github.com/robotrocketscience/aelfrice/issues/1503)); and seven
user-facing documentation statements that disagreed with the code are fixed
([#1511](https://github.com/robotrocketscience/aelfrice/issues/1511)).

**The injection path is the other half.** The seven injection lanes now charge the line
their own renderer emits rather than a compressed form no renderer produces
([#1526](https://github.com/robotrocketscience/aelfrice/issues/1526)), the injected block
is bounded again with user locks exempt from the bound
([#1551](https://github.com/robotrocketscience/aelfrice/issues/1551)), a belief shown in
the session-start sub-block is no longer shown a second time in the same envelope
([#1547](https://github.com/robotrocketscience/aelfrice/issues/1547)), and a
cadence-resume recap no longer sheds the prompt's own retrieval hits to keep a synthesis
of an earlier session ([#1564](https://github.com/robotrocketscience/aelfrice/issues/1564)).
**No budget constant moved.** The re-tune those corrections were expected to enable is
gated on an answer-quality instrument, and the census built to price that instrument
reports the effect is not measurable against any corpus this repository can reach
([#1546](https://github.com/robotrocketscience/aelfrice/issues/1546)).

Store safety gained two fixes worth calling out for anyone running against a repository
they cannot write: a `#` or `?` anywhere in the store path used to make the read-only open
read *a different database* and create it, then report that a current store needed a
migration ([#1416](https://github.com/robotrocketscience/aelfrice/issues/1416)).

### Added

- **An opt-in turn-differential for the injected memory block ([#1382](https://github.com/robotrocketscience/aelfrice/issues/1382)).** With `AELFRICE_TURN_DIFFERENTIAL=1`, a belief already injected verbatim in this session is re-injected as a one-line `seen <id>: "<topic>"` entry in the locks manifest instead of the identical `<belief>` element, because the full text is already above in the same context window. **Default-off**, ratified 2026-08-19, reversing the 2026-08-11 default-on ruling — that ruling rested on the failure direction being one-way, and adversarial review of the implementing PR showed it was not. `begin_epoch` sat inside a `if body:` guard, so a store with no locked beliefs rendered an empty SessionStart baseline, never opened an epoch, and left the pre-compaction ledger live under the same `session_id`; every later turn then emitted `seen <id>` for text the window no longer held, reducing that belief to an 80-character stub for the rest of the session. Fixed three ways: the epoch reset is unconditional, `PreCompact` resets too (it is the event actually guaranteed to precede compaction, and it fires whatever the rebuilder's `trigger_mode` is), and a boundary carrying no `session_id` now deletes the ledger rather than returning early and leaving it live. The second reason for default-off is that the saving can be negative: a `seen` entry opens the `<aelfrice-locks-manifest>` wrapper on a block that had none, a fixed ~237 characters, so a single-belief block must exceed ~310 characters of content before the change saves anything — against a recorded median content length of 86. Small blocks of short beliefs get bigger; large or long blocks get much smaller. No aggregate percentage is published, because nothing in the tree re-derives one. Writes are gated on `emit_memory_block` ([#1359](https://github.com/robotrocketscience/aelfrice/issues/1359)): a suppressed fire put nothing in the window, so recording it would reference content the model never saw.
- **`scripts/check_doc_preservation.py` makes a documentation rewrite reviewable ([#1509](https://github.com/robotrocketscience/aelfrice/issues/1509)).** A style conversion is a large diff with no behaviour change, which is the shape a reviewer skims, and the failure it hides is a lost fact: a figure rounded, a citation dropped out of a shortened sentence, a table row lost in a reflow. None of those break a build. The script compares a file against its pre-rewrite form and fails on any lost number, URL, code block, inline code span, table row, section or front-matter key, and on an in-document anchor that a rewording orphaned. It is one-directional by design — adding a subheading is a legitimate conversion move, dropping one is not — and it never reports prose differences, because prose changing is the point. Heading *wording* is deliberately not compared: removing idiom from a heading is required by the style, so a checker that flagged it would forbid the conversion it verifies. `tests/test_check_doc_preservation.py` is a mutation suite: a faithful conversion must pass, and dropping a figure, rounding one, dropping a citation, renaming an identifier, editing a code block, dropping a table row, dropping a section, renaming the title and orphaning an anchor must each fail. The known gap is pinned rather than left to be discovered — numbers compare as a multiset, so a rewrite that swaps two figures between sentences passes, and `test_a_swapped_pair_of_numbers_is_not_detected` fails loudly if that ever changes.
- **`benchmarks/scored_query_census.py` makes the #1516 population gate re-runnable ([#1516](https://github.com/robotrocketscience/aelfrice/issues/1516)).** #1516 parked a re-measurement of #1348's top-10 movement behind a threshold committed before any measurement was taken — run it when `input.scored_query` holds **>= 500 distinct queries spanning >= 30 days** — and the only way to decide that was a hand-written scan that went stale between askings. The census scans every `rebuild_logs/*.jsonl` reachable from a root and reports the six numbers the bound needs kept apart: rows scanned, rows carrying `input.scored_query`, **distinct** scored queries, days with at least one, the calendar span, and a per-day breakdown of rows against distinct. Both halves of the bound have a cheaper neighbour that would pass the gate early — row count is not distinct queries, and active days are not a calendar span — so `tests/test_scored_query_census_1516.py` feeds synthetic rows in which those numbers deliberately differ and pins each separately. The two bounds are module constants with **no CLI flag**, because a flag lets a re-run lower the bar it is checking and still look like the same census; a test asserts the flags do not exist. Exit codes separate "could not census" (2) from "censused, a bound is unmet, do not measure" (3). The logs are repo-local — `<git-common-dir>/aelfrice/rebuild_logs/` per repo, plus `~/.aelfrice/rebuild_logs` for work outside any work-tree — so `--discover` finds both layouts; a census that knew only about `~/.aelfrice` would report a near-empty population. Rows are read through `rebuild_log_query_population.load_rows` so the two censuses cannot drift on what counts as a parseable row, and nothing here opens a `MemoryStore`, since opening one runs pending migrations. Both flags are repeatable, so directories are resolved before they are de-duplicated: one directory named twice is read once, rather than doubling every row count under a corpus identity that still reports one file. A query's identity is its stripped form, the same form blankness is judged on, so whitespace cannot split one query into several and inflate the number the 500-query bound is checked against.
- **`aelf show <belief-id>` reads one belief back by id ([#1553](https://github.com/robotrocketscience/aelfrice/issues/1553)).** Every injected `<belief>` element carries an id, and nothing turned that id back into the belief's full text. None of the existing surfaces was a substitute: `aelf search` is FTS5 over *content*, so an id matches on whatever it happens to tokenize into and is neither guaranteed to come back nor to come back first; `aelf graph` is anchored by id but returns edges and neighbours; `locked`, `core` and `speculative` are tier listings, not lookups. The `show` that existed was `category show`, and it shows a category. The command prints the content in full plus the origin, lock level, retention class, posterior, created and valid-to timestamps, and scope — one field per line in a fixed order, with the content last and unindented so a multi-line body stays unambiguous to read and to parse.

  Addressing, not search. The new `MemoryStore.find_beliefs_by_id_prefix` is the first prefix lookup over `beliefs.id` in the store — `delete`, `retire`, `unlock` and `context` all demand the exact id — and it returns the whole matching set rather than the first row, so the caller names the ambiguity instead of guessing: two candidates exit 1 with both ids on stderr and nothing on stdout. An exact id wins outright over being a prefix of a longer one, so a short id still addresses itself. The prefix arm is `substr(id, 1, ?) = ?` rather than the index-friendlier `LIKE prefix || '%'`, because a `%` or `_` in a pasted id would otherwise silently become a wildcard — turning the exact lookup the command exists to provide back into the search it is meant to replace.

  Tombstones are included, unlike `get_belief`, whose lifecycle filter (#1210) hides them: the id in an injected block from last week may well name a retired belief, so `show` reaches it and labels it `status: retired`. A missing id is distinguishable from a belief whose content is empty — the first prints `no belief with id` on stderr and exits 1, the second prints its field block with an empty body and exits 0.

  The store opens through `open_store_for_read()`, making `show` the fifth command routed to the #1416 path and the first added since that ruling — a per-command decision with the audit that ruling asks for, not the blanket change it refused. What the routing buys is stated exactly: the command changes no belief, and it reads a store the caller cannot write. It does **not** make the command write-free. `open_store_for_read` attempts the ordinary writable open first and falls back to `mode=ro` only on a permission failure, so against a writable store `show` still pays the full store open (DDL, migrations, the scope-id mint, the expired-lock sweep) to print one row. That cost is real and unaddressed here; it is re-filed as its own issue over every read-only verb rather than settled inside this command. The audit's one finding is that on the *fallback* handle no expired-lock sweep has run (#1314), so a lock past its `lock_expires_at` still prints `lock: user` there — the same staleness `aelf locked` already carries on that path, on a command that reports a stored field rather than acting on it. The routing is proved behaviourally rather than by a call-site grep: against a directory at mode 555 whose schema is one table short, a writable open dies in `MemoryStore.__init__` before the belief is read, and the test asserts `show` exits 0 and leaves the database byte-identical.

  Whether an injected `<belief>` should now advertise `aelf show` is deliberately not settled here. #1547 shipped its byte reduction without a pointer, on the ruling that naming a command the CLI does not implement is worse than shipping no pointer; the command now exists, and pointing at it is a separate decision.

### Changed

- **The transcript-admission harness reports the rescued set split by kind ([#1490](https://github.com/robotrocketscience/aelfrice/issues/1490)).** `rescued_distinct` said how many sentences the relaxed filter admits and nothing about what kind of thing they were, and the kinds behave very differently once stored: a durable policy statement earns its slot, while an ephemeral session-status line ("No failures yet.") is true of one run and of nothing afterwards — yet both enter through `derive()`'s `role=user` transcript path at the undeflated `USER_SOURCE` prior ([#888](https://github.com/robotrocketscience/aelfrice/issues/888)), storing as `factual`/`user_transcript` at `alpha=3.0, beta=1.0` (posterior mean 0.75, origin rank 3), so they compete with durable policy for the same injection slots. `benchmarks/transcript_noise_admission.py` now buckets into `ephemeral_status`, `operator_directive`, `durable_policy` and `unclassified`. Nothing reaches the ingest write path. A shape detector *would* have reached it, and that option was rejected twice — on 2026-08-11 and again on 2026-08-12 — as "the same widening #1371 §1 just narrowed". A wrong bucket therefore produces a wrong number in a manually-run report, and never a dropped belief. `unclassified` is the deliverable rather than a leftover — CI can never watch these counts, because the corpus is an untracked local archive, so a rise there is the only available signal that the closed set of three has stopped describing what the filter admits. `tests/test_transcript_noise_buckets_1490.py` pins that the split is total (a sentence matching no rule is counted, not dropped), that every declared bucket is reachable (a dead bucket is a permanent zero column that reads as a measurement), and that an unseen shape reaches `unclassified` instead of being absorbed. The disclosure comment in `src/aelfrice/noise_filter.py` is stamped with **both** figures and is explicit that the finding is no longer reproducible: the measurement of record is 6 distinct / 9 rows over 17,628 sentences at `corpus_sha256 3ad68670…` (tree `c6f0c0c3`, 2026-08-12), and a re-run on 2026-08-19 yields 0 / 0 over 18 sentences at `corpus_sha256 cffcf557…` because the transcript archive was removed from disk around 2026-08-13 — not by rotation, since `transcript_logger` contains no pruning code. Quoting only the fresh run would report a degenerate corpus as the finding; quoting only the old one would imply it is still checkable.
- **The H1 directive gate is a tripwire, so the bench tier is no longer red by design ([#1502](https://github.com/robotrocketscience/aelfrice/issues/1502)).** `test_directive_detection_gate` asserted `precision >= 0.80`, but that bar is the *reopening* criterion for work `docs/design/v2_enforcement.md` § H1 documents as deferred — so red was its correct, permanent, shipped state. It could never go green, and it held the whole bench-gate tier red at every release cut, in the tier that [#1477](https://github.com/robotrocketscience/aelfrice/issues/1477) made the project's only scheduled quality signal. A check that can never be green cannot be distinguished from a broken one, and it teaches a reader to skip the reds beside it. Inverted as `test_h1_reentry_bar_is_still_unmet`: green while the bar is unmet, and it fires when `detect_directive` clears both bars — the event that actually reopens [#374](https://github.com/robotrocketscience/aelfrice/issues/374). The assertion is the conjunction of precision and recall, because that is how § H1 states the criterion, and the failure text says to reopen the issue rather than adjust the test. It also stamps the corpus digest, computed rather than pinned, because the corpus is now a union of v0.1 and v0.2 and the two score differently. Its companion `test_directive_corpus_defeats_a_first_token_baseline` goes **green** in the same change, once the v0.2 minimal-pair corpus is present: the one-token baseline clears the bar on 0 of 200 salted partitions against the union, where it cleared 196 of 200 against v0.1 alone. Latest measurement on the 510-row union: precision 0.665, recall 0.636 — H1 stays deferred, now on a number that means what § H1 intends.
- **The public documentation follows the Google developer documentation style guide.** Twenty-three files — `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `docs/README.md`, everything under `docs/user/` and `docs/concepts/`, and the four index `README.md` files — are written to [Google's style guide](https://developers.google.com/style): second person, present tense, active voice, sentence-case headings, the condition stated before the instruction, serial commas, US spelling, descriptive link text, and the guide's [word list](https://developers.google.com/style/word-list). Table cells were converted as well as paragraphs, 236 of 390 rows, the remainder being data cells that hold a flag, a default, a type, a path, or a version. British spellings outside code fall from 92 to 9, and those 9 are `analysis` and its inflections, which is already US spelling, plus one verbatim quote of a shipped CLI string. Records stay out of scope, because rewriting one changes what it says happened: `CHANGELOG/`, `docs/audits/` bodies, `docs/design/historical/`, and the numbered ADRs. `CODE_OF_CONDUCT.md` stays out too, as adopted normative text attributed to the Contributor Covenant. No fact changes: every numeric literal, URL, link target, fenced code block, inline code span, table row and section that appears in the pre-conversion file still appears, verified per file by `scripts/check_doc_preservation.py`. The one deliberate exception is `CONTRIBUTING.md`, whose `Documentation style` section now names this guide and so no longer carries the two sentence-length limits it used to state; that is a content change rather than a conversion, and the checker reports it rather than being loosened to permit it.

### Removed

- **The unwired posterior-decay surface, and every doc statement resting on it ([#1369](https://github.com/robotrocketscience/aelfrice/issues/1369), discharging [#1162](https://github.com/robotrocketscience/aelfrice/issues/1162) §4).** `src/aelfrice/scoring.py` defined a Jeffreys-targeted `(alpha, beta)` ager, a type half-life lookup and a four-entry half-life table. No module under `src/` ever imported or reached any of the three — `tests/test_docs_posterior_decay_1218.py` had asserted that fact by parsing the tree since [#1218](https://github.com/robotrocketscience/aelfrice/issues/1218) — so nothing has ever moved a stored posterior toward a prior, and the lock short-circuit inside the ager exempted locks from a mechanism that did not run. [#1162](https://github.com/robotrocketscience/aelfrice/issues/1162)'s acceptance criterion is wire-it-or-delete-it and the operator authorized deletion on 2026-08-05; wiring it needs a calibration bench that is not funded. Three private constants went with it (`_HOUR`, `_PRIOR_ALPHA`, `_PRIOR_BETA`) and so did the `LOCK_USER` import, which the short-circuit was the only reader of. The two pre-registered property tests written against the function — decay-required and lock-floor sharpness — are retired rather than rewritten: both exercised the function rather than the pipeline, which is exactly why decay-required passed while the property it protected was violated in the shipping product. The [#1218](https://github.com/robotrocketscience/aelfrice/issues/1218) guard is rewritten instead of deleted, and it now fails if the surface comes back, so the prose is revisited rather than going stale in the other direction. The documentation statements that rested on it are corrected, not just the two the issue named: `ARCHITECTURE.md` principle 5, its `scoring.py` module row, its property-test row and its claim that decay penalizes candidates from old branches; `PHILOSOPHY.md`'s "Locks, not just decay" section and its deferred-feedback paragraph; `COMMANDS.md`'s defaults table, which advertised the decay target and the four half-lives as tunable constants; `LIMITATIONS.md`'s "a belief whose evidence decayed fully"; `bayesian_ranking.md`'s numerical-safety argument, which derived a bound from the ager; `ROADMAP.md`'s "v1 ships per-belief decay"; the three "a lock short-circuits decay" lines in `README.md`, `QUICKSTART.md` and `INSTALL.md`, which promised an exemption from nothing; and the entry in `docs/design/historical/substrate_decision.md`'s single-axis consumer audit, struck in place rather than deleted, on the pattern `docs/design/historical/README.md` already uses for `RetrievalCache` after [#1418](https://github.com/robotrocketscience/aelfrice/issues/1418). Two mechanisms keep the word *decay* and neither touches a stored posterior: `retrieval._apply_temporal_decay` discounts a ranking score behind the default-off `temporal_sort`, and `meta_beliefs.decay_toward_default` ages a meta-belief toward its configured default. The rewritten guard pins both by name, because the corrected prose now cites them.
- **The `uri_baki` post-rank adjusters leave the shipped package ([#1369](https://github.com/robotrocketscience/aelfrice/issues/1369), under [#1162](https://github.com/robotrocketscience/aelfrice/issues/1162)).** `src/aelfrice/uri_baki.py` held three pure-function score adjusters — `apply_locked_floor`, `apply_supersession_demote`, `apply_recency_decay` — and no module in the package has ever imported it: `grep -rn 'aelfrice\.uri_baki\|aelfrice/uri_baki' src/` returned two comments pointing at it and nothing else, and the only importers were `benchmarks/uri_baki_retest/harness.py` and `tests/test_uri_baki.py`. The module is now `benchmarks/uri_baki_retest/adjusters.py`, beside the retest that is issue [#153](https://github.com/robotrocketscience/aelfrice/issues/153)'s actual deliverable. It moves rather than being deleted because `benchmarks/uri_baki_retest/RESULTS.md` publishes NDCG figures this code produces, and deleting the producer would leave those numbers unreproducible; the retest returned an honest negative and the approach is filed as not-adopted there. The two comments that pointed at the old path now name the new one, and `retrieval._supersession_penalty` keeps its warning that the multiplicative primitive is wrong for a log-domain score — the point that comment exists to make survives the move, because the primitive still exists to be misread. The `src/aelfrice/` file count in `docs/concepts/ARCHITECTURE.md` is derived by `tests/test_docs_truth_1511.py`, so it tracks the tree rather than drifting.
- **`hook.DEFAULT_SESSION_START_TOKEN_BUDGET` and the `token_budget` parameter of `hook.session_start()` are deleted; the SessionStart block is bounded by the lock count ([#1546](https://github.com/robotrocketscience/aelfrice/issues/1546)).** The constant could not bind on the lane it governed, at any value. `session_start` retrieves through `_retrieve_baseline_with_block`, which calls `retrieve()` with an **empty query**, and in `retrieve_with_tiers` every relevance lane — L2.5, L1, HRR expansion, the temporal spine and the BFS hop — is gated on `query.strip()`. Only L0 contributes, and L0 is appended unconditionally and never trimmed ([#379](https://github.com/robotrocketscience/aelfrice/issues/379)), so the pack loop a budget drives is never entered. Reproduced before the deletion on a 300-lock store of 150-character beliefs: 300 hits and 61,144 rendered bytes at `token_budget=1`, at 1500 and at 100000 alike. **The knob the deletion exposes is the TOML key, not the environment variable.** `resolve_token_budget`'s precedence is environment variable, then the explicit keyword argument, then `[retrieval] token_budget` in `.aelfrice.toml`, then the default, so `AELFRICE_RETRIEVAL_TOKEN_BUDGET` already outranked the budget this caller passed and already reached the lane: `resolve_token_budget(1500, start=<dir>)` returns 111 with that variable set to `111`. What is new is the TOML key, which the explicit argument used to shadow — with `[retrieval] token_budget = 77` on disk, the same call returns 1500 in the pre-deletion shape (`explicit=1500`) and 77 in the post-deletion one (`explicit=None`). Both are inert here, because the pack loop is never entered: the guard below drives the production call under four environment values, under `[retrieval] token_budget = 1`, and under neither, and gets the store's whole lock set and one block length from all six arms, on a 10-lock store and on a 300-lock one alike. The bound that remains is the one [#379](https://github.com/robotrocketscience/aelfrice/issues/379) states: every locked belief is injected, and the lock count is the operator's knob.

  The guard is kept and re-aimed. `tests/test_render_cost_1526.py::test_session_start_lane_never_trims_its_l0_pool` (renamed from `test_session_start_budget_does_not_bind_on_its_own_lane`) asserts the [#379](https://github.com/robotrocketscience/aelfrice/issues/379) contract directly rather than asserting a now-deleted constant: it drives the real `_retrieve_baseline_with_block` at the production call shape, varies the budget across four orders of magnitude through the environment variable, once through `[retrieval] token_budget` and once through neither, and requires every belief from `list_locked_beliefs()` in both the hit list and the rendered block each time — by content in the block, not by id, because the id sits in the `<belief id="…"` attribute ahead of the content and a per-line cap would leave every id in place while truncating every lock. The fixture's locks run past every per-belief character cap the two injection modules ship, and the test discovers that set by name shape and asserts the lock length above its maximum rather than above one named constant. Sizing it against one constant is what the first version of this guard got wrong: it was built against `hook_search_tool.PER_LINE_CHAR_CAP = 200`, the truncation already shipped on the `Grep|Glob` lane, while `hook` — the module that renders this very block — ships `STOP_PROMPT_MAX_CONTENT = 1000` for the identical reason. Truncating every lock at 1,000 characters in `_format_baseline_hits` left the whole suite green. A maximum over a discovered set rises on its own when the next cap lands **under one of the name shapes the discovery matches** (`CHAR_CAP`, `MAX_CONTENT`, `_CHARS`); a cap named otherwise is not found, the floor does not rise, and a trim at it above the fixture's padding would pass. The two known caps are also required by name, so a rename fails loudly instead of shrinking the set — but discovery is a name convention rather than a proof, and the entry says so rather than letting "rises on its own" read as unconditional. The TOML arm asserts its own resolution before it measures, so a config file the resolver never discovers fails instead of agreeing with the other arms for the wrong reason. The assertion is absolute rather than an identity across arms, because a trim that does not vary with the budget agrees with every arm and still breaks #379; and it runs on two store sizes, because any fixture is blind to a cap above its own lock count. Proved by mutation: `hits = hits[:5]` and a budget-driven pack loop each fail both sizes, `hits = hits[:50]` fails the 300-lock size and is invisible to the 10-lock one, and giving the lane a non-empty query fails the 10-lock size, where 50 candidate slots leave room for the unlocked decoys that the 300 locks would fill. Truncating each rendered belief's content in `_format_baseline_hits` fails both sizes at 200 characters and at the discovered maximum's 1,000 — the mutation an id-presence assert could not see, because every id survives it and the block length stays identical across arms, and the one a fixture sized for 200 could not see either. `benchmarks/injection_budget_bytes.py` keeps measuring the lane, at an explicit `SESSION_START_PROBE_BUDGET` literal of its own with the production path's "passes none" stated beside it, and still reports which cap ended each arm (`token_budget` / `l25_subbudget` / `both` / `pool`) — the `session_start` row reads `pool` for both arms at every content length, which is the evidence for this deletion rather than a restatement of it. Both halves of that legend are guarded on the producer's own stdout, not on the helper that builds it. `tests/test_render_cost_1526.py::test_the_producer_says_the_session_start_number_is_its_own_probe` runs `main(["--curve"])` and reads the printed lines, because the helper has two call sites and reverting only those to the pre-branch f-strings — leaving the helper, its docstring and a helper-level assertion all in place — puts `session_start: budget 1500 unchanged, emitted bytes 1408 -> 1408 (+0.0%) at 92 content chars` back on stdout with the full suite green. `--curve` prints both call sites, both directions are asserted, and every lane must be found in the output or one that stopped printing would pass vacuously. The probe value carries a derived-figure marker on the SessionStart row of the [#1526](https://github.com/robotrocketscience/aelfrice/issues/1526) entry's table, so the `derived-figures` job re-derives it from the module and exits 1 on a mismatch — and `test_the_producer_reads_the_session_start_budget_off_its_own_constant` asserts the wire that marker runs through, by monkeypatching the constant and requiring `shipped_budget("session_start")` to return it. Written back as the literal `1500`, that entry leaves the suite green and the gate at exit 0 while the constant says 3000 and the CHANGELOG publishes 1500: a marker comparing a literal against a literal.

  **A user-facing page promised the budget this deletion removes, and it now says what the bound really is.** `docs/user/PRIVACY.md` listed "a token budget for each query … 1,500 for the UserPromptSubmit hook and the SessionStart hook" under *What aelfrice does not control*, as a mitigation limiting what reaches the cloud model. - **`BASH_FIRE_CAP_PER_TURN` now binds, because its counter moved to a per-session map in the session ring ([#1522](https://github.com/robotrocketscience/aelfrice/issues/1522)).** The declared ceiling of three retrieval-performing Bash searches per turn could not be reached in any deployed configuration. `aelf-search-tool-hook` is registered as a `"type": "command"` hook, so the host spawns one OS process per fire; the counter was a module-level dict, empty at the start of every one of them. The map survives the record reset that a session switch performs, is bounded to `BASH_STATE_MAX_SESSIONS` (8) entries evicted least-recently-touched-first so one file serving a machine's worth of sessions cannot grow without limit, and a turn stamp bumps only the stamping session's `turn_id` — a prompt submitted next door does not re-open this session's budget.

  Both writes that maintain the map — the turn stamp and the fire count — touch the `bash` key alone and write every other key back as it was read, rather than going through the record-reshaping mutator the injection writes use. Through that one they would be worse than the defect they fix: the stamp runs on *every* prompt, so in the shared checkout above each prompt session A submitted would discard session B's dedup ring, `next_fire_idx` and #876 cadence state, and B would then re-inject beliefs it had already injected. `tests/test_search_tool_hook_bash_cap_1522.py::test_a_turn_stamp_leaves_a_co_tenants_ring_record_intact` drives the real `UserPromptSubmit` hook for A against a record owned by B, asserts every field of B's record unchanged, and asserts A's stamp did land — so a stamp that stopped writing at all cannot pass it.

  Writing the `bash` key alone raises the question of what happens when the rest of the record is not there to leave alone, and "is there a record here at all" turned out not to be the same question as "is the record complete". A file holding `{"bash": {}}` — what an aelfrice that had only ever stamped a turn leaves behind, and what a hand edit can leave behind — is a record, so an emptiness check passes it through and the Bash map is written back on top of a record still missing `ring_max` and `evicted_total`. The raw readers of this file do not normalize: `aelf doctor` renders that record as `injection ring: 0/None ids (evicted None this session)`. Both writes now fill in whichever of the record's fields are absent, each with the default a fresh record gets, and pass through every field the record already carries — a co-tenant's `session_id` and ring included, which is the property above. A field that is *present* but of the wrong type is left as it was found, because coercing it would mean rewriting a neighbour's record; every reader that consumes the record for its owner already coerces on read.

  Every ring failure (absent, malformed, unwritable, no record yet, no `session_id` in the payload) degrades to "no cap", never to "cap reached": a hook that suppressed retrieval because it could not read a file would be worse than the unbounded firing this bounds. Two overshoots follow from that direction and are documented in the spec rather than closed: a payload with no `session_id` is uncapped, and the read is lock-free, so Bash calls dispatched in parallel can each see the same count and exceed the cap by that parallel width.

- **The hook audit log records its own truncation, and the zero-hit fire it was silently dropping ([#1528](https://github.com/robotrocketscience/aelfrice/issues/1528)).** `hook_audit.jsonl` is the substrate this project measures itself with — [#1407](https://github.com/robotrocketscience/aelfrice/issues/1407) exists so per-fire outcomes are counted rather than inferred — and two properties of the writer made every rate derived from it narrower and more optimistic than it looked. Both defeated that intent the same way: they made an absence indistinguishable from a measurement.

  **Rotation was destructive and silent.** Rollover is an append-then-`os.replace` into a single slot `hook_audit.jsonl.1`, so the second rollover overwrites the first archive and that history is gone. Nothing in the surviving files said so, and a benchmark reading `hook_audit.jsonl*` could not tell a short history from a truncated one. Retention was deliberately **not** widened — N slots multiply the on-disk cost by N on every repo that has an audit log, and the property the issue asks for is detectability, not retention. Each rollover now stamps one `{"hook": "audit_rotation"}` row as the first line of the freshly emptied live file, carrying that file's generation number, a summary of the file just retired (row count and `ts` range), and the one fact nothing else can reconstruct: how many archives have already been discarded.

  **The answer is three-valued, and the third value is what makes it honest.** `audit_window()` reads the markers back as a generation, a `records` count, a first/last `ts`, and a pair of flags: `truncated` when archives are provably gone, `complete` when nothing was discarded and that is provable, and *neither* when the files cannot settle it. The first rollover is `complete` — it fills an empty slot and destroys nothing, and a warning that fired on every rotated log would be no signal at all. A `.1` carrying no generation stamp is the unknown case, and it is the common one: every log already rotated in the wild predates this marker, so one rollover discarded nothing and a second discarded the first archive, and no surviving file can say which. **When such a log next rolls over, the writer reads the doomed `.1`'s existence before the `os.replace` removes it** and stamps `discarded_generations: 1, discarded_unknown: true` — at least one archive destroyed, true count unknowable. Without that read the live file scans as generation 1, and the very rotation that destroyed 10.5 MB of history would have claimed to discard nothing. "Unknown, at least one destroyed" is a truthful answer; "nothing discarded" is not.

  **The zero-hit population was never recorded.** On the `UserPromptSubmit` path the audit write lived inside `if hits:` and `elif gate_skip:`. A fire where retrieval ran and returned zero hits, with the shape gate not firing, matched neither and wrote **no row**. That is exactly the population an analysis wants most — the prompts where retrieval did full work and found nothing — so every hit rate, fires-per-session and cold rate computed from this log had that class missing from its denominator with nothing indicating the gap. Such a fire now writes one row of the same shape with `n_beliefs: 0`, an empty `beliefs[]`, and no `prompt_shape_gate_skip` key, so it is a measured zero rather than a hole and is not confused with the gate-skipped bucket. It carries `sidecar_outcome` and `order_policy` for the same reason the gate-skip branch does: a zero-hit fire can still have paid a full rebuild, and that is the fire [#1380](https://github.com/robotrocketscience/aelfrice/issues/1380) is priced on. The zero covers both "BM25 found nothing" and "the project-context, session-exclusion and category filters emptied what it found" — both are a fire that injected nothing, which is what a hit rate's denominator needs; separating them would need a pre-filter count and is out of scope here. The `hook.py` edit is one `else` branch and nothing else, because another change is in flight against that file.

  **`benchmarks/sidecar_rebuild_rate.py` states the window it covered** — first and last row timestamp, whether a `.1` was present, the rotation generation — above the rate. It prints `WINDOW TRUNCATED` with the discarded count when generations are gone, `at least N` when that count is a floor, and `WINDOW UNKNOWN` for a `.1` with no generation stamp. Two ways it could contradict itself are closed: the completeness wording is gated on the generation rather than on a `.1` being among the paths, so a marked live file passed alone no longer prints "no rotation has occurred" under "rotation generation 2"; and an archive handed in without its live file reports unknown rather than complete, because each file records what had been lost when it was *created* and is blind to the loss caused by the rotation that archived it.

  **Compatibility and cost.** Every existing reader filters on a specific `hook` value, so the marker row is inert to all of them and is excluded from the benchmark's row census explicitly. A log with no marker and no `.1` has never rotated and reads as exactly complete; one with a `.1` reads as unknown — and the `.1` counts whenever it is on disk beside the live file, not only when the caller passed it in, because the single-path invocation is the documented one and every log already rotated in the wild is unmarked; `audit_window()` skips missing, unreadable, non-object and unparseable lines rather than raising. Disk is unchanged at two files — a `.2` slot is still never created. The scan runs once per rotation, which is once per `max_bytes` of accumulated log. Measured against a synthetic file at the 10 MiB default cap — 10.00 MiB, 9,939 rows, medians of 7 — it costs **31.2 ms** on the single fire that rotates, so **0.0031 ms** amortised across the 9,939 fires that filled the file, and the marker row is **275 bytes**, 0.0026% of the cap. Read those as one corpus, not as constants: the scan parses every row, so its cost tracks row CONTENT as well as file size, and `[hook_audit] max_bytes` is operator-settable, so a larger cap costs proportionally more per rotation and proportionally less per fire. Quote the ratio rather than the milliseconds for any other cap or corpus. The scan parses every row because `first_ts`/`last_ts` are a true min/max: concurrent hook processes append to this file, so reading the first and last line instead would be an ordering assumption rather than a measurement. A byte-oriented newline count over the same file is roughly an order of magnitude cheaper at **3.7 ms**, but yields only the row count.

### Performance

- **The BM25 sidecar is warmed by a detached child at `SessionStart`, so the session-first full rebuild is no longer paid on the user's first prompt ([#1513](https://github.com/robotrocketscience/aelfrice/issues/1513)).** `benchmarks/sidecar_rebuild_rate.py` now buckets scored fires by position within the session, and the two populations do not resemble each other: the `full_rebuild` rate on the first scored fire of a session runs materially above the rate on every later fire, on the prompt where a user is least willing to wait. Run the script to see the current split. **No magnitude for it is published here.** The population is a live, growing, single-slot-rotating audit log; successive re-derivations weeks apart moved the session-first rate substantially while the sign never flipped, and the rows the earlier runs scored are gone to rotation, so any percentage frozen into this file would be one nobody could reproduce.

  **The pre-registered target, corrected.** The first statement of it (committed in `a34bbb58`, and left in the history rather than rewritten) could not be read against the command it named. All three of its parts were wrong, for one underlying reason:

  - *It never named its population.* Its baseline came from every `hook_audit.jsonl*` on the machine, but the command a reader would run — `benchmarks/sidecar_rebuild_rate.py` with no arguments — globs one repository's log. Those two have no denominator in common, so the settling run could never be compared against the baseline it was meant to be read against.
  - *Its read gate was already met when it was written.* "Read only once at least 26 sessions carry a scored fire" was satisfied at more than 26 sessions on the baseline population itself, so it gated nothing.
  - *Its LATER clause was already false.* "The LATER bucket does not rise above its 1.0% baseline" was false on the day it was written: re-deriving over the same machine-wide population put LATER above 1.0% with nothing shipped. Held as stated, the gate would have read ordinary population drift as a regression the fix caused.

  The one underlying reason is that it compared a number taken at one time against a number taken at another, over a log set that grew and rotated in between. That difference is not the fix. The restated target compares two windows cut out of a single log set, in one pair of invocations that differ only in the window, which is what `--since` / `--until` were added for:

  ```
  find ~ -name 'hook_audit.jsonl*' -not -path '*/node_modules/*' | sort > /tmp/logs.txt
  xargs uv run python benchmarks/sidecar_rebuild_rate.py --until "$WARM_SHIPPED_AT" < /tmp/logs.txt
  xargs uv run python benchmarks/sidecar_rebuild_rate.py --since "$WARM_SHIPPED_AT" < /tmp/logs.txt
  ```

  `$WARM_SHIPPED_AT` is the ISO-8601 UTC instant the operator's installed hooks began running a build that carries the warm — not the merge date, because until then no fire in the log was spared by anything. The bound is half-open, so the two runs partition the log set with no fire in both and none lost.

  - **Read condition.** Read the pair only once the `--since` run's own `sessions beginning in this window` line reports 30 or more. That count is over the same population as the rate it gates, which the "26 sessions" condition was not.
  - **Primary.** The session-FIRST `full_rebuild` rate in the `--since` run is at most half the rate the `--until` run reports for the same log set. Relative, because the baseline is re-derived inside the pair rather than frozen into this file.
  - **Check that the pair partitions the sessions, not only the rows.** The `--until` and `--since` session counts must sum to the whole-set run's `sessions with a scored fire`. They did not before this branch's last pass: a session that began before the boundary and ran past it had its first in-window fire promoted to session-FIRST in the `--since` run and was counted on both sides. That promoted fire is a mid-session prompt no `SessionStart` warm inside the window could have spared, and LATER fires carry the lower rebuild rate, so each one pulled the `--since` session-FIRST rate down — toward satisfying the primary above. A session's position is now fixed by its first scored fire anywhere in the input, so a straddling session contributes only LATER fires to the `--since` run. The `sessions carried in from earlier` line counts those sessions: a `--since` run whose fires are mostly theirs holds few first prompts, and its primary rests on that much smaller sample.
  - **Deferral guard.** Compare the LATER rate between the two runs of the pair, never against a frozen figure. A fall in session-FIRST matched by a rise in LATER means the rebuild moved rather than went away, and fails the target however far session-FIRST fell.
  - **Sanity check that the warm ran at all.** The child writes one `sidecar_warm` row per spawn, unless the hook audit is off (`AELFRICE_HOOK_AUDIT=0`, or `enabled = false` under `[hook_audit]`), so `grep '"hook": "sidecar_warm"'` over the same logs says whether the `--since` window contains any warm at all. A window with none is an unshipped warm, a warm suppressed with `AELF_NO_SIDECAR_WARM=1`, or an audit the user turned off — not a failed target.
  - The fix cannot reach 0%: a user who types immediately, or a sibling session that ingests between the warm and the first prompt, still meets a stale index.

  The warm is a **detached child process** spawned from the SessionStart hook, chosen against the failure mode rather than the happy path. *A thread the hook does not join* was rejected: the hook is a short-lived process, so a non-daemon thread keeps the interpreter alive until the build finishes and the host waits on the hook — that moves the latency into `SessionStart` instead of removing it, which the issue's AC2 names explicitly; a daemon thread inverts the failure and is killed mid-build, writing nothing. *Warming on a later fire* was rejected on the measurement: the later bucket already runs far below the session-first one, so a warm that runs on the second fire arrives after the fire that pays. The parent does one environment read and one `Popen` and nothing else — no store open, no retrieval flag, no numpy — because every decision that costs anything (is the L1 lane on, is the sidecar fresh, what tokenisation parameters apply) is made inside the child. That is structural rather than measured, and no spawn-cost figure is published: a wall-clock millisecond number taken on a loaded developer machine does not reproduce.

  Both halves are fail-soft and neither can change what the hook emits: a spawn that raises returns False, a warm that raises returns None, and `SessionStart`'s stdout, stderr and return code are pinned byte-identical between a suppressed warm and one that explodes. The child builds through the *same* helper and resolvers the L1 lane uses, which is load-bearing rather than tidy — a sidecar written under different tokenisation parameters is rejected as describing different documents, so a warm that resolved its own would pay the whole build and leave the next fire rebuilding anyway. Sharing the resolvers is not by itself enough: three of the four parameters come from env and TOML and so agree across processes by construction, but `anchor_weight` decodes a *decaying* posterior when the #757 meta-belief is enabled, and the warm's clock at T and the fire's at T+30s were observed decoding adjacent integers out of the `[1, 10]` band under the shipped 30-day half-life — both fires then recorded `full_rebuild`. While a sidecar is fresh, the weight it was built under is read back off its header and is the answer both sides take; the next write to the store lifts the pin, which is where a moved meta-belief takes effect. `AELF_NO_SIDECAR_WARM=1` suppresses the spawn.
- **A gate-skipped hook fire stops importing the retrieval subtree it exists to skip ([#1527](https://github.com/robotrocketscience/aelfrice/issues/1527)).** The prompt-shape gate refuses trivial and system-generated prompts so they never retrieve. They never did retrieve — and imported the whole retrieval stack anyway, because the skip branch calls `_emit_user_prompt_submit_rebuild_log` unconditionally and that function reached into `aelfrice.context_rebuilder` *above* its own `session_id` and `:memory:` early returns, pulling `retrieval`, `triple_extractor`, `scoring`, `clustering`, `bfs_multihop`, `correction`, `derivation*`, `doc_linker*`, `exploration`, `compression` and `np_pattern` behind it. That circularity is why the fix is a module extraction rather than a lazy import — the same remedy #1407 applied to `sidecar_outcome`, for the same reason, that every hook fire is a fresh process. `aelfrice.rebuild_log` now holds the `[rebuilder]` / `[rebuild_log]` config resolution and the phase-1a diagnostic log, and `entity_extractor` / `triple_extractor` are function-scope imports below every early return, so a skipping fire (which passes an empty candidate list) never reaches them. `context_rebuilder` re-exports every name in `rebuild_log.__all__` except `_extracted_entities_for_log` and `_recent_turns_hash`, which nothing outside `rebuild_log.py` calls, so the CLI, the benchmarks and the existing `from aelfrice.context_rebuilder import ...` callers import what they ask for unchanged. `tests/test_rebuild_log_reexports_1527.py` holds both halves: the exception list as a set equality, and every such import under `src`, `tests`, `benchmarks` and `scripts` resolving. Neither half moves the number alone; the leaf extraction is worthless while `hook.py` imports `context_rebuilder` eagerly, and the deferral is worthless while the rebuild-log call re-pays it. **The measurement is the module closure, and `scripts/measure_1527_import_closure.py` is what produces it**: it exports each git ref with `git archive` so neither arm is the installed package, then probes it in cold subprocesses with every `AELFRICE_*` / `AELF_*` variable stripped and `HOME`, the dotdir and the DB pinned to a scratch directory, because the lane resolvers are env-first and opening a `MemoryStore` is a write. Against `github/main`: **`import aelfrice.hook` falls from 35 `aelfrice` modules to 18, and a driven gate-skipped fire from 40 to 26**; `aelfrice.rebuild_log` costs 12 where `aelfrice.context_rebuilder` cost 28. `tests/test_hook_import_cost_1351.py` pins 18 and 26 as ceilings and asserts that none of the twelve retrieval-subtree modules loads on a skipped fire. - **`benchmarks/README.md` states the rule that agreement is not quality evidence ([#1453](https://github.com/robotrocketscience/aelfrice/issues/1453)).** Top-10 movement rate, Jaccard overlap at k, Kendall tau and "N of M queries changed" are **change** statistics: they say two configurations return different results, not which one is right. A movement rate becomes a quality statistic only against labelled relevance, external to both rankers. Without labels a large movement and a small movement are equally consistent with an improvement, a regression and noise. The note names the two failure modes that have actually occurred — reporting a movement rate as if it were an uplift, and treating agreement between two approximations as validation — and cites [`848dbf83`](https://github.com/robotrocketscience/aelfrice/commit/848dbf83aab6e2c5198b1bc5b0f70ebcc7f11ea9), the revert that retracted a published table for the second reason, after `extracted_query` turned out to be handed to `retrieve()` by neither caller (97.7% of recorded rows come from `user_prompt_submit`, which scores a conversation-aware composition the context rebuilder never sees). - **The premise that an observational store open is worth optimizing is refuted, the four components are measured apart, and the invariant underneath them now has a guard ([#1561](https://github.com/robotrocketscience/aelfrice/issues/1561)).** `aelf search`, `stats`, `locked`, `speculative` and `show` open through `db_paths.open_store_for_read()`, which attempts the ordinary writable open first and falls back to `mode=ro` only when that open is refused for lack of write access ([#1416](https://github.com/robotrocketscience/aelfrice/issues/1416)). Against a writable store — every ordinary store — the handle is the writable one, so an observational command pays the whole open-time write window: the schema battery, the one-shot migrations, the scope-id mint, and the [#1314](https://github.com/robotrocketscience/aelfrice/issues/1314) expired-lock sweep. **The open order is unchanged, and nothing in `src/aelfrice/` moves here.** `benchmarks/store_open_cost.py` measures what the writable-first attempt costs at the repo-store layout, by installing a SQLite trace callback on the connection `MemoryStore` opens and reading the row count off that connection's own `total_changes`: 87 statements — 56 `CREATE`, every one of them `IF NOT EXISTS`, 26 `SELECT`, and 5 `PRAGMA` — against 5 statements for a `mode=ro` handle, so 82 statements are the whole of what reversing the order could recover. **The four components are counted apart rather than as one keyword census**, because a total cannot answer which part a short-cut would be short-cutting: 58 statements are the DDL battery, 23 the migration check, 1 the scope-id mint, 1 the expired-lock sweep, and 4 the connection `PRAGMA`s that precede all of them. Attribution is by execution nesting — each component's entry point in `aelfrice.store` is wrapped, and the innermost open span owns the statement — so the split survives a one-shot being added or reordered, which a positional slice of the trace would not. The producer refuses to publish any per-component figure unless the parts sum to the whole, which is what catches an entry point being renamed on one side only.
  **The decision is that no component should be short-cut, and the split is why.** The DDL battery is 58 of the 87 and is the only part worth a mechanism, but it is also 56 `CREATE ... IF NOT EXISTS` against a schema that already exists — the cost of establishing that is the cost being measured, and it is 0.282 ms. The migration check is 23 marker probes on `schema_meta`, one pair per one-shot, and skipping it is what `mode=ro` already does: it is the degraded semantics [#1416](https://github.com/robotrocketscience/aelfrice/issues/1416) rejected, not a saving. The scope-id mint is a single `SELECT`. The sweep is a single index probe when nothing is due, and it is the one component that must run for correctness of what these commands print. There is no component whose removal is both material and semantically free, so nothing is proposed and the five callers keep the open they have.
  **The zero-write figures hold on a *settled* store, which is two conditions and not one.** Every one-shot has already run, **and** no time-boxed lock is due to expire. On such a store the open issues 0 `INSERT`, `UPDATE` or `DELETE` statements, mutates 0 rows, and changes 0 bytes of the database file. Neither condition is a hedge, and the second is the one an ordinary user meets repeatedly rather than once: on the same store with one lock past its `lock_expires_at`, the same open issues 95 statements — the sweep's own 9 of them — performs 6 `INSERT`/`UPDATE` statements, mutates 6 rows, and changes the file's bytes. That is the writable-first order working exactly as designed, and it is measured and published rather than described, under the `expired_lock_*` keys, because a reader who takes the zero as unconditional is reading a false statement about their own store. **The counts are size-invariant but not state-invariant**, and the entry says which: the producer refuses to publish a figure unless the census agrees at 200, 2,000 and 20,000 beliefs, so a count that starts moving with store size fails the gate instead of being averaged into one — while the 87-versus-95 gap above is a property of what the store holds, is not visible to any size grid, and has its own arm for that reason. On one machine at 20,000 beliefs the avoidable component's median is 0.267 ms against `aelf stats` at 9.3 ms in process, an avoidable share of 2.86% of the work the command does. **Those latencies carry no marker, deliberately.** A wall-clock reading is a property of the machine that took it, `--emit-figures` emits none, and `docs/design/derived_figure_markers.md`'s own rule is that a marker over a value nobody can recompute publishes a second unchecked number beside the first. The statement counts are store-free instead, because the producer builds its fixture from shipped code in a temporary directory: `scripts/check_derived_figures.py --mode producers` re-runs them on every pull request and hard-fails on a difference, which is the stronger of the two marker classes and the one a count is eligible for. **`--store` has no default, and it copies what it is given.** Nothing in the file calls `db_path()`, a run with no mode selected exits 2, and a named database is copied into a temporary directory before it is opened — opening a store is a write, so measuring one in place would mutate the corpus under measurement, which is [#1328](https://github.com/robotrocketscience/aelfrice/issues/1328) exactly. **Two layouts are published, because a census taken at the wrong path disagrees with itself**: outside the repo-store layout `repo_identity_from_db_path` returns no identity, the project-context backfill's marker probe drops out, and the same open issues 86 statements rather than 87 — a one-statement gap that is the likeliest way for a re-derivation of this issue to contradict the one recorded here.
  **The permanent deliverable is the invariant, not the number.** `tests/test_store_open_cost_1561.py` reds if a write enters the observational path on a settled store: strip the completion-marker guard from `_maybe_backfill_project_context` and the open stamps `schema_meta` on every fire, which turns every read command into a writer and which nothing else in the suite would see — `tests/test_readonly_store_1416.py` compares the file bytes only on stores frozen at 0444, where the engine forbids the write regardless. **Both halves of the precondition are asserted rather than hedged.** One test builds a store carrying an unrun one-shot, counts the rows it is due to stamp off the fixture, and pins the write it performs; another back-dates one lock's expiry on an otherwise settled store and pins that the open flips the lock, changes the file, and settles. So the zero-write guard cannot be misread as "an observational open never writes", and a future change making the open unconditionally read-only reds with the semantics it drops named in both directions. **`docs/user/COMMANDS.md` now documents the open for all five callers, not one.** The `show` row already carried the mechanism in full; the same explanation now sits above the command table as its own section, naming the five commands, what the writable-first open does on a store an older version wrote, what it does to an expired lock, and what the read-only fallback gives up instead — so `search`, `stats`, `locked` and `speculative` stop being silent on a write their readers would not expect.

# Commands

The `aelf` command-line interface (CLI) has many subcommands. To list the full set, run `aelf --help --advanced`. The retrieval and feedback commands also exist as slash commands, described in [SLASH_COMMANDS](SLASH_COMMANDS.md). Most lifecycle commands have a slash-command form too: `setup`, `doctor`, `upgrade`, and `uninstall` all have `/aelf:*` forms. Only `migrate` and `unsetup` are CLI-only. `aelf unsetup` has no slash form, and the `/aelf:uninstall` flow does the teardown.

```
aelf <subcommand> [args] [options]
aelf --help
aelf --version
```

The database (DB) path resolves in this order:

1. `$AELFRICE_DB`.
2. `<git-common-dir>/aelfrice/memory.db`, when `cwd` is inside a git work-tree.
3. `~/.aelfrice/memory.db`, the non-git fallback.

## Memory operations

| Command | What it does |
|---|---|
| `onboard <path>` | Walks the filesystem, the git log, and the Python abstract syntax tree (AST), classifies the candidates, and inserts the ones that are not duplicates. To tune the behavior, edit `.aelfrice.toml` — see [CONFIG](CONFIG.md). From v1.5.1, host-driven classification by a large language model (LLM) is on by default (#238), so `[onboard.llm].enabled = true` is the default. The host model's Task tool does the classification, so you need no API key. When no host Task tool is reachable, the command falls back to the deterministic regular-expression classifier without an error. `--llm-classify` selects the direct-API path, which requires the API-key install extra and keeps the legacy fail-fast install hint. `--emit-candidates` and `--accept-classifications` are the low-level handshake that drives the host-driven classifier; see [llm_classifier.md](../design/llm_classifier.md). `--dry-run` previews the candidates and inserts nothing. `--revoke-consent` removes the stored consent sentinel and exits. `--check` is a read-only pre-scan that reports the already-present count and the to-classify count, then exits (#761). `--force` bypasses the rejection ledger, so the command emits previously-rejected candidates again (#801). |
| `search <query> [--budget N]` | Combines three lanes: L0 locked beliefs, the L2.5 entity index (v1.3+), and L1 full-text search version 5 (FTS5). The L1 lane ranks with Best Matching 25 (BM25). The result is token-budgeted: the default budget is 2,400 at v1.3+, and it was 2,000 before that. L2.5 is on by default. To disable L2.5, set `[retrieval] entity_index_enabled = false` in `.aelfrice.toml`, or set `AELFRICE_ENTITY_INDEX=0` in the environment. The output distinguishes "store empty" from "no match". |
| `lock <statement>` | Inserts the belief at `(α, β) = (9.0, 0.5)` with `lock_level=user`. The command is idempotent: locking the same statement again upgrades the existing belief. |
| `locked` | Lists the locks. |
| `core [--json] [--limit N] [--min-corroboration N] [--min-posterior FLOAT] [--min-alpha-beta N] [--locked-only] [--no-locked]` | (v2.0+, #439) Surfaces the load-bearing beliefs. The set is the union of three groups: the locked beliefs, the beliefs with corroboration ≥ 2, and the beliefs with posterior ≥ 2/3 and α+β ≥ 4. The command is read-only. |
| `unlock <belief_id>` | Drops a user lock without changing the origin. It is idempotent, and it writes a `lock:unlock` audit row. |
| `delete <belief_id> [--yes] [--force]` | Hard-deletes a belief. It removes the belief row, the FTS entry, the edges (src and dst), and the entity index rows. Before the cascade it writes one audit row to `feedback_history` (valence=-1.0, source=`user_deleted`), so the forensic record survives. By default the command prompts for confirmation: it prints the belief content, and you must type the first 8 characters of the id. `--yes` skips the prompt. Without `--force`, the command refuses a locked belief (`lock_level=user`); with `--force`, the audit source becomes `user_deleted_force`. The command exits 0 on success. It exits 1 on not-found, on locked-without-force, and on a prompt mismatch. |
| `retire <belief_id> [--force]` | (v4.0+, [#1081](https://github.com/robotrocketscience/aelfrice/issues/1081)) A **reversible** soft-delete, the reversible form of `delete`. It sets `valid_to`, so the belief leaves retrieval and FTS search, and it preserves the belief's evidence trail: the edges, the entity index rows, and the corroborations. Before the soft-delete it writes one `feedback_history` audit row (valence=-1.0, `user_retired`, or `user_retired_force` with `--force`). A locked belief requires `--force`. Retiring an already-retired belief is a no-op. To undo a retire, run `restore`. |
| `restore <belief_id>` | (v4.0+, [#1081](https://github.com/robotrocketscience/aelfrice/issues/1081)) The inverse of `retire` and of `soft_delete_belief`. It clears `valid_to` and re-inserts the pruned FTS row, so the belief returns to keyword search and to retrieval. It writes a `user_restored` audit row (valence=+1.0). On an already-active id or an unknown id the command is a no-op: it reports "not restorable" and exits non-zero. |
| `introspect [--by session\|project] [--session ID] [--project CTX] [--only-noise] [--limit N] [--json]` | (v4.0+, [#1081](https://github.com/robotrocketscience/aelfrice/issues/1081)) A read-only honest-signal view over the active beliefs, and the native answer to "analyse the beliefs it extracted." It groups the beliefs by ingest session, or by project with `--by project`. For each belief it shows the signals that the store already holds but never showed together: the posterior μ and the evidence weight (α+β); the **recurrence** (`corroboration_count`), labeled explicitly as recurrence and *not* as truth; the **grounding** (`durable`/`ephemeral`/`neutral`, from `entity_persistence_scores`); the floated-versus-decided **status**, from the `RESOLVES` and `POTENTIALLY_STALE` edges; and the stranded-capture **noise** (`is_stranded_capture_noise`). The noise rows come first in each group. They are the prime retire candidates. `--only-noise` gives you the retire shortlist. `--limit 0` removes the cap. The command is deterministic per #605: it uses counts and edge lookups only, with no model and no clock. To curate from its output, use `retire`, `lock`, and `resolve`. |
| `demote <belief_id> [--to-scope SCOPE]` | Drops a user lock, one tier per call: first the lock, then user_validated. The lock-drop path delegates to `unlock`, so the command always writes an audit row. From v3.0 ([#689](https://github.com/robotrocketscience/aelfrice/issues/689)), `--to-scope` flips the federation visibility back to `project`, or to any other valid scope. When `--to-scope` is the only flag, the command skips the tier demotion and changes the scope only. It writes a `scope:<old>-><new>` audit row. |
| `promote <belief_id> [--source user_validated] [--to-scope SCOPE]` | Promotes an `agent_inferred` belief to `user_validated`. It is an alias of `validate` for the promotion semantics, but unlike `validate` it also accepts `--to-scope`. From v3.0 ([#689](https://github.com/robotrocketscience/aelfrice/issues/689)), `--to-scope` flips the belief's federation visibility (`project` / `global` / `shared:<name>`) in the same call, and writes a zero-valence `scope:<old>-><new>` audit row. The scope flip works on an `agent_inferred` belief, combined with the origin flip. It also works on a row that is already `user_validated`, where it changes the scope only, because the origin path is idempotent. A foreign id raises `ForeignBeliefError`. A speculative belief (`origin=speculative`) promotes to `user_validated` per Surface A ([#550](https://github.com/robotrocketscience/aelfrice/issues/550)). |
| `validate <belief_id> [--source user_validated]` | Promotes an `agent_inferred` belief to a user-validated origin (v1.2+). |
| `confirm <belief_id> [--source S] [--note TEXT]` | Records an explicit user affirmation. It adds 1.0 to α with the source `user_confirmed` (the default), and writes to `feedback_history`. It prints the note on success, but it does not persist the note. Unlike `lock`, `confirm` does not freeze the belief, and unlike implicit retrieval feedback (the `used` signal), the affirmation is explicit rather than passive. For that reason `confirm` is the one feedback surface that the [#1168](https://github.com/robotrocketscience/aelfrice/issues/1168) lock floor exempts, so it still moves the posterior of a locked belief. |
| `feedback <belief_id> <used\|harmful> [--source S]` | `used` adds 1 to α. `harmful` adds 1 to β. The command is a **no-op on a user lock** ([#1168](https://github.com/robotrocketscience/aelfrice/issues/1168)): passive feedback does not move a lock. It writes the event to `feedback_history`, leaves the posterior alone, reports that it left the posterior alone, and exits 0. To change a locked belief, first unlock it, or use `delete` or `demote`. [#814](https://github.com/robotrocketscience/aelfrice/issues/814) removed the contradiction-driven lock demotion. Lock correction now goes through `aelf lock`, which overwrites the belief, per PHILOSOPHY [#605](https://github.com/robotrocketscience/aelfrice/issues/605). |
| `resolve` | Sweeps the unresolved `CONTRADICTS` threads, picks a winner by the precedence `user_stated > user_corrected > document_recent`, then inserts a `SUPERSEDES` thread. The command is idempotent. |
| `reason <query> [--seed-id ID]... [--k N] [--depth N] [--budget N] [--fanout N] [--json]` | (v2.0+, [#389](https://github.com/robotrocketscience/aelfrice/issues/389)) Surfaces a reasoning chain over the belief graph. The default seeds are the top-3 BM25 hits over `<query>`. `--seed-id` overrides the default seeds, and you can repeat it. The command walks `expand_bfs` with terminal-tight defaults (depth=2, budget=10, fanout=8). The default output is an indented hop tree with edge-type breadcrumbs and path-scores. `--json` produces output for tooling. The command is read-only over the graph. **From v3.0 ([#645](https://github.com/robotrocketscience/aelfrice/issues/645), [#658](https://github.com/robotrocketscience/aelfrice/issues/658), [#690](https://github.com/robotrocketscience/aelfrice/issues/690), [#713](https://github.com/robotrocketscience/aelfrice/issues/713)):** the `--json` payload gains these fields. `verdict` and `impasses` come from the Verdict classifier and the ImpasseKind classifier. `paths` holds the ConsequencePath fork on `CONTRADICTS`. `dispatch` holds one row per impasse, mapped to Verifier, Gap-filler, or Fork-resolver. `suggested_updates` holds belief-id direction notes for the `feedback` close-the-loop step. The command is peer-aware: it annotates hops and seeds in foreign scopes with `[scope:<name>]` in the human output, and it carries `owning_scope` in JSON. If a `--seed-id` is foreign, the command resolves it through `find_foreign_owner`. |
| `review [--generate] [--apply] [--out PATH] [--json]` | (v3.5+, [#936](https://github.com/robotrocketscience/aelfrice/issues/936)) The weekly belief-review checkpoint. **`--generate`** is the default when you give no flag. It writes `.aelfrice/review.md` with up to 10 oldest-unconfirmed beliefs as a markdown checkbox list. The sort order is `last_confirmed_at NULLS FIRST`, then `last_retrieved_at NULLS FIRST`, then `created_at ASC`. **`--apply`** parses the verdicts from the file: `keep` updates `last_confirmed_at`; `remove` soft-deletes the belief and writes an audit row; `lock` promotes the belief to `lock_level=user`; a blank verdict skips the belief. The command rejects any row with two or more checked boxes and applies nothing, so it fails closed. `--out PATH` overrides the default `.aelfrice/review.md` in both modes. `--json` works with `--apply` only, and emits `ApplyReport` as JSON. The command shares its NULLS-FIRST age ordering and recency ordering with `aelf stale` (#933), which shipped alongside it in v3.5.0. |
| `wonder [QUERY] [--axes QUERY] [--axes-agents N] [--seed ID] [--top N] [--emit-phantoms] [--persist] [--persist-docs FILE] [--gc] [--gc-dry-run] [--gc-ttl-days N] [--json]` | (v2.0+, [#389](https://github.com/robotrocketscience/aelfrice/issues/389)) The command has two modes, and the shape of the argument selects the mode. **No-argument graph-walk mode (v2.0)**: surfaces consolidation candidates with `--seed`. The default seed is the highest-degree non-locked belief, with an id-ascending tiebreak. The command ranks the candidates by combining the breadth-first search (BFS) path-score with the `wonder_consolidation.score` token-overlap. The suggested actions are in `{merge, supersede, contradict, relate}`. **Axes mode, selected by the positional `QUERY` or by `--axes QUERY` (v3.0+, [#542](https://github.com/robotrocketscience/aelfrice/issues/542) / [#551](https://github.com/robotrocketscience/aelfrice/issues/551) / [#552](https://github.com/robotrocketscience/aelfrice/issues/552) / [#645](https://github.com/robotrocketscience/aelfrice/issues/645))**: the command runs `analyze_gaps()` and `generate_research_axes()`, and emits 2-6 orthogonal research axes for subagent dispatch at the skill layer. It recognizes the agent-count shorthand `quick N-agent` / `deep N-agent` / `N-agent`. **`--persist`** writes BFS phantom candidates through `wonder_ingest`. `--persist` is mutually exclusive with `--axes` and with the positional QUERY, and that combination exits 2. **`--persist-docs FILE`** ingests subagent research documents through `wonder_ingest`, per the #644 v2 dedup key. The file is JSONL with `{axis_name, content, anchor_ids}` rows. **`--gc [--gc-dry-run] [--gc-ttl-days N]`** runs `wonder_gc`. The v3.0 flag form replaces the v2.1 `wonder gc` sub-subcommand. Garbage collection (GC) is manual by default. To opt into automatic per-session GC on the SessionStart hook, set `AELFRICE_WONDER_AUTOGC=1` (default-off, [#980](https://github.com/robotrocketscience/aelfrice/issues/980)). `AELFRICE_WONDER_AUTOGC_TTL_DAYS=<days>` overrides the 14-day threshold. A sweep that deletes anything emits a `wonder.gc` feed row and an `aelf-hook:` notice on stderr. `--emit-phantoms` prints `Phantom` JSON objects for offline review. `--json` emits the `WonderResult` dataclass ([#656](https://github.com/robotrocketscience/aelfrice/issues/656)) with `mode` (`graph_walk` / `axes`), the clamped `coverage ∈ [0.0, 1.0]` ([#667](https://github.com/robotrocketscience/aelfrice/issues/667)), `phantoms_created`, and other fields. |
| `stale [--older-than N] [--cold-for N] [--locked-only] [--limit N] [--json]` | (v3.5+, [#933](https://github.com/robotrocketscience/aelfrice/issues/933)) Lists the beliefs that meet two conditions: `created_at` is older than N days (default 30), and `last_retrieved_at` is NULL or older than M days (default 14). There is no decay model, and the windows are plain. The `--limit` default is 20. |
| `feed [--since DUR] [--limit N] [--json]` | (v3.5+, [#931](https://github.com/robotrocketscience/aelfrice/issues/931)) Reads the belief-write event log at `<git-common-dir>/aelfrice/feed.jsonl`. The log holds lock rows, onboard rows, wonder-promote rows, and feedback rows. `--since` takes a duration such as `5m`, `2h`, or `1d`. `--limit 0` is the default, and it shows all rows. |
| `speculative [--origin TAG] [--limit N] [--json]` | (v3.5+, [#937](https://github.com/robotrocketscience/aelfrice/issues/937)) Lists the non-user-locked active beliefs, sorted by α descending. This set is the agent-inferred, ingested, and wonder-generated layer. The `--limit` default is 20. |
| `category <action>` | (v4.x+, [#1126](https://github.com/robotrocketscience/aelfrice/issues/1126)) Manages keyword-triggered belief categories. A category is a named group of beliefs, bound to an activation trigger. The actions are `init` (seed the 5 starter categories idempotently), `add <name> [--always-on] [--keyword PHRASE]… [--tool-glob G]… [--file-glob G]… [--lock none\|locked\|advisory]`, `list`, `show <name>`, `set-trigger <name> [--keyword …]…`, `assign <belief_id> <name>`, `unassign <belief_id> <name>`, and `delete <name>`. The `UserPromptSubmit` injection lane surfaces the members of a fired category. That lane is **default-off**: to enable it, set `AELFRICE_BELIEF_CATEGORIES=1` or `[belief_categories] enabled=true`. The lane is advisory, and it never blocks a tool call. To assign a belief at lock time, run `lock "<rule>" --category <name>`. The membership is user-driven, and there is no auto-classification. |
| `audit-claude-memory [--project PATH] [--json]` | (v3.5+, [#935](https://github.com/robotrocketscience/aelfrice/issues/935)) Runs a read-only cross-store deduplication audit. It compares the locked aelfrice beliefs with the host's auto-memory `MEMORY.md`, and reports potential duplicates, contradictions, and store-exclusive entries. |
| `reconcile-claude-memory [--project PATH] [--force]` | (v4.0+, [#1089](https://github.com/robotrocketscience/aelfrice/issues/1089)) Ingests the project's claude-memory fact files (`<memory-dir>/*.md`, excluding `MEMORY.md`) into the belief graph. It is the full-set sweep that complements the `PostToolUse` write-through mirror (#985), and it normally runs once per project at `aelf setup`, behind a sentinel, so this command is the manual re-run. It's idempotent: content-derived ids mean a re-run corroborates a belief instead of duplicating it. `--project` defaults to the current directory, and `--force` re-runs past the per-project sentinel. The flow is one-way and non-authoritative: aelfrice never writes back to the memory files. |
| `export-obsidian <vault> [--scope all\|recent\|query] [--query TEXT] [--neighborhood-hops N] [--k N] [--max-notes N] [--force]` | (v3.0+) Runs a one-way export from the DB to the vault, one Markdown note per belief under `<vault>/aelfrice/`. The typed edges go in the YAML front-matter, where Dataview can query them, and the note body carries wikilinks. The default cap is 500 notes, and without `--force` the hard ceiling is 5000 notes. |

## Diagnostics

| Command | What it does |
|---|---|
| `stats` | Prints the belief count, the thread count, the lock count, and the feedback count. |
| `health [--json]` | The structural auditor. It checks orphan threads, FTS5 synchronization, locked contradictions, and corpus volume. The report includes a per-edge-type count breakdown, sorted by count descending, then alphabetically. On an empty store it prints `no edges yet`. `--json` emits `{"audit": {...}, "features": {"edges_by_type": {...}}}`. The command exits 1 on a structural failure. The corpus-volume warnings are informational. |
| `status` | An alias for `stats`. It prints the belief count, the thread count, the lock count, and the feedback count. From v3.0 it adds an `hrr.persist_state` summary line for the holographic reduced representation (HRR) index — see [HRR persistence reporter](#hrr-persistence-reporter) below. The structural auditor is `aelf doctor graph`. The `health` verb is hidden. |
| `graph [anchor] [--seed-id ID]... [--hops N] [--budget N] [--fanout N] [--edge-types CSV] [--format dot\|json] [--preview-chars N] [--out PATH]` | (v3.3+, [#629](https://github.com/robotrocketscience/aelfrice/issues/629)) Emits a BFS subgraph anchored on a belief. It tries `anchor` as a literal belief id first, and it falls back to the top BM25 hit. `--seed-id` overrides the anchor, and you can repeat it. The edges are color-coded for all 11 edge types, and the legend is in `--help`. The nodes are shaded by lock status and by posterior bucket. `--format dot` is the default, and it produces Graphviz output. `--format json` produces output for tooling. The defaults are `--hops 2` and `--preview-chars 80`. |
| `scope-out <pattern> [--list] [--clear]` | (v3.3+, [#856](https://github.com/robotrocketscience/aelfrice/issues/856)) A session-scoped retrieval exclusion. The positional `pattern` adds a case-insensitive literal substring. The hook injection then drops every belief whose content contains that substring, the locked beliefs included, for the rest of the active session. The list clears itself when a new session starts. `--list` shows the active patterns. `--clear` empties the list. For federation visibility, use `promote` or `demote --to-scope` instead of this command. |
| `regime` | Prints the v1.0 regime classifier output (`supersede` / `ignore` / `mixed` / `insufficient_data`). It is informational, and it always exits 0. |
| `doctor` | Verifies that the hook commands and the statusline command resolve. It inspects `bash <script>` wrappers, flags `2>/dev/null \|\| true` patterns, and surfaces the empty-store warning, then exits 1 on a broken hook. From v1.6 it has two more flags. `--gc-orphan-feedback` deletes the `feedback_history` rows whose `belief_id` no longer exists (#223). `--promote-retention` is a one-shot reclassification pass over the low-prior beliefs, based on the accumulated retrieval evidence and corroboration evidence (#290 phase-3). From v3.0 the command adds three HRR persistence rows (`hrr.persist_enabled`, `hrr.on_disk_bytes`, `hrr.last_build_seconds`) — see [HRR persistence reporter](#hrr-persistence-reporter) below. |
| `bench [--top-k N]` | Runs the deterministic benchmark of 16 beliefs by 16 queries, and prints a JSON `BenchmarkReport`. |
| `bench all --out PATH [--canonical] [--adapters CSV] [--smoke]` | (v2.0+, #437) The reproducibility harness. It runs each academic-suite adapter (mab, locomo, longmemeval, structmemeval, amabench) in a subprocess at the canonical headline cut, and it merges the results into one schema-v2 JSON file. `--canonical` asserts that the run matches `CANONICAL_INVOCATIONS`, which is the full benchmarks per the 2026-05-06 ratification, and it refuses if the cut differs. `--smoke` runs the small SMOKE_INVOCATIONS subset. `--adapters` filters the adapters. `--adapters` combined with `--canonical` refuses, because the cut then differs. The command returns 0 for ok, 1 for any error, and 2 for any skipped_data_missing. |
| `tail [--since DUR] [--filter key=value]... [--no-blob] [--no-follow]` | (v1.6+) Live-tails the per-turn hook audit log at `<git-common-dir>/aelfrice/hook_audit.jsonl`. For each fire it prints a header line with the time, the hook, the tokens, the latency, and `L0×N L1×M`. It then prints one indented snippet line per injected belief. `--no-blob` suppresses the snippet bodies. `--no-follow` dumps the log and exits. `--filter` matches fields such as `hook=user_prompt_submit` or `lane=L0`, and you can repeat it. See [hook-injection-audit.md](../design/hook-injection-audit.md). |
| `sweep-feedback` | (v1.6+) **Audits** the deferred-feedback queue (#191). It reports how many exposures are past their grace window. For those exposures it reports the `+ε` α (default 0.05) that they *would* have received, and what that would total. The command changes nothing. #1162 gave this sweep the treatment that #1091 flagged it for, so both exposure-as-evidence paths are now audit-only and agree. The same change made enqueue-on-retrieve opt-in. The sweep consumes nothing, so the numbers are repeatable rather than draining to zero on the first run. `--gc` deletes the banked `enqueued` rows that the sweep can no longer act on, and it reports the count. `--gc` is the one destructive action, and it is never implicit. |
| `eval [--corpus PATH]` | Runs the relevance-calibration harness (P@K / ROC-AUC / Spearman ρ) on a synthetic corpus. It prints the calibration block, and it exits 0 on success. |
| `clamp-ghosts [--threshold F] [--target F] [--apply] [--limit N]` | **Hidden / advanced.** A one-shot repair tool for stores migrated from pre-v1.0 schemas. It identifies the belief rows that meet two conditions: the row's α is inflated above the prior, and the row has zero `feedback_history` entries and zero `belief_corroborations` entries. Those rows are ghosts without an audit trail. The α floor is `--threshold`, default 4.0. `--target` (default 4.0, and it must be ≤ threshold) is the α value that the command clamps down to. `--limit` caps the rows per call. The command is a dry run by default, and `--apply` writes the UPDATE plus a negative-valence `feedback_history` row inside one transaction, so the clamp is reversible and idempotent. |
| `scan-derivation --reference PATH [--threshold F] [--n N] [PATH ...]` | (v3.0+, [#681](https://github.com/robotrocketscience/aelfrice/issues/681)) An n-gram Jaccard similarity gate against a reference document. It reads each PATH. With `-` or with no arguments it reads stdin. For each input it prints `MATCH [score] label: excerpt` or `clean [score] label`. It exits 0 when all inputs are clean, 1 when one or more inputs matched, and 2 when the reference is unreadable. Use it in a git pre-commit hook or a git pre-push hook. The defaults are 3-gram windows and threshold 0.6. |

## Lifecycle

| Command | What it does |
|---|---|
| `setup` | Installs the full default hook set. Alongside the `UserPromptSubmit` retrieval hook and the statusline notifier, the set contains these lanes, each one default ON with a `--no-*` opt-out: transcript-ingest (four-event loggers), commit-ingest (`PostToolUse:Bash`), session-start (L0 injection), stop-hook (lock prompt), sessionstart-recap, search-tool (`PreToolUse:Grep\|Glob`), search-tool-bash, pre-issue-guard, claude-memory-mirror, and agent-context. The claude-memory-mirror lane is `PostToolUse:Write\|Edit\|MultiEdit`, v3.7.0+. It runs once the one-shot reconcile at the first `aelf setup` records per-project consent, and it also runs when `AELFRICE_MIRROR_CLAUDE_MEMORY` or `[memory] mirror_claude_memory` enables it explicitly. An explicit `0` or `false` always wins (#985/#1089). The agent-context lane is `PreToolUse:Agent`, and dispatched workers inherit the locked beliefs and the task-relevant beliefs (#1068). `--rebuilder` is the one opt-in lane. Its block ships on `SessionStart(source="compact")`, after compaction, and not on `PreCompact` ([#1031](https://github.com/robotrocketscience/aelfrice/issues/1031)). `--host {claude,codex}` selects the host. With `codex`, the hooks land in the Codex home's `hooks.json` (`$CODEX_HOME`, else `~/.codex`), and the slash bundle installs as `$aelf-*` agent skills. `--codex-skills` is default-on, and `--no-codex-skills` installs the hooks only. See [SLASH_COMMANDS § Codex host](SLASH_COMMANDS.md). The command auto-detects the scope: `project` if `cwd/.venv` matches the active interpreter, else `user`. The command is idempotent and atomic. See [INSTALL § default-on hooks](INSTALL.md). |
| `unsetup` | Removes the hook and the aelfrice statusline contribution. On a composed statusline it strips the aelfrice part and leaves the rest in place. It mirrors the `setup` flags. |
| `upgrade-cmd [--check]` | Prints the upgrade command for the install method (uv tool, pipx, venv, or system), including the wheel SHA-256 for hash-pinned installs. It doesn't run the upgrade itself, because replacing the running interpreter mid-process is unreliable. Bare `upgrade` remains as a hidden deprecated alias. That alias prints a notice on stderr, then delegates to `upgrade-cmd`. |
| `uninstall (--keep-db \| --archive PATH \| --purge)` | Tears down aelfrice. It requires one disposition flag. `--purge` has three confirmation gates. `--archive` writes a Fernet-encrypted file, then deletes the original. |
| `migrate [--from P] [--apply] [--all]` | Ports beliefs from the legacy global DB into the active project's per-project DB. It is a dry run by default, and it is read-only on the source. |
| `statusline` | Emits the update-banner snippet, or nothing. It reads the cache only, and it makes no network call. |
| `ingest-transcript [PATH \| --batch DIR] [--since DATE]` | Ingests one `turns.jsonl` file, or batch-walks a directory. It auto-detects the aelfrice and Claude Code formats, and it's idempotent. |
| `rebuild [--transcript PATH] [--n N] [--budget N]` | Runs the context rebuilder manually. The rebuilder is alpha. It also fires automatically on `SessionStart(source="compact")`, after compaction, but not on `PreCompact`, which cannot inject ([#1031](https://github.com/robotrocketscience/aelfrice/issues/1031)). The command prints the rebuild block to stdout. |
| `project-warm <path> [--debounce N]` | The CwdChanged hook entry point. It resolves `<path>` to a project root, which is a git work-tree or an ancestor provisioned under `~/.aelfrice/projects/<id>/`. It pre-loads the SQLite page cache and the operating-system page cache, then writes a sentinel under `~/.aelfrice/projects/<id>/.last_warm`. It's a silent no-op for three cases: an unknown path, a denied path, and any call inside the 60-second debounce window. The default deny list is `/tmp/**`, `/var/folders/**`, `~/Downloads/**`, and `~/Desktop/**`. To override the deny list, set `project_warm.deny_globs` in `~/.aelfrice/config.json`. The command always exits 0, and it never writes to stdout. **Manual wiring:** nothing installs this hook. `aelf setup` does not register it. The hook stays inert unless you wire a CwdChanged hook to it yourself. |
| `session-delta [--id ID] [--telemetry-path PATH]` | **Advanced/hidden.** The SessionEnd hook entry point. It computes the per-session deltas from the beliefs tagged with `--id` in the active store. The deltas are the beliefs created, the corrections detected, the feedback given, and the velocity. It combines the deltas with a current store snapshot (beliefs blocks and graph blocks) and with the rolling-window rollups from the existing `telemetry.jsonl`, then appends one v=1 JSON row to `PATH` (default `~/.aelfrice/telemetry.jsonl`). A missing `--id` or an empty `--id` is a silent no-op, with a stderr warning and exit 0. An idle session with zero beliefs still emits a row, so `len(telemetry.jsonl)` equals the session count. The command does not appear in `aelf --help`. **Manual wiring:** nothing installs this hook. The hook stays inert unless you wire a SessionEnd hook to it yourself. It makes no network calls (see [PRIVACY § no telemetry](PRIVACY.md)). |

## HRR persistence reporter

(v3.0+, #696) `aelf doctor` and `aelf status` report three facts about the HRR structural index: whether the index is persisted to disk, the size of the blob, and the duration of the most recent rebuild. The rows let you confirm that warm-load is actually firing, and that the index is not silently rebuilding on every cold start.

### `aelf doctor`

Three rows under the `HRR` block:

| Row | Type | Meaning |
|---|---|---|
| `hrr.persist_enabled` | `true` / `false` | The row holds the result of `HRRStructIndexCache._resolve_persist_dir()`, and it is `true` when the resolver returns a path that is not `None`. That case captures three conditions: `store_path` is set; `AELFRICE_HRR_PERSIST != "0"`; and (#695) the ephemeral path has not auto-disabled persistence. |
| `hrr.on_disk_bytes` | int | `os.path.getsize(<persist_dir>/struct.npy) + os.path.getsize(<persist_dir>/meta.npz)` when both files exist, and `0` otherwise. |
| `hrr.last_build_seconds` | float / `n/a` | The wall-clock duration of the most recent `HRRStructIndex.build()` call in this process, or `n/a` if no build has fired since the process started. |

On `aelf doctor`, `--json` affects `--meta-beliefs` only. The report for the hooks and the graph, which includes the HRR rows, is text-only today. When persistence is off, the command appends the `reason` string to the `hrr.persist_enabled: false` row. That string is `no store path`, `AELFRICE_HRR_PERSIST=0`, or `ephemeral path`.

### `aelf status`

One summary line:

```
hrr.persist_state: on <N> bytes, last build <X>s
hrr.persist_state: off (<reason>)
```

The `<reason>` value is one of `no store path`, `AELFRICE_HRR_PERSIST=0`, `ephemeral path`, or `unknown (probe error)`.

For the underlying flag, see [CONFIG § `hrr_persist`](CONFIG.md). For the substrate specification, see [`docs/design/feature-hrr-integration.md`](../design/feature-hrr-integration.md). For the matrix of observable states, see `tests/test_hrr_struct_index.py`.

## Dangling-edge reporter

(#1375) `aelf doctor` counts the `edges` rows whose `src` or `dst`
names a belief that is not in the `beliefs` table:

```
dangling edges (endpoint missing from `beliefs`):
  3 of 412 edge(s) — 2 missing src, 2 missing dst
    TEMPORAL_NEXT: 2
    SUPPORTS: 1
```

The command prints the zero reading (`none of 412 edge(s)`) too. A check
that is silent when it is clean looks the same as a check that never ran.

The endpoint counts are per endpoint. An edge that misses both ends adds
one to `total`, one to `missing src`, and one to `missing dst`. A
**retired** belief is still a row, so its edges are not dangling.
`--classify-orphans`
([#206](https://github.com/robotrocketscience/aelfrice/issues/206)) is a
different report, about *belief* orphans.

The reporter only reports, and it changes nothing. `edges` has
`PRIMARY KEY (src, dst, type)` and no foreign key. `insert_edge` checks
federation ownership rather than endpoint existence. For those two
reasons the database accepts these rows without error. Adding the
foreign key requires a rebuild of the `edges` table, and aelfrice
deliberately does not attempt that rebuild. An `edges` migration is what
made stores unusable in
[#1161](https://github.com/robotrocketscience/aelfrice/issues/1161).

## Help flags

`aelf --help` shows the everyday surface, which is the visible subcommands. `aelf --help --advanced` (or `aelf --advanced`) shows the full surface. The full surface includes the hidden subcommands (`bench`, `cadence-score`, `clamp-ghosts`, `context`, `demote`, `export-canvas`, `feedback`, `gate`, `health`, `ingest-transcript`, `label`, `project-warm`, `regime`, `resolve`, `session-delta`, `spine`, `stats`, `statusline`, `uninstall`, `unsetup`, `upgrade`, `upgrade-cmd`, `validate`). PR #174 wired the `--advanced` flag in v1.4. `export-obsidian` is visible in the everyday `--help`.

## Output and exit codes

- aelf prints human-readable output on stdout and errors on stderr.
- `bench` prints JSON.
- Exit codes: `0` = success or no-op; `1` = bad argument, belief not found, or structural audit failure; `>1` = uncaught exception.

## Defaults that matter

| Constant | Value |
|---|---|
| Lock initial prior | `(α, β) = (9.0, 0.5)` |
| Decay target | Jeffreys prior `(0.5, 0.5)` |
| Half-lives | factual 14d, requirement 30d, preference 12w, correction 24w |

| Benchmark hit-depth | top-5 |

The half-lives and the decay target live in `aelfrice.scoring`. The token budget lives in `aelfrice.retrieval` (`DEFAULT_TOKEN_BUDGET`). The lock prior lives in `aelfrice.derivation` and `aelfrice.classification_core`. The valence-propagation defaults live on `MemoryStore.propagate_valence`.
